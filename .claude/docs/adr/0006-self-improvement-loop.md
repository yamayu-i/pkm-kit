# ADR-0006: 自己改善は 4 つの観測から月 1 回評価し、提案までにする

- 状態: 承認
- 日付: 2026-10-31

## 背景

ハーネスの目的には、LLM wiki の仕組みとハーネス自体を、調査と利用実態を踏まえて改善することが含まれる。テンプレートは、作業中の気づきを記録し、月 1 回の評価で改善案を Issue にする。

## 決定

利用実態は次の 4 つから把握する。

| 観測 | 置き場所 | 書く人・タイミング |
|---|---|---|
| git の履歴 | リポジトリ | 自動。`node .claude/scripts/usage-report.mjs` が集計する（コミットの種類、よく編集されたノート、更新されないページ、参照されないページ） |
| 作業中の気づき | `.claude/notes/` | Claude Code が、訂正・質問・食い違い・手戻りが起きたその場で書く（`harness-note`） |
| wiki の操作の記録 | `wiki/log.md` | wiki のスキルが、操作のたびに追記する |
| ユーザーのフィードバック | `wiki/feedback.md` | ユーザーが、使っていて気づいたときに書く（モバイルからも書ける） |

- 評価（`harness-review`）は **月 1 回**。SessionStart フックが期限を知らせる。気になったらいつ行ってもよい
- 評価の対象は、ハーネス（文書・スキル・検査）と wiki の仕組み（構成・書式・スキル）の両方。Claude Code と Obsidian の更新、LLM wiki の運用例も調べる
- 出力は **提案まで**: レポート（`.claude/reviews/YYYY-MM-DD.md`）と改善案の Issue。変更は通常の工程（[ADR-0002](0002-workflow-by-size.md)）で行う
- 処理した気づきのファイルは消す。残っているファイルが未処理の気づき

## 理由

- 4 つは観点が違う。履歴は「何が実際に使われているか」、気づきは「エージェントがどこでつまずいたか」、log は「wiki の操作の中身」、フィードバックは「人がどう感じたか」
- 自動で変更まで行うと、ハーネスと wiki の仕組みが人の知らないうちに変わる。どちらも以後のすべての作業に効くので、人が判断する
- セキュリティチェック（週 1 回）とは目的と重さが違うので、別の周期にする

## 却下した案

- 定期実行で PR まで作る: 評価が溜まると読む負担が増える。まずは手動で回して、提案の質を見てから検討する
- 気づきを Claude Code のメモリに保存する: 他のセッションや将来のツールに届かない

## 影響

- 無人の定期実行に移すかは、評価を数回行ってから、新しい ADR で決める
