# ADR-0003: wiki は `sources/`・`wiki/` に分ける。`daily/` はその場で元資料として扱う

- 状態: 承認
- 日付: 2026-10-31

## 背景

LLM wiki では、LLM が元資料を読み、まとめのページを書き、ページ同士をリンクでつないで保守する。参考にした Karpathy の LLM wiki は、変更しない元資料、LLM が書く wiki、目次（index.md）、操作の記録（log.md）、それらの規約（スキーマ）に分けている。

この Vault には、人が書くデイリーノート（`daily/YYYY/MM/YYYY-MM-DD.md`）と、ルートのメモがある。LLM にさせたいことは、取り込み、質問への回答と蓄積、保守（lint）、デイリーノートの整理の 4 つ（ヒアリング）。

## 決定

| パス | 内容 | 書く人 |
|---|---|---|
| `sources/` | 取り込んだ元資料（記事の本文や抜粋、手入力のメモ）。1 資料 = 1 ファイル。サブフォルダを作らない | LLM（作成後は変更しない） |
| `asset/` | 添付（PDF・画像）。元資料のバイナリもここに置き、`sources/` のページから参照する | 人・LLM（追加のみ） |
| `wiki/` | LLM がまとめるページ。サブフォルダを作らず、種類は frontmatter の `type` で表す | LLM（人の編集は入力として扱う） |
| `wiki/index.md` | すべてのページの目次 | LLM |
| `wiki/log.md` | 操作の記録（追記のみ） | LLM |
| `wiki/feedback.md` | 使っていて気づいたこと | 人 |
| `daily/` | デイリーノート。**移動しない**。人が書く元資料として扱う | 人 |

書式の詳細（ページの種類、frontmatter、index と log の形式）は [LLM wiki の仕組み](../llm-wiki.md) にある。

`daily/` は次のように扱う。

- **処理するのは前日までの日だけ**。当日のノートは書き足している途中なので対象にしない
- **どこまで処理したかは `wiki/log.md` に残す**。日付と、そのときのコミットを書く。次回は、前回の後の日付と、前回のコミットから追記された日を処理する（`node .claude/scripts/daily-pending.mjs` が列挙する）
- **戻りのリンク**: 反映した wiki のページへのリンクを、デイリーノートの末尾に追記してよい（本文は変えない。[ADR-0004](0004-human-notes-append-only.md)）
- wiki のページの `sources` には、デイリーノートのパスもそのまま書ける

## 理由

- 元資料と wiki を分けると、「何を根拠に書いたか」を辿れ、wiki を作り直すこともできる
- `daily/` を `sources/` に写すと、同じ内容が 2 箇所にでき、追記のたびにずれる。その場で元資料として扱えば写す必要がない
- `daily/` は書き足され続けるので、「処理済み」の印をノートに付ける方法は使えない（人のノートを変えられない）。log.md にコミットを残せば、git の差分で追記分だけを取り出せる
- `wiki/` をフラットにすると、リンクのパスが短く安定し、ページの改名でしかリンクが変わらない。分類は `type` と index で足りる

## 却下した案

- 人のページと LLM のページを混ぜる: どこまで書き換えてよいかを、ページごとに判断しなければならなくなる
- `daily/` を対象外にする: 日々のメモが wiki に入らず、整理の手間が人に残る
- index と log を Vault のルートに置く: ルートは新規ノートの既定の作成先で、人のメモと混ざる

## 影響

- `.claude/docs/vault-conventions.md` の「配置」に `sources/` と `wiki/` を足す
- wiki のページが数百を超えて index が読み切れなくなったら、検索の仕組み（プラグインかスクリプト）を ADR で検討する
