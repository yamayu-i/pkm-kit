# ADR-0004: 人のノートに LLM は追記だけ。CI で検査する

- 状態: 置換（[ADR-0007](0007-note-format.md)）
- 日付: 2026-10-31

## 背景

ヒアリングで「人のノートは追記のみ可。すでに書かれていることは許可なく変更しない」と決めた。wiki の操作は PR を通さず main に直接コミットする（[ADR-0002](0002-workflow-by-size.md)）ので、レビューでは止められない。

## 決定

パスごとに「所有の区分」を決める（[LLM wiki の仕組み](../llm-wiki.md)）。

| 区分 | パス | LLM ができること |
|---|---|---|
| 人のノート | `daily/`、`wiki/feedback.md`、その他の見えるフォルダ | 既存の行を変えずに追記する。新しいファイルを作らない。消さない・移動しない |
| wiki | `wiki/`（`feedback.md` を除く） | 自由に作る・書き換える・消す。人が編集した内容も入力として扱い、作り直してよい。ただし人の書いた内容を消すときは log.md に理由を書く |
| 元資料・添付 | `sources/`、`asset/` | 追加だけ |
| 隠しパス | `.claude/`、`.obsidian/` など | wiki の操作では変えない（開発の作業として PR で変える） |

- wiki の操作のコミットは、件名を `wiki(<操作>): <要約>` にする
- `node .claude/scripts/check-append-only.mjs` が、件名が `wiki(` で始まるコミットの差分を検査する。スキルはコミットの前に実行し、CI は main への push と PR で実行する
- 人のノートの誤字やリンク切れに気づいても直さない。wiki-lint はユーザーに伝えるだけにする。直す許可をもらったら、そのときは開発の作業と同じく通常のコミット（`docs(vault): …`）にする

## 理由

- 「追記だけ」は差分の削除行がないこととして機械的に判定できる。文書の約束だけにすると、整理のついでに書き換える間違いを防げない
- 件名で wiki の操作を見分ければ、人の snapshot コミットや開発のコミットを誤って止めない
- 最終行に改行がないファイルへの追記は、差分上は「最後の行の削除と再追加」になるので、検査ではこの場合だけ許す

## 却下した案

- Claude Code のフックで編集の前に止める: ツール経由の編集は止められるが、シェルで書いたものは漏れる。コミットの差分を見る方が確実
- 人のノートも LLM が整理してよいことにする: ヒアリングで否定された

## 影響

- 検査は事後（push の後）なので、違反は CI の失敗として通知される。直すときは追加のコミットで元に戻す（履歴は書き換えない）
