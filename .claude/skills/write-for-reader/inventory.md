# 棚卸しと突き合わせ

削りすぎを防ぐ工程。欠落は出力に跡が残らないので、出力だけを読み返しても見つからない（E7）。先に全部集め（棚卸し）、書いた後に集めたものと照らす（突き合わせ）。網羅は捨てずに層を移す。

## 棚卸しする

書き始める前に、出力に関係しうるものを全部、一覧にする。この一覧は LLM だけが読むもの（[読み手](readers.md#llm-だけ)）で、推敲しない。

集める先:

| 先 | 例 |
|---|---|
| ユーザーの依頼 | 会話で求められたこと、気にしていたこと、条件（「〜に留意して」）。最も落としやすい |
| 元の資料 | 読んだ資料・ページ・コードの、出力に関係する事実 |
| 機械で出せるもの | 検査の出力、差分のファイル一覧、記録の集計 |
| 作業で起きたこと | 期待と違ったこと、飛ばした工程、試して失敗したこと、未確認のこと |
| 観点 | 選択肢、リスク、前提、制約、影響を受ける人やもの |

- 置き場所: 短ければ考えの中でよい。長い作業や、サブエージェントに渡すときはファイルにする（作業用の一時ファイル。コミットしない）
- 1 項目 1 行にし、出典を付ける

## 行き先を決める

段階の規則（段階のファイルの「判断のロジック」）に従って、項目ごとに行き先を 1 つ決める。

| 行き先 | 意味 |
|---|---|
| 本文 | 出力の本文に書く |
| 扱わなかったこと | 本文に書かないが、書かなかったことを読み手に示す（段階 2） |
| 付録 | 本文の外（付録の節、別のファイル・ページ、リンク）に置く |
| 対象外 | 範囲の外として、理由を付けて示す（段階 4） |
| 関係なし | どこにも書かない。書かない理由を自分で 1 語で言える |

## 突き合わせる

書いた後に、棚卸しの一覧と出力を照らす（段階 2 以上）。

1. 一覧の各項目が、決めた行き先に実際に入っているか
2. 「関係なし」にした項目を見直す: ユーザーの依頼から来た項目を「関係なし」にしていないか。していたら本文か「扱わなかったこと」に移す
3. 段階 3: 「付録」にした項目に、判断を変えうるものがないか
4. 段階 4: 一覧の件数と本文の件数が一致するか（数える）
5. 本文にあって一覧にないものがあれば、それが要るかを問う（後から足した飾りや繰り返しであることが多い）

突き合わせで直したら、記録には残さなくてよい。ユーザーに指摘されてから直したものは、[記録](recording.md)の `issue` にする。
