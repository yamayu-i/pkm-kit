# 段階の選び方

人が読む出力（「両方」の人の層を含む）の段階を決める。段階を決めるのは、**読み手が読んだ後に何をするか**と、**見落としの代償**の 2 つ。長さは段階の結果であって、目標ではない（E10、E11）。

## 段階の一覧

| 段階 | 読んだ後にすること | 見落としの代償 | 例 |
|---|---|---|---|
| [1 知らせる](stages/1-notify.md) | 状況を知る。次の 1 手をする | 小さい（期待との差だけは大きい） | 作業の完了、途中の進み具合 |
| [2 答える](stages/2-answer.md) | 問いの答えを得る | 中くらい | wiki-query の回答、調査の要点 |
| [3 決める](stages/3-decide.md) | 承認する・選ぶ | 判断を変えうるものについて大きい | ADR、計画、PR の概要、評価の提案 |
| [4 確かめる](stages/4-verify.md) | 漏れなく点検・監査する | 大きい | セキュリティチェック、点検の結果、移行の影響 |
| [5 引く](stages/5-reference.md) | 後で何度も探して読む | 範囲の中で大きい | 規約、wiki のページ、`surfaces/` |

## 決め方

1. **既定を見る**: 出力を作るスキルの末尾の「出力の段階」の節。スキルの外の出力なら、上の表の例で一番近いもの
2. **既定がないとき**: 「読み手はこれを読んだ後に何をするか」に答え、上の表の「読んだ後にすること」で選ぶ。2 つに当てはまるなら、数の大きいほう
3. **上げ下げを判断する**（下の節）
4. **混ぜるかを決める**: 節ごとに読んだ後にすることが違うなら、節ごとに段階を決める。主な段階は、読み手が最初に読む節の段階
5. **記録する**: 既定から上げ下げしたら、`start` に `--default` と `--reason` を付ける（[記録](recording.md)）

## 上げ下げ

| 向き | 条件 |
|---|---|
| 上げる | ユーザーが「全部」「漏れなく」「詳しく」と言った |
| 上げる | 取り消せない操作、セキュリティ、データの消失、子の Vault への Breaking Change に関わる |
| 上げる | 読み手が、これだけを根拠に、ほかの人に影響する判断をする |
| 下げる | ユーザーが「ざっと」「要点だけ」「一言で」と言った |
| 下げる | 同じ内容を、この会話ですでに伝えた |

- 上げ下げは 1 段ずつにする。2 段以上動かすなら、読み手が読んだ後にすること自体が違うので、2 からやり直す
- 迷ったら: 見落としの代償が大きいなら上げる。そうでなければ 1 つ下げて出し、詳細の置き場所を示す（E5、E16。詳細は求められたら出せるが、読ませた負担は取り戻せない）

## よくある誤り

- **長さで段階を選ぶ**: 「長くなりそうだから 4」ではなく、読んだ後にすることで選ぶ。4 でも冒頭は短い
- **全部 3 にする**: 完了の報告に選択肢やリスクを並べない。決めることがなければ 3 ではない
- **4 を避ける**: 点検の結果を「主なもの」に絞ると、残りは見ていないのと区別できなくなる
