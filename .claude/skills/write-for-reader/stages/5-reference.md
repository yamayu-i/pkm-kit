# 段階 5 引く

## 目的

読み手が後で何度も探して読む。通読されず、引かれる。読み手は人と LLM の両方であることが多い（[両方](../readers.md#両方)）。

- 使う: 規約、手順の文書、`surfaces/`・`concepts/`、wiki のページ、スキルの説明
- 使わない: 一度読んで終わる報告は 1〜4。経緯や理由は ADR（段階 3）に書く

## 判断のロジック

1. **範囲を決める**: このページが受け持つもの。範囲の中は網羅し、範囲の外は書かずに別のページへリンクする。同じことを 2 か所に書かない
2. **構造を対象の構造に合わせる**: 説明する対象（機能、概念、フォルダ）の構造に見出しを合わせる（E15）
3. **同じ種類は同じ構造にする**: 同じ種類のページは同じ見出しと項目にする。種類の型を決めている規約やテンプレートがあれば、それに従う
4. **冒頭に要約を置く**: 何のページか、要点は何かを 1〜3 文で。冒頭だけで、探しているページかどうかが分かるようにする
5. **事実を中立に書く**: 説明・経緯・意見を混ぜない。理由は ADR、手順は手順の文書に置いてリンクする
6. **出典を付ける**: wiki のページは主張ごとに出典を付ける（[LLM wiki の仕組み](../../../docs/llm-wiki.md)）

## 書くときの指示

```
読み手は、これを後で探して読む。通読しない。
1. 冒頭に、このページが何を受け持つかと要約を 1〜3 文で書く
2. 受け持つ範囲の中は漏れなく書く。範囲の外は書かずに、別のページへリンクする
3. 見出しは、説明する対象の構造に合わせる。同じ種類のページは同じ見出しと項目にする
4. 事実を中立に、短く書く。経緯・理由・手順は、それぞれの置き場所に置いてリンクする
5. 主張ごとに出典を付ける（wiki のページ）
```

## 構成の部品

結論（要約）→ 節（対象の構造に合わせる）→ 表（要素ごとに同じ項目）→ 参照（関連するページ・出典）。

## 確かめ方

- 既存の検査を通す（文書は `check-docs.mjs`、wiki は `wiki-lint.mjs`）
- 同じ種類のページと見出し・項目がそろっているか
- 範囲の中の抜け: 対象の一覧（機能の一覧、フォルダの中身、目次）と突き合わせる（[突き合わせ](../inventory.md#突き合わせる)）
- 同じことが別のページにも書かれていないか

## 根拠

- 参照用の文書は、中立に、簡潔に、対象の構造に合わせて、一貫した形で書く。読まれるのではなく引かれる（E15）
- 冒頭で要点を示し、詳細は段階的に開示する（E16）
- 規約・README は短く保つもの（E3）。範囲を分けて 1 単位を小さく保つ

## よくある失敗

- 経緯や理由を本文に書き、事実が埋もれる
- 範囲の外のことまで書いて、別のページと重複する
- ページごとに見出しがばらばらで、探しにくい
