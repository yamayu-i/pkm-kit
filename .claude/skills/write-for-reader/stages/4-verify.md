# 段階 4 確かめる

## 目的

読み手が漏れなく点検・監査する。見落としは長さより高くつくので、認知負荷が高くなっても網羅する。負担は件を減らさず、構造で下げる。

- 使う: セキュリティチェック、wiki の点検の結果、レビューの指摘、移行の影響、Breaking Change、worklog の見直しの候補、PR の検証の結果
- 使わない: 読み手が全件を見る必要がなく、要点で足りるなら [2](2-answer.md)。範囲の中を後で引くための網羅なら [5](5-reference.md)

## 判断のロジック

1. **範囲を決める**: 何を点検したか、何を点検していないか。範囲を書かない網羅は、どこまで網羅したかが分からない
2. **全件の一覧を先に作る**: 機械で出せるもの（検査の出力、差分のファイル一覧、記録の集計）は機械で出す。手で集めるものは集め方を書く（[棚卸し](../inventory.md)）
3. **件ごとに同じ項目で書く**: 何・どこ・重さ・根拠・対応（済み・要対応・見送り）。項目がそろっていれば、長くても目で追える
4. **重さの順に並べる**: 重さの基準を書く（例: データの消失 ＞ 誤った表示 ＞ 文言）
5. **冒頭の要約を書く**: 範囲、重さ別の件数、最も重いもの 1〜3 件、読み手がすること。要約は段階 3 の形で書く（判断を変えうるものを入れる）
6. **0 件の分類を「なし」と書く**: 見て 0 件だったのか、見ていないのかを区別する
7. **対象外にしたものを理由付きで並べる**

似た件をまとめてよいが、まとめた件数と場所をすべて書く。

## 書くときの指示

```
読み手は、これで漏れなく確かめる。見落としは長さより高くつく。
1. 先に全件の一覧を作る。機械で出せるもの（検査の出力、差分のファイル）は機械で出す
2. 冒頭に、範囲（見たもの・見ていないもの）、重さ別の件数、最も重いもの、読み手がすることを書く
3. 全件を重さの順に、件ごとに同じ項目（何・どこ・重さ・根拠・対応）で書く。件を省かない
4. 似た件をまとめるときは、まとめた件数と場所をすべて書く
5. 見た分類で 0 件なら「なし」と書く。対象外にしたものは理由を付けて並べる
文は短くしてよい。件は減らさない。
```

## 構成の部品

結論（範囲・件数・最も重いもの・読み手がすること）→ 表（全件。重さの順）→ 節「分類ごとの結果」（0 件は「なし」）→ 節「対象外」→ 詳細（各件の根拠。長ければ別のファイル）。

## 確かめ方

1. 棚卸しの件数と、本文の件数を数えて一致させる。数えた結果を冒頭の件数と照らす
2. 見た分類がすべて書かれているか（0 件の「なし」を含む）
3. 範囲と対象外が書かれているか
4. 見落としの代償が特に大きい点検（セキュリティチェックの目視、移行の影響）は、文脈を持たない読み手（サブエージェント）に、元の対象から独立に一覧を作らせて突き合わせる（E7）

## 根拠

- 欠落は出力に跡が残らず、誤りより見つけにくい。元の一覧と突き合わせると見つかる（E7）
- 詳しい内容でも、段階的に開示すれば負担は要約だけと同じくらいになる（E5）。冒頭の要約と、同じ項目の表がそれに当たる
- 障害の分析やトレードオフの説明は、詳しく書くものの代表（E3）
- 長さの上限は、この段階では害になる（ADR-0013 の却下した案）

## よくある失敗

- 「主なもの」だけを書く
- 0 件の分類を書かず、見たのか見ていないのかが分からない
- 冒頭の要約がなく、全件を読まないと重いものが分からない
- 件ごとに書き方がばらばらで、見比べられない
