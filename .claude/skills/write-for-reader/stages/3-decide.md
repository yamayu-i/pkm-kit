# 段階 3 決める

## 目的

読み手が承認する、または選ぶ。このハーネスで最も多い場面（ADR、Issue の計画、PR、評価の提案、エスカレーション）。

- 使う: 決めてほしいことがある出力
- 使わない: 決めることがないなら [1](1-notify.md) か [2](2-answer.md)。判断の前に全件の点検が要るなら、その部分は [4](4-verify.md) にして混ぜる

## 判断のロジック

1. **決めてほしいことを書き出す**: 1 つが理想。複数なら番号を付ける。書けないなら、まだ段階 3 の出力を書く時ではない
2. **棚卸し**: 選択肢、それぞれの影響、リスク、前提、制約、却下した案、調べた過程（[棚卸し](../inventory.md)）
3. **項目ごとに「判断を変えうるか」を問う**: 「これが違っていたら、読み手は別の選択をするか」
   - 変えうる → 本文に必ず書く。1 つでも本文から外すと、読み手は知らずに決めることになる
   - 変えない → 付録かリンクに回す（背景、経緯、調べた過程、細部）
   - この問いが、削りすぎと書きすぎの両方を防ぐ
4. **推奨を 1 つ決める**: 理由は、3 で本文に残した項目で書く。推奨できないなら、何が決まれば推奨できるかを書く
5. **取り消しやすさを書く**: 戻せるか、戻すときの手間。読み手が決める速さと慎重さを、これで調整できる
6. **決めることを分けられないか考える**: 本文が 2 画面を超えるなら、判断を変えうる項目が多すぎる兆候。決めることを分けて、出力を分ける

## 書くときの指示

```
読み手は、これを読んで「<決めること>」を決める。
1. 冒頭に、決めてほしいことと推奨を書く。冒頭だけで判断できるようにする
2. 判断を変えうる事実・トレードオフ・リスクは、すべて本文に書く
3. 判断を変えない背景・経緯・調べた過程は、付録かリンクに回す
4. 選択肢が 2 つ以上なら、同じ観点で並べた表にする。却下した案には理由を 1 行ずつ付ける
5. 取り消せるか、取り消すときの手間を書く
6. 本文は 1〜2 画面にする。超えるときは、決めることを分けられないかを先に考える
```

## 構成の部品

結論（決めてほしいことと推奨）→ 節「理由」→ 表（選択肢の比較）→ 節「リスクと戻し方」→ 節「決めてほしい点」（一覧）→ 詳細（付録・リンク）。ADR や PR のように型が決まっているものは、その型の節に上の内容を入れる。

## 確かめ方

- **大きい変更**（ADR、Issue の計画、大きい変更の PR）: 文脈を持たない読み手（サブエージェント）に本文だけを渡し、次に答えさせる（E8）。答えられない・誤るなら直す
  1. 何を決めるのか
  2. 推奨は何で、なぜか
  3. 主なリスクと戻し方
  4. 推奨を選ばない理由になりうるもの
  続けて付録に回したものを渡し、「この中に判断を変えるものはあるか」を問う。あれば本文に戻す
- **小さい変更**: 同じ問いに自分で答える
- どちらも、[突き合わせ](../inventory.md#突き合わせる)で棚卸しの各項目の行き先を確かめる

## 根拠

- 判断に使う要約は単独で読めるようにし、詳細は付録に置く（E4）。結論から書き、理由を下に並べる（E17）
- 詳細を段階的に開示すると、要約だけのときと同じ認知負荷で判断がよくなる（E5、E16）
- 文脈を持たない読み手に質問させると、書き手の思い込みと不足が見つかる（E8）

## よくある失敗

- 調べた過程を時系列で書き、推奨が最後に来る
- 推奨を書かずに選択肢を並べるだけにする
- リスクを付録に回す（判断を変えうるので本文に書く）
- 決めることがはっきりしないまま書き始める
