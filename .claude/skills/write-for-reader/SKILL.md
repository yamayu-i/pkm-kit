# 読み手と段階に合わせて書く

網羅しすぎると人が読めず、削りすぎると判断に要る観点が落ちる。どこまで書くかを、読み手と、読み手が読んだ後にすることで決める（[ADR-0013](../../../.kit/harness/docs/adr/0013-output-by-reader-and-stage.md)）。網羅は捨てずに層を移す: 先に全部集め、段階に合わせて選び、選んだ結果を集めたものと突き合わせる。

## 対象

成果物として渡す出力（調査の報告、問いへの回答、計画・ADR・Issue・PR、点検の結果、wiki のページ、作業の完了の報告、サブエージェントへの依頼と返答）。会話の短いやり取り（確認の質問、相づち）は対象にしない。

## 流れ

1. **読み手を決める**: [読み手](readers.md)。LLM だけなら、その方式で書いて 4 と 5 を飛ばす
2. **段階を決める**: [段階の選び方](select-stage.md)。スキルの「出力の段階」の節の既定から始め、上げ下げだけをその場で判断する
3. **記録を始める**: `node .claude/scripts/output-log.mjs start …`（[記録](recording.md)）
4. **棚卸し**: 観点・事実・件を全部集める（[棚卸しと突き合わせ](inventory.md)）
5. **段階の規則で書く**: 段階のファイルの「判断のロジック」と「書くときの指示」に従う
   - [1 知らせる](stages/1-notify.md) / [2 答える](stages/2-answer.md) / [3 決める](stages/3-decide.md) / [4 確かめる](stages/4-verify.md) / [5 引く](stages/5-reference.md)
6. **文体を整える**: [文体](style.md)
7. **確かめる**: 段階のファイルの「確かめ方」と、[棚卸しとの突き合わせ](inventory.md#突き合わせる)。長いほうを良いとしない
8. **形式に渡して描く**: このスキルが決めるのは内容と構成の部品まで。md・html などの描き方は[形式への渡し方](formats.md)の先に従う
9. **記録を終える**: 渡した時点で `output-log.mjs end …`。後でユーザーに問題を指摘されたら `output-log.mjs issue …`

段階を混ぜる出力（例: PR の本文は概要が 3、検証の結果が 4）は、節ごとに 5 と 7 を行う。

## 守ること

- 段階の規則を、その場で書き換えない。合わないと思ったら記録し（`issue --type stage`）、月 1 回の評価で直す
- 規則を変えるときは、根拠（[evidence.md](evidence.md) の ID か、記録の集計）を付ける
