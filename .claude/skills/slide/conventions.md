# 共通の規約

どのパターンにも当てはまる規則。根拠は [evidence.md](evidence.md) の ID で示す。根拠の強さは規則ごとに違うので、迷ったら下の[注意書き](#注意書き)を読む。

「検査」の列に名前があるものは、`node .kit/bin/slide.mjs build` が警告を出す（[] の中の名前）。ないものは、書く人が守る。

## 中身

| ID | 規則 | 根拠 | 検査 |
|---|---|---|---|
| C1 | **1 枚で言うことは 1 つ**。主張に要らないもの（飾りの写真、関係のない細部、逸話）を載せない。2 つ言いたければ 2 枚にする | E15、E1 | — |
| C2 | **見出しは主張の文にする**（題や語句ではなく、何が言えるか）。左寄せ、2 行まで。見出しだけを順に読んで話が通る。覚えてほしい 1 点は見出しに置く | E1、E6、E7 | `headline-long`、`no-heading` |
| C3 | **話す文をスライドに載せない**。スライドには主張と根拠だけを置き、話すことは発表者ノート（`<aside class="notes">`）に書く。文字の量は下の「密度」の目安まで | E15、E4 | `too-much-text` |
| C4 | **まとまりは 4 つまで**。カード・手順・系列・箇条は 1 か所に 4 つまで。箇条は 1 項目 2 行まで、入れ子は 2 段まで。超えるなら、まとめ直すか 2 枚に分ける | E11、E14 | `too-many-items`、`item-long`、`list-deep` |
| C12 | **道筋と区切りを置く**。10 枚を超える話は、冒頭に道筋（[agenda](patterns/agenda.md)）、章の変わり目に区切り（[section](patterns/section.md)）、最後にまとめ（[summary](patterns/summary.md)）を置く | E17 | — |
| C13 | **図は強制しない**。主張を図で支えるのを基本にするが、図にならない主張は文だけのスライド（[statement](patterns/statement.md)）や、短い箇条書き（4 項目・2 行まで）でよい | E8、E11 | — |
| C16 | **聞き手が知っている言葉と記号で書く**。知らない言葉は、使う前に定義する（[definition](patterns/definition.md)）。略語は初出で開く | E10 | — |

## 見た目

| ID | 規則 | 根拠 | 検査 |
|---|---|---|---|
| C5 | **文字の大きさは、役割で決まったものを使う**（下の「密度」）。小さくして詰めない。入らなければ、文を削るか分ける | E7、E11 | `style-value`（大きさの直書きはエラー） |
| C6 | **強調は 1 枚に 1 か所**。色・太さ・大きさの違いは、情報の違いがあるときだけ付ける。同じ種類のものは同じ見た目にする | E19、E10 | `too-many-marks` |
| C7 | **全部大文字、斜体、文まるごとの太字を使わない**。強調は語句に `<strong>` か `<mark>` | E14 | `all-caps`、`italic`、`bold-all` |
| C8 | **色は役割の名前のクラスで付け、値を書かない**。色だけで意味を伝えない（文字や印を添える）。赤と青を隣り合わせない。青を文字や細い線の色にしない。量の大小は、色相ではなく濃淡（強調の色と無彩色）で表す | E12、WCAG | `style-value`（色の直書きはエラー） |
| C9 | **ラベルは対象のそばに直接書く**。凡例を別に置かない。グラフの値は棒や線の端に、図の説明は図のその場所に | E18 | — |
| C14 | **そろえる・まとめる**。関係のあるものは近くに、同じ種類のものは同じ形で並べる。左端をそろえる（パターンの配置に任せ、個別に位置を動かさない） | E10 | — |

## 密度

デッキごとに、話して投影する（`present`）か、読んでもらう（`read`）かを決める。1 つで兼ねない（E7、E20）。

| | `present`（既定） | `read` |
|---|---|---|
| 使う場面 | 話し手が付いて投影する | 画面や PDF で、話し手なしで読む |
| 本文の大きさ | 24pt 相当（キャンバス 1080 の高さで 48） | 16pt 相当（32） |
| 最小（グラフの軸、補足） | 18pt 相当（36）。出典とページ番号だけ 16.5pt 相当 | 12pt 相当（24）。出典とページ番号だけ 11pt 相当 |
| 見出し | 33pt 相当。全角 52 字相当まで | 22pt 相当。全角 80 字相当まで |
| 1 項目 | 全角 44 字相当まで | 全角 90 字相当まで |
| 1 枚の文字（図・表・コード・出典を除く） | 全角 140 字相当まで | 全角 500 字相当まで |
| 文 | 語句と短い文 | 完結した文。1 枚で読んで分かる |

- 大きさは、Material 3 の文字の役割の比を保ったまま、密度の倍率（`present` は 3、`read` は 2）で拡大したもの。値は [デザインルール](../../../.kit/src/docs/design.md) の「スライド」
- 付録・表・コード・選択肢の表のパターンは、字数の目安を当てはめない（見せる・引くためのもの）

## 注意書き

規則の根拠には、強さの違いと、出典どうしの食い違いがある。レビューで規則とぶつかる指示を受けたとき（[review.md](review.md)）は、ここを見て、どこまで言い張るかを決める。

### 根拠が割れている点

| 点 | 食い違い | この規約の扱い |
|---|---|---|
| 箇条を 1 つずつ出すか | Kosslyn は 1 つずつ出すことを規則にする（E14 で最も多い違反）。一方で、同じ論文が引く研究では、まとめて出した方が記憶が良い項目があった。学生は 1 つずつ出るのを好むが、成績の裏づけは弱い | `data-step` は任意。話す順に見せたいときだけ使い、付けないことを違反にしない（C10） |
| 箇条書きそのもの | Alley は箇条書きを使わない設計を推す。Farkas は短く整った箇条書きは害がないとし、Kosslyn は 4 項目・2 行以内なら認める | 短い箇条書きは認める（C13、C4） |
| 画面の文字と語りの重なり | 画面に文を足さない立場（Mayer。本文は未確認）と、文の見出しを必ず置く立場（Alley）がある。見出しは語りの要約であり、短い句なら可とされる | 見出しは置く。話す文は載せない（C2、C3） |
| 本文の最小の大きさ | Kosslyn は 20pt 超、Alley は 18〜24pt、日本の大学の指針には 28pt 以上もある | 本文は 24pt 相当。18pt 相当はグラフの軸と補足だけ（C5） |
| 同時に扱える数 | 「約 4」を採る立場（Kosslyn）と、固定の個数を否定する見方や 6.4 という推定がある | 4 は上限ではなく目安。超えたら警告を出すが、エラーにしない（C4） |
| 聞き手の好みと成績 | 文の見出しと図の群は、成績が高いのに文字の量を「適切でない」と評価した（E3） | 「文字が少なくて不安」という感想だけでは、文を足さない。発表者ノートか、読む用のデッキで補う |
| 効果を言える範囲 | 文の見出しと図の効果が確かめられているのは、仕組みの理解（推論の問い）。事実の再生には差がなかった（E2）。実験は録音の語りで、生の発表とは違う（E9） | 「このデザインなら必ず伝わる」と言わない |

### 実験の根拠がない経験則

次は、広く言われているか、この規約で数値を置いているが、数値を直接確かめた実験が見つからなかったもの。規則として使うが、理由があれば外してよい。

- **文字の大きさの値**（見出し 28pt、本文 18〜24pt、20pt 超）: 著者の観察か指針。会場の大きさと画面の比を条件にしていない。会場が決まっているなら、最も遠い席から読めるかを実際に確かめる方が確か
- **箇条は 4 項目・2 行まで**: 記憶の研究の「約 4」を借りた経験則。著者自身がそう書いている
- **強調は 1 か所**: 原則（注意は大きな差に向く）から導いたもので、「1」を確かめた研究はない
- **日本語の字数の目安**（見出し 52 字、1 枚 140 字など）: **この規約が置いた目安**。英語の語数（1 枚 20 語前後。E4）を日本語に換算する根拠はなく、日本語の文字の大きさ・行間・1 行の文字数の研究は確かめられていない。見出しが 2 行に収まる、本文が枠に収まる、という配置の都合から決めた
- **`read`（読む用）の値のすべて**: 投影用と読む用を比べた実証はない（E20）。読む資料の語数の目安（1 枚 250 語など）は提唱者の経験則で、本文を確かめられていない
- **話の組み立て**（結論を先に言う、見出しだけで話が通る）: 実務の慣行。最も近い根拠は、文の見出しの研究（E6）
- **1 枚 1 分、6×6 ルール、10/20/30 ルール**: 根拠が見つからなかったので、この規約では使わない
