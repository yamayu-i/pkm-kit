# worklog の見直し

worklog は `worklog/<端末名>/YYYY-MM.jsonl` に 1 行 1 件で入っている（ADR-0004）。
止め忘れの警告や自動停止はしない方針なので（ADR-0009）、間違ったログはこのスキルで後から直す。

## 1. 候補を出す

```sh
TZ=Asia/Tokyo node .kit/bin/worklog-review.mjs . --json   # 日またぎの判定はタイムゾーンに依存する。ユーザーのタイムゾーンを使う
```

`.kit/bin/` のものはビルド済みなので、`pnpm install` もビルドも要らない。

- 閾値を変えるとき: `--running-hours=4`（記録中のまま何時間で候補にするか）、`--long-hours=6`、`--overlap-count=3`
- `findings` が候補。`code` の意味:
  - `still-running`: 記録中のまま長時間経っている（止め忘れ）
  - `too-long`: 1 件が長すぎる
  - `crosses-midnight`: 日をまたいでいる
  - `non-positive`: 終了が開始以前
  - `many-overlaps`: たくさんのログと時間が重なっている（グループで再生したまま、など）
  - `unknown-task`: `task_id` の issue / routine がない
- `effort` は issue ごとの按分前（`raw`）と按分後（`prorated`）の実績（分）。按分は ADR-0005
- CLI は issue を閉じた日時を取得しないため、閉じた後のログは検出しない。

候補が 0 件なら、そう伝えて終わる。

## 2. 一覧を見せる

候補を issue ごと・日付ごとにまとめ、表で見せる（ID、issue の summary、開始〜終了、何が怪しいか）。
そのうえで「どれから直すか」「まとめて同じ直し方でよいか」をユーザーに聞く。

## 3. 1 件ずつ直す

- 直し方を提案する（例: 「終了を 12:30 にする」「削除する」「task_id を i-12 にする」）。その日のほかのログ、デイリーノート（`daily/YYYY/MM/YYYY-MM-DD.md` の `## Task board`）、issue の本文を手がかりにする
- **ユーザーが承認してから**書き換える。推測だけで直さない
- 書き換えるのは該当する 1 行だけ。`id` は変えない。日時はタイムゾーン付き（`2026-10-31T12:30:00+09:00`）
- 1 行は `{"id":…,"task_id":…,"from":…,"to":…,"description":…}` の JSON のまま保つ（キーの順もこのまま）
- 削除するときは行ごと消す（空行を残さない）
- 開始日時を別の月に変えても、ファイルは移さない（プラグインと同じ）

## 4. 注意

- **他の端末で記録中のログ**（`to` が `null`）は、その端末で同期（vault-git の pull / push）してから直してもらう。同期前に直すと、その端末が止めたときに行の ID が合わず、プラグインが書き込みを止める
- 直し終わったら `node .kit/bin/lint.mjs .` を実行し、エラーがないことを確かめる
- 変更は worklog のファイルだけ。コミットするかはユーザーに確認する（ふだんは vault-git が同期するので、Claude Code からはコミットしなくてよいことが多い）

## 出力の段階

出力は [write-for-reader](../write-for-reader/SKILL.md) に従う。下は既定で、上げ下げはその場で判断する。

| 出力 | 読み手 | 段階 |
|---|---|---|
| 候補の一覧 | 人 | 4 |
| 1 件ずつの確認 | 人 | 3 |
