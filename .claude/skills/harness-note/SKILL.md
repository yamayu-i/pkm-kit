# 気づきを記録する（子の Vault）

気づいた時点で `.claude/notes/` に書く。後でまとめようとすると、会話が終わった時点で失われる。記録は月 1 回の評価（[harness-review](../harness-review/SKILL.md)）の入力になる（[ADR-0011](../../../.kit/harness/docs/adr/0011-harness-parent-and-child.md)）。

`.kit-local/` がない（上流そのものを開発している）ときは、上流の [kit-note](../../../.kit/harness/skills/kit-note/SKILL.md) を使う。

## 記録する条件

| 種類 | 起きたこと |
|---|---|
| 訂正 | ユーザーに、やり方や出力を直された（必ず記録する） |
| 質問 | 文書にあるべきことが書かれておらず、ユーザーに質問した |
| 繰り返し | 同じ失敗を 2 回繰り返した |
| 食い違い | 文書やスキルの記述が、実際のコードや挙動と違っていた |
| 迂回 | 検査を迂回したくなった、検査が誤っていると感じた |
| つまずき | 上のどれでもないが、文書や検査が足りずに遠回りや手戻りをした |
| wiki | wiki の構成・書式・スキルが、実際の使い方に合わなかった |

迷ったら記録する。

## 直す先

記録ごとに、どこを直せば防げるかを書く。迷ったら `未定` にして、評価で決める。

| 直す先 | 当てはまるもの |
|---|---|
| `子` | この Vault のもの（`template/`、`.claude/local/`、`skills/local-*`、`.obsidian/*.json`、ノートの置き方）だけを変えれば防げる。またはこの Vault の好み |
| `上流` | 上流のもの（`.kit/owned-paths.json` に当たる。上流のスキル・文書・検査・プラグイン・テンプレートの既定）を変えないと防げない。またはどの Vault でも起きる |
| `未定` | まだ決められない |

この Vault の好みでも、上流に上書きの手段がないせいで子で直せないなら、`上流` にして「上書きの手段がほしい」と書く。

`上流` で、しかも作業が止まるもの（移行の失敗、プラグインの不具合で使えない）は、評価を待たずに [escalate](../escalate/SKILL.md) をユーザーに提案する。

## 書き方

ファイルは作業ごとに 1 つ: `.claude/notes/YYYY-MM-DD-<作業を表す英語の短い名前>.md`。同じ作業の中では同じファイルに追記する。

```markdown
# 2026-10-31 デイリーノートの整理

## 訂正

- 起きたこと: 反映先のリンクを本文の途中に足したら、末尾に追記するよう直された
- 直す先: 上流
- 改善案: wiki-daily のスキルに「リンクは末尾に追記する」を明記する
```

- 起きたことは事実を書く（何をして、何が起き、ユーザーが何と言ったか）
- 改善案は省いてよい。検査で防げるなら検査、無理なら文書の修正を書く
- 秘密情報は書かない。`上流` の記録は、後で上流（公開）に伝えることがあるので、個人のノートの内容を書き写さない

## 記録した後

- 元の作業に戻る。ハーネスはこの場では直さない。上流のものは、小さな誤字でも直さない（escalate する）。この Vault のもの（`子`）で、直し方が明らかで小さいものは今の作業の中で直してよい。そのときも記録を残し、改善案に「直した」と書く
- 記録のファイルは、今の作業のコミット（wiki の操作なら別の `harness(note): …` のコミット）に含める。wiki の操作のコミットは隠しパスを変えられないため
- プロジェクトについて学んだことを、Claude Code のメモリだけに保存しない
- `.claude/notes/` は通常の作業では読まない。読むのは評価のときだけ
