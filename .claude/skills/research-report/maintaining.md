# 型を足す・消す・直す

型は 12 個で試行を始め、使いながら足す・消す・直す（[ADR-0092](../../../.kit/harness/docs/adr/0092-research-report-types.md)）。直す判断は、記録の集計とユーザーの指摘で行い、思いつきで型を増やさない。

## 判断の材料

- **記録の集計**: `node .claude/scripts/output-log.mjs summary`。`--skill research-report` の出力を、`--kind` の型の id ごとに見る
  - 件数: 使われた型、使われない型
  - 上げ下げ: 既定の段階から毎回動かしている型は、既定が合っていない
  - 問題の種類: 長い・足りない・要点が分からない・段階が違う・形式
  - 型なし: `調査報告: 型なし（…）` の件数と、依頼の種類
- **ユーザーの指摘**: 型の推定が違うと言われた、必須の節が足りない・要らないと言われた。指摘はその場で `output-log.mjs issue …` に書く（write-for-reader の[記録](../write-for-reader/recording.md)）
- 見直しの時期: 子は月 1 回の harness-review、上流は kit-review で集計を読む。急ぐ指摘は、その場で直してよい

## 直し方

| 起きていること | すること |
|---|---|
| 同じ種類の「型なし」が 2 回以上 | 型を足す候補にする。3 回目で型を足す |
| 型の推定が同じ向きに 2 回以上違った | [型の選び方](select-type.md)の「依頼の言葉」の表を直す |
| 既定の段階から、同じ向きに毎回動かしている | 型の「既定」の段階を変える |
| 「足りない」が同じ節で続く | 型の「必須の節」に足す |
| 「長い」が続く | 型の「省くもの」に足す。必須の節を減らせないかを見る |
| 3 か月使われない | 消す候補にする。似た型に寄せられるなら寄せて消す |
| 2 つの型の必須の節がほとんど同じ | 1 つにまとめる |

- 型を足す・消す・名前を変えるときは、`SKILL.md` の型の一覧、[select-type.md](select-type.md) の表、このファイルを使う他のスキルのリンクを一緒に直す
- 規則を足すときは、[evidence.md](evidence.md) に根拠を足して ID で引く。記録の集計から分かったことも根拠にしてよい
- 型の数や分け方そのものを変える（例: 型を 2 つの軸に分ける）ときは、ADR を書く

## 型のファイルのひな形

`types/<型の id>.md`。型の id は英小文字とハイフン。どの型も同じ見出しにする（同じ種類は同じ構造にする）。

````markdown
# 型: <型の名前>（`<型の id>`）

## 目的

<読み手が読んだ後にすること。1〜2 文>

- 使う: <この型の場面>
- 使わない: <似ているが別の型になる場面と、その型へのリンク>

## 既定

| 読み手 | 段階 | 語彙の層 | 寿命 |
|---|---|---|---|
| <人・LLM・両方> | <1〜5> | <コード・技術・業務> | <一度読む・引き直す> |

## 冒頭の結論の形

<冒頭の 1〜3 行に何を書くか。例>

## 必須の節

<節の順と、それぞれに書くこと。番号付きの一覧>

## 語彙と粒度

<使う言葉、数で書くもの、粒度>

## 省くもの

<この型で書きすぎやすいもの>

## 書くときの指示

```
<書くときに読むプロンプト>
```

## 確かめ方

<段階の確かめ方に足すもの>

## よくある失敗

## 根拠
````
