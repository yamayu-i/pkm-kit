# 型: 実装への引き継ぎ（`handoff`）

## 目的

読み手（サブエージェント、次のセッション、実装を担う LLM）が、調査の結果だけを読んで、そのまま作業に入る。

- 使う: 調査を終えて実装を別のエージェントに渡す、中断して次のセッションに渡す
- 使わない: 人が読む報告なら、調査の中身に合う型を使う。中断と再開の手順そのものは、上流の dev-handoff に従う

## 既定

| 読み手 | 段階 | 語彙の層 | 寿命 |
|---|---|---|---|
| LLM | なし（write-for-reader の[LLM だけ](../../write-for-reader/readers.md#llm-だけ)） | コード | 一度読む |

形式は md に決める（html にしない）。

## 冒頭の結論の形

```
目的: <何を作る・直すか 1 文>。完了の条件: <確かめられる形で 1〜3 個>。
```

## 必須の節

1. **目的と完了の条件**: 何ができたら終わりか。確かめるコマンドやテスト
2. **確定した仕様**: 決まったこと。値・名前・振る舞いを具体的に
3. **決めていないこと**: 作業の中で判断してよいこと、判断せずに止めて聞くこと
4. **関係する場所**: ファイルのパスと、それぞれで何をするか
5. **調べて分かった事実**: 出典（パス・URL・コマンド）と確度付き
6. **試して失敗したこと**: 何を試し、なぜだめだったか。繰り返させないため
7. **使ってはいけない手段**: 規約・制約で禁じられていること（依存の追加、検査の迂回など）

## 語彙と粒度

- 「上記」「それ」などで指さず、ファイル名と識別子で書く
- 確かめた・推測・未確認を、事実ごとに書く
- 要るものは全件書く。字数で削らない

## 省くもの

- 調べた経緯、言い換え、挨拶
- 人向けの推敲（要約の冒頭、読みやすさのための言い換え）

## 書くときの指示

```
読み手は、この会話の文脈を持たない LLM。これだけを読んで作業に入る。
1. 最初に目的と完了の条件（確かめるコマンド・テスト）を書く
2. 確定した仕様、決めていないこと（判断してよい・止めて聞く）、使ってはいけない手段を分けて書く
3. 関係するファイルのパスと、それぞれで何をするかを書く
4. 調べて分かった事実を、出典と確度付きで全件書く
5. 試して失敗したことと、その理由を書く
「上記」「それ」で指さず、ファイル名と識別子で書く。
```

## 確かめ方

- 文脈を持たない読み手として読み、最初の 1 手（どのファイルを開くか、何を実行するか）が決まるか
- 完了の条件が、読み手が自分で確かめられる形か

## よくある失敗

- 完了の条件がなく、読み手がどこで止めるか分からない
- 決めていないことを書かず、読み手が勝手に決める
- 試して失敗したことを書かず、同じ失敗を繰り返させる

## 根拠

- サブエージェントへの依頼には、目的・出力の形・道具・境界を明示する（R12）
- 読み手が LLM だけのときの方式（write-for-reader の読み手、E12、E13）
