# 型: 点検（`audit`）

## 目的

読み手が、決まった基準に照らして漏れなく確かめ、見つかった件の対応を割り振る。

- 使う: セキュリティ、依存のライセンス、規約・ガイドラインへの準拠、アクセシビリティ、設定の点検
- 使わない: 1 つの変更の影響を見るなら [impact-analysis](impact-analysis.md)。上流のハーネスの週 1 回のセキュリティチェックは、上流の security-check の手順に従う（この型は、その手順の外で頼まれた点検に使う）

## 既定

| 読み手 | 段階 | 語彙の層 | 寿命 |
|---|---|---|---|
| 人 | 4 | 技術（件の場所はコード） | 一度読む |

## 冒頭の結論の形

```
<基準>で <範囲> を点検した。重さ別の件数: 重 <N> / 中 <M> / 軽 <L>。
最も重いもの: <1〜3 件>。読み手がすること: <1 つ>。
```

## 必須の節

1. **基準と範囲**: 照らした基準（規約の名前と版、チェックリスト）、点検した範囲、点検していない範囲と理由
2. **方法**: 機械で行ったもの（ツールと版、コマンド）と、目で見たもの
3. **全件の表**: 件ごとに同じ項目（何・どこ・重さ・根拠・対応）。重さの順
4. **分類ごとの結果**: 基準の項目ごとに結果。0 件は「なし」と書く
5. **対象外**: 理由付きで

## 語彙と粒度

- 重さの基準を書く（CVSS などの決まった基準があればそれ。なければ、データの消失 ＞ 漏洩 ＞ 誤った表示 ＞ 文言 のように書く）
- 件の根拠は、基準の項目の番号・節で書く
- ツールの出力の誤検知を除いたなら、除いた件数と理由を書く

## 省くもの

- 基準の各項目の説明（番号と名前で引く）
- 「主なもの」に絞ること

## 書くときの指示

```
読み手は、これで漏れなく確かめ、対応を割り振る。見落としは長さより高くつく。
1. 照らした基準（名前と版）、点検した範囲と、していない範囲を先に書く
2. 機械で行ったもの（ツール・版・コマンド）と、目で見たものを分けて書く
3. 冒頭に、重さ別の件数、最も重いもの、読み手がすることを書く
4. 全件を重さの順に、同じ項目（何・どこ・重さ・根拠・対応）で書く。件を省かない
5. 基準の項目ごとに結果を書き、0 件は「なし」と書く。誤検知として除いたものは件数と理由を書く
```

## 確かめ方

- ツールの出力の件数 ＝ 表の件数 ＋ 除いた件数 になっているか
- 基準の項目がすべて「分類ごとの結果」にあるか
- 見落としの代償が大きい点検は、文脈を持たない読み手（サブエージェント）に独立に一覧を作らせて突き合わせる（write-for-reader の段階 4）

## よくある失敗

- 基準の版を書かない
- ツールの出力をそのまま貼り、重さと対応がない
- 0 件の分類を書かず、見たのか見ていないのかが分からない

## 根拠

- 重さを決まった基準で付ける（R8）
- 範囲・含めた基準・除いた基準・件数を書く（R6）
- 全件を同じ項目で、0 件も書く（write-for-reader の段階 4、E7）
