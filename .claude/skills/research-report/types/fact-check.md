# 型: 事実の確認（`fact-check`）

## 目的

読み手が、1 つの問いの答えを得て、それを使って次を考える。

- 使う: 「X は本当か」「仕様ではどうなっているか」「この API は〜を返すか」「このバージョンで〜は使えるか」
- 使わない: 答えを受けてやるかを決めるなら [feasibility](feasibility.md)。概念の仕組みを理解したいなら [concept](concept.md)

## 既定

| 読み手 | 段階 | 語彙の層 | 寿命 |
|---|---|---|---|
| 人 | 2 | 技術 | 一度読む |

## 冒頭の結論の形

```
答え: はい / いいえ / 条件付き（<条件>）。確度: <確かめた・推測・未確認>。
根拠: <一次資料 1 つ>。
```

## 必須の節

1. **問いの言い直し**: 何に答えたか 1 文。問いが曖昧なら、どう解釈したか
2. **根拠**: 一次資料（仕様、ソース、公式ドキュメント、実際に動かした結果）。二次資料（ブログ、回答サイト）は一次資料が見つからないときだけ、そう明示して使う
3. **成り立つ条件**: バージョン、設定、環境、日付。答えが変わる条件
4. **扱わなかったこと**: 読み手が続けて聞きそうだが、答えていないこと

## 語彙と粒度

- 答えは最初の文に置く。「〜については」から始めない
- 一次資料は、版と場所（URL と節、`file:line`、コマンドと出力）まで書く
- 確度は 3 つで書く。「〜のはず」と「確かめた」を混ぜない

## 省くもの

- 背景の解説、歴史
- 一次資料で確かめたことの言い換え

## 書くときの指示

```
読み手は、この問いの答えだけを得たい: 「<問い>」
1. 最初の文に、はい・いいえ・条件付きの答えと確度を書く
2. 根拠は一次資料（仕様・ソース・公式ドキュメント・動かした結果）を、版と場所まで書く
3. 答えが変わる条件（バージョン・設定・環境・日付）を書く
4. 続けて聞かれそうだが答えていないことを 1 行ずつ書く
全体を 1 画面に収める。
```

## 確かめ方

- 根拠の資料の版が、問いの対象の版と合っているか
- 最初の文だけで問いに答えているか

## よくある失敗

- 二次資料だけを根拠に「確かめた」と書く
- 版を書かず、古い仕様の答えになる
- 答えの前に長い前置きを書く

## 根拠

- 答えを最初の文に置く（R13、write-for-reader の E4）
- 段階 2 の結論・要点・扱わなかったこと（write-for-reader の段階 2）
