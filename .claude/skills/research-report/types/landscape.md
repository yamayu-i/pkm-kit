# 型: 動向・先行事例の調査（`landscape`）

## 目的

読み手が、ある領域に何があるか・他ではどうしているかを知り、視野を広げる、または次に深く調べる先を決める。

- 使う: 「何があるか」「他のプロジェクトではどうしているか」「最近の動向」
- 使わない: 候補から 1 つを選ぶなら [tech-selection](tech-selection.md)（この型の結果を候補の出どころにしてよい）

## 既定

| 読み手 | 段階 | 語彙の層 | 寿命 |
|---|---|---|---|
| 両方 | 2 | 技術 | 引き直すことがある（残すなら wiki に取り込む） |

## 冒頭の結論の形

```
<領域>の取り組みは <N> 通りに分けられる: <分類 1>、<分類 2>、…。
<共通するパターン、または目立つ空白 1 つ>。調べた範囲: <情報源と日付>。
```

## 必須の節

1. **調べた範囲**: 情報源（検索の場所、リポジトリ、論文の DB）、検索の条件、日付、含めた基準と除いた基準。何件を見て何件を残したか
2. **分類**: 分類の軸（方式・規模・対象など）と、分類ごとの代表例 1〜3 件。代表例は同じ項目（名前・何をするか・特徴・出典）で
3. **共通するパターン**: 多くの例に共通する作り・考え方
4. **空白**: どの例も扱っていないこと、決着していない論点
5. **次に調べるとよいもの**: 深く調べる価値のある例と、その理由

## 語彙と粒度

- 網羅を約束しない。「調べた範囲の中では」と範囲で書く
- 各例は、事実（何をするか、いつから、規模）で書き、評価の言葉を書かない
- 日付を書く。動向は古くなる

## 省くもの

- 各例の詳しい紹介（代表例は 1〜3 行）
- 分類に入らない例の羅列（件数と除いた理由だけでよい）

## 書くときの指示

```
読み手は、この領域に何があるかを知り、次に深く調べる先を決める。
1. 冒頭に、分類の数と名前、共通するパターンか空白を 1 つ、調べた範囲と日付を書く
2. 調べた範囲（情報源・条件・日付・含めた基準と除いた基準・見た件数と残した件数）を書く
3. 分類の軸を明示し、分類ごとに代表例を 1〜3 件、同じ項目で書く
4. 共通するパターンと空白を分けて書く
5. 網羅を約束しない。範囲で書く
```

## 確かめ方

- 調べた範囲が、読み手が同じ手で調べ直せる形で書かれているか
- 分類が重ならず、残した例がどれかの分類に入っているか

## よくある失敗

- 見つけた順に例を並べ、分類がない
- 調べた範囲と日付がなく、どこまでの話か分からない
- 少数の例から「業界では〜が主流」と言い切る

## 根拠

- 情報源・条件・基準・件数を書く（R6）
- 一度に扱える項目は 3〜5 個（write-for-reader の E14）。分類の数もこれを目安にする
