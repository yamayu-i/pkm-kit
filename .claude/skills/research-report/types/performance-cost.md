# 型: 性能・コストの調査（`performance-cost`）

## 目的

読み手が、遅い・重い・高いの原因を知り、打ち手を選ぶ、または予算を決める。

- 使う: 処理が遅い、メモリ・容量が多い、API・クラウドの費用が高い、費用の見積もり
- 使わない: 振る舞いが壊れているなら [root-cause](root-cause.md)。製品の料金の比較が主なら [tech-selection](tech-selection.md)

## 既定

| 読み手 | 段階 | 語彙の層 | 寿命 |
|---|---|---|---|
| 両方 | 3 | 技術 | 一度読む |

## 冒頭の結論の形

```
今: <指標と値>（<測った条件>）。ボトルネック: <1 つ>。
推奨する打ち手: <1 つ>。見込み: <指標> が <値> から <値> へ、費用・手間 <…>。
```

## 必須の節

1. **指標と目標**: 何を測るか（p50・p95 の時間、メモリ、月額）と、目標の値
2. **測った条件と結果**: 環境、データの量、回数、ツール。読み手が同じ条件で測り直せる形で
3. **ボトルネック**: 資源ごと（CPU・メモリ・I/O・ネットワーク・外部の API）に使用率と待ちを見て、どこで詰まっているか
4. **打ち手の比較**: 打ち手ごとに、見込みの効果（値で）・費用・手間・リスク。表にする
5. **推奨と、効果の確かめ方**: 打った後に何を測れば効いたと分かるか

## 語彙と粒度

- 「遅い」「重い」ではなく、指標と値で書く。平均だけでなく p95 などの分布を書く
- 費用は、単価 × 量 ＝ 月額 のように、計算の式を見える形で書く
- 見込みの効果が推測なら、そう書き、根拠（似た例、机上の計算）を添える

## 省くもの

- 測っていない部分の推測による最適化の提案
- プロファイラの出力の全文（要点と、置き場所を示す）

## 書くときの指示

```
読み手は、これを読んで打ち手を選ぶ、または予算を決める。
1. 冒頭に、今の値（測った条件付き）、ボトルネック、推奨する打ち手と見込みの効果を書く
2. 指標と目標を値で書く。平均だけでなく分布（p95 など）を書く
3. 測った条件（環境・データ量・回数・ツール）を、測り直せる形で書く
4. 資源ごとに使用率と待ちを見てから、ボトルネックを決める
5. 打ち手を、効果（値）・費用・手間・リスクで比べた表にする。費用は計算の式で書く
6. 打った後に何を測れば効いたと分かるかを書く
```

## 確かめ方

- ボトルネックと推奨の打ち手がつながっているか（ボトルネックでない所を最適化していないか）
- 費用の式の単価と量に、出典か測った値があるか

## よくある失敗

- 1 回だけ測った値で判断する
- 測らずに「たぶんここが遅い」で打ち手を出す
- 費用を合計だけで書き、どの量が効いているか分からない

## 根拠

- 資源ごとに使用率・飽和・エラーを測ってから決める（R9）
- 打ち手を同じ観点で比べ、推奨を 1 つ選ぶ（write-for-reader の段階 3）
