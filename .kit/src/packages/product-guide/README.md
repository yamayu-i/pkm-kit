# Product guide

ユーザー体験と現在の仕様を、正本の Markdown と実装の画面例から生成する。設計はハーネスの ADR-0042。

## 使う人の入口

子 Vault のファイル一覧で pkm-guide/user-experience.html を開く。PKM HTML が必要。外部に渡すときは Export HTML to tmp/ を使い、色と画像を埋め込む。

## 更新する人の手順

1. 変更に関係する product/ の原本だけを直す。HTML を LLM に書かせない。
2. 新しい面なら catalog.json に原本・実装・登録された View と画面の条件を追加する。画像が不要なら理由を書く。
3. UI や撮影条件を変えたら、上流の開発環境で pnpm --filter product-guide capture を実行する。
4. pnpm build、node .claude/scripts/verify.mjs --plugin、pnpm --filter product-guide preview:ui を実行する。
5. 原本、生成器、CLI、HTML、画像と manifest を一緒にコミットする。

コマンドはリポジトリのルートから node .kit/bin/product-guide.mjs inventory / build / check。pnpm のコマンドは .kit/src/ で実行する。inventory は原本と画面対応の一覧、check は差分のある入力と修正手順を出す。HTML 本文や画像のデータは標準出力に流さない。

## 再生成するもの

章立て・目次・見出し ID・相互リンク・全文の HTML 変換・用語の一覧・画像配置・出典はコードで組む。説明の意味、場面、条件と結果は原本に書く。見出しの形が揃っていても意味が正しいとは限らないので、実装との照合も行う。

画面例は実装コンポーネントと CSS、固定した合成データから撮る。Obsidian の API・周囲の枠・アイコン API の一部はモックであり、実機そのもののキャプチャではない。個人の Vault は読まない。時計は 2026-11-16 10:00 JST、ロケールは ja-JP。ライト／ダーク × 1024／390px で、画面の領域を撮る。

manifest は入力の指紋と画像ハッシュ、画面内の文字のハッシュ、OS・ブラウザを記録する。Node だけの check は生成物・入力・画像の一致を検査する。上流 CI の capture --check は再描画した文字を比較し、同じ OS とブラウザなら画像も比較する。別 OS の PNG のバイト一致は要求しない。固定環境の画像を確認する場合は同じフォント環境も使う。

## 子への配布と復旧

HTML と ui/ は上流が持つ生成物で、clone と上流の merge で届く。子で npm やブラウザをインストールする必要はない。子のノートや設定の変更がないため移行は不要。同じパスに子のファイルがあった場合は上書きせず、git の衝突で退避・解決する。

画像が欠けるときは同期・取り込み漏れを確認する。子で build や capture を実行して上流のものを直さず、直らなければエスカレーションする。

## 今回の完了条件

生成・配布・検査の仕組みの完成を今回の完了条件とする。収録した仕様本文と画像の意味上の最新 UI への一致は、今後この仕組みで継続的に更新する。
