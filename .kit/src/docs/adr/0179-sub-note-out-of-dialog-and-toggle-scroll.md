# ADR-0179: サブの編集ダイアログから Note を外し、開閉でスクロール位置を保つ

- 状態: 承認
- 日付: 2026-11-15

## 背景

[Issue #179](https://github.com/yamayu-i/pkm-kit/issues/179)。issue 画面のサブについて、次の困りごとがある。

- 「Edit sub-issue」のダイアログ（ADR-0142）の Note 欄は、自前の CodeMirror に段落ごとの `MarkdownRenderer` の描画を重ねた簡易エディタで、Obsidian 本体の Live Preview と見た目も操作も違う。段落ごとに丸ごとソースへ切り替わり、リスト・チェックボックス・リンクの入力補助も効かない
- 下部のサブカード（ADR-0161）を開閉すると、スクロール位置が変わり、押した行を見失う

本文の表示と編集は、すでに下部のサブカード（issue 本体の Live Preview）に集約している（ADR-0165）。

## 決定

### ダイアログから Note を外す

- 「Edit sub-issue」のダイアログは項目（題・status・委任先・日付・見積もり・依存先）だけを直す。Note 欄をなくし、保存しても本文に触れない
- ダイアログに「Open note」を置く。押すとダイアログを閉じ、そのサブを開いて、下部のカードの題を画面の上端に出す
- 上部のサブ一覧（ヘッダーの「Sub-issues」カード）の行にも、同じ動きのアイコンボタン「Open note」（`file-text`）を置く。ダイアログを経ずに本文へ行ける
- 自前の簡易エディタ（`NoteEditor`、`core/note-preview.ts`）は使う場所がなくなるので消す

### 開閉でスクロール位置を保つ

- 下部のカードの題の行から開閉したときは、押した題の行の画面上の位置を変えない。変わるのはその下だけにする。開いた本文が画面の外に出ても、自動ではスクロールしない
- 例外: 開いたサブの題の行が上端に浮かんでいる（ADR-0161 の追記。カードそのものは上端より上にある）状態で、浮かんだ行から閉じたときは、そのカードの題が上端に来るまでスクロールを戻す
- Live Preview と Reading で同じ動きにする
- 実装: 開閉の前に題の行の画面上の位置を測り、開閉で描き直した後に、ずれた分だけスクロールを戻す。原因（デコレーションの作り直し、高さの見積もり、Reading の遅延描画）によらず同じ処理で保つ。例外のときは、位置ではなく「題を上端に」を目標にする。Reading で題が DOM にないときは、セクションの行番号から位置を求める

## 理由

- 本文の編集を本体の Live Preview の 1 か所に寄せれば、見た目と操作が本体と同じになる。非公開 API に頼らずに済み、本体の更新で壊れない
- 押した行が動かなければ、開閉の前後で読んでいた場所を見失わない。浮かんだ行から閉じると、題より上のカードは画面外にあるので、位置を保つと閉じたサブがどこか分からなくなる。題まで戻せば、閉じた結果が見える

## 却下した案

- **本体のエディタ（`MarkdownEditor`）をダイアログに埋め込む**: 見た目と操作は本体と同じになるが、非公開 API（`app.embedRegistry`）から内部のクラスを取り出す必要があり、本体の更新で壊れうる。本文の編集が 2 か所に分かれる
- **自前の簡易エディタを本体に寄せて直す**: 行・記号ごとの描き替えを作り直すことになり、それでも本体と同じにはならない
- **開いた本文が画面外に出るときに、本文の先頭まで自動でスクロールする**: 押した行が動く。開閉でスクロール位置が変わること自体が困りごと
- **開閉に高さのアニメーションを付ける**: CodeMirror の高さの計算とぶつかり、Live Preview と Reading で揃えられない

## 影響

- ADR-0142 の Edit ダイアログの項目から本文を除く。ADR-0161 の開閉の挙動にスクロールの規則を足す
- 部品の表（`docs/design.md`）のサブの項目のカードの行に、開閉でスクロール位置を保つことを書く
- データ形式・設定・依存は変わらない。子の Vault に手を入れないので移行は要らない。`.kit/changes/` に変更を 1 件書く
- スクロールの補正は Obsidian の描き方に依存するので、マージ後に実機で確かめる
