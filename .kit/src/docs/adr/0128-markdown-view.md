# ADR-0128: ノートの表示を自作プラグイン pkm-markdown で整える（インラインコードのコピー、本文のタグを文字に、見出しと箇条書き）

- 状態: 承認
- 日付: 2026-11-12

## 背景

[Issue #128](https://github.com/yamayu-i/pkm-kit/issues/128)。ノート（Markdown）の表示について、次の 3 つの要望がある。

1. インラインコード（`` `...` ``）の中身をよくコピーするが、範囲を選んでコピーするのが手間
2. 本文の `#` で始まる語（`#同期` など）が、タグとして色付きの丸い札で表示され、押すと検索が開く。この Vault の群ではタグの機能を使わない（分類は frontmatter と wiki のリンクで行う）ので、見た目がうるさく、誤って押すと邪魔になる
3. 見出し（H1〜H3）と箇条書き（記号・番号・チェックボックス）が Obsidian の既定のままで、階層が読み取りにくい

Obsidian には、本文の `#foo` をタグとして解釈するのを止める設定がない。設定で止められるのは、タグの一覧の画面（コアプラグイン「タグ」、`tag-pane`）だけである。

## 決定

新しい自作プラグイン **pkm-markdown**（ノートの表示の改善をまとめる）を作り、次の 3 つを行う。モバイル対応。ほかのプラグインに依存しない。

### 1. インラインコードのコピーボタン

- インラインコードにカーソルを合わせると、右上に枠のないアイコンボタン（コピーのアイコン。面はノートの面と同じ色で、透明に見せる）を出す。押すと中身（`` ` `` を除く）をクリップボードに書き、通知する。書けなければ失敗を通知する（成功したふりをしない）
- 閲覧モード: `MarkdownPostProcessor` で、`pre` の中にない `code` にだけ付ける
- ライブプレビュー: CodeMirror の拡張（`ViewPlugin`）で、マウスの下の要素が Obsidian の描いたインラインコード（`.cm-inline-code`）かを調べ、そうなら浮かせたボタンを出す。コピーする中身は、その要素の位置（`posAtDOM`）から文書の行を読み、前後の `` ` `` までを取る。カーソルがそのコードの中にある（記号が見えている）間は出さない
- ホバーのない端末（スマホ・タブレット）: 閲覧モードではインラインコードをタップすると出す。編集中は出さない（タップはカーソルを置く操作なので）

### 2. 本文の `#` で始まる語をタグとして表示しない

- 閲覧モード: タグの要素（`a.tag`）を、同じ文字の普通のテキストに置き換える（色も札もなく、押しても何も起きない）
- ライブプレビュー: タグの装飾（`.cm-hashtag`）の色・背景・角丸を消して本文と同じ見た目にし、押したときに検索が開かないようにする
- コアプラグイン「タグ」（`tag-pane`）を無効にする。`.kit/obsidian-required.json` の `core-plugins.json` に `"tag-pane": false` を足し、子の設定を書き換える移行を付ける
- frontmatter の `tags` は変えない（プロパティ欄の表示もそのまま）。規約の項目なので
- Obsidian の中ではタグとして数えられること自体は残る（検索の `tag:` も効く）。止める手段がないため。見た目と画面からは消える

### 3. 見出しと箇条書きのスタイル（線を使わず静かにする案）

pkm-markdown の `styles.css` に置き、閲覧モードとライブプレビューの両方に効かせる。色はデザイントークン（`--vt-*`）だけで付け、フォントは固定しない（[design.md](../design.md)）。

- 枠や帯を使わず、太さ・余白・色で階層を見せる。見出しの大きさは Obsidian の既定のまま（実装の前の合意では H1 2 倍・H2 1.4 倍・H3 1.1 倍としたが、文字の大きさのトークンは px で、ノートに使うと利用者の文字の大きさの設定に追従しない。検査もこれを許さないので、ユーザーと相談して既定のままにした）
  - H1: 太字。下に primary の色の短い線（幅 40px、高さ 4px、角丸）
  - H2: 少し太く（semibold）、上に広い余白
  - H3: 少し太く（semibold）、文字は on-surface-variant
- 箇条書き: 記号を小さく（本文の文字の 0.3 em ほど）、`outline` の色にする（`text-faint` はプラグインのトークンにない）。深さで ●（塗りの丸）→ ○（白抜きの丸）→ –（短い横線）の 3 段をくり返す（4 段目は ● に戻る）。行間を広めにする
- 同じ深さのガイド線: 同じ深さの項目が分かるように、項目の記号の真ん中から、次の同じ深さの項目の記号の真ん中まで、1px の縦線を引く（間に子の項目があれば、その左を通る）。線と上下の記号との間には、同じ幅の隙間（5px）を空ける。最後の項目からは引かない。チェックボックスのリストには引かない。色は `outline-variant`（本文の文字の色の 14%。案 A の線より薄い）。線は閲覧モードだけで引く。ライブプレビューは行ごとの要素で入れ子の形を持たないので、Obsidian 自身のネストの線の色を同じ薄い色にする
- 番号付きリスト: 番号を `outline` の色にし、桁がずれない数字（`tabular-nums`）にする
- チェックボックス: 角丸の枠にし、チェックすると primary で塗り、on-primary のチェックを描く。1 行目の行の高さの中央に置く（Obsidian 自身のチェックボックスの `margin` より優先されることを、実機とプレビューで確かめる）。完了した項目の文字は薄くして取り消し線を引く
- H4〜H6、引用、表、コードブロックは変えない（今回の要望の外）

案を見比べたプレビュー（3 案）は Issue に記録する。

## 理由

- 3 つとも「ノートの表示」に関わり、今あるプラグインはどれも役割が狭い（タスク、テンプレート、HTML、図など）。1 つの小さなプラグインにまとめると、どこを見ればよいかが分かり、不要なら無効にするだけで元に戻せる
- タグの解釈は止められないので、見た目と操作で止めるのが取れる手段のうちで最も小さい
- 見出しと箇条書きを `pkm-theme.css`（トークンから作るスニペット）ではなくプラグインの `styles.css` に置くのは、スニペットの役目が「Obsidian 本体の色の固定と図の配色」で、レイアウトを含めると役目が広がるため。プラグインの `styles.css` はほかのプラグインと同じく、生成した `tokens.css` の `--vt-*` を使える
- 線を使わない案（3 案のうちの B）をユーザーが選んだ。ノートは長く読むものなので、装飾を減らして余白で区切る方が落ち着く
- 箇条書きだけは、案 A の「深さで形を変える」と「縦のガイド線」を、B の薄さに合わせて取り入れた。深い入れ子で、どの項目が同じ深さかを見分けられるようにするため

## 却下した案

- **スニペット（CSS）だけでタグを隠す**: 閲覧モードではタグは `a` 要素のままで、押すと検索が開く。CSS の `pointer-events: none` では文字の選択もできなくなる
- **本文の `#` を書き換える（`\#` にエスケープする）**: ノートの本文を変えることになり、DailyNote の保護（ハーネスの ADR-0007）に当たる
- **既存のプラグイン（pkm-template など）に足す**: 役割が混ざり、片方を無効にするともう片方も消える
- **見出しに帯や区切り線を付ける案（A・C）**: ユーザーが B を選んだ（箇条書きの形とガイド線だけは A から取り入れた）
- **コピーボタンを常に出す**: インラインコードは文中に多く、常に出すと本文が読みにくい

## 影響

- 追加: `.kit/src/packages/pkm-markdown/`（ソース、テスト、`styles.css`、`tokens.css`）、ビルドの成果物 `.obsidian/plugins/pkm-markdown/`、`.kit/owned-paths.json` の対象
- 変更: `.kit/obsidian-required.json`（`community-plugins.json` に `pkm-markdown`、`core-plugins.json` に `"tag-pane": false`）、`pkm-ribbon` など他のプラグインは変えない
- 子の Vault: 移行 `0128-pkm-markdown` で、`.obsidian/community-plugins.json` に `pkm-markdown` を足し、`.obsidian/core-plugins.json` の `tag-pane` を `false` にする。`.kit/changes/` に書く
- 依存の追加なし（`@codemirror/state` / `@codemirror/view` は pkm-task・pkm-template と同じ版を、Obsidian が持つものとして external で使う。構文木（`@codemirror/language`）は使わない）
- セキュリティ: クリップボードへの書き込みだけ（読み取らない）。外部に通信しない
