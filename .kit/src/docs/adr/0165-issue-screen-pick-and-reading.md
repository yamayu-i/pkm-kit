# ADR-0165: issue の本文表示を下部に集約し、Pick の後にタイマーを出す

- 状態: 承認
- 日付: 2026-11-15

## 背景

issue 画面の上部と本文側にサブがあり、どちらでも本文を展開できた。Pick と再生も別々に並んでいた。下部のサブ間には空行が残り、Reading View ではスクロール中に画面が上下に揺れるとの報告があった（#165）。変更方針はチャットで承認された。

## 決定

- 上部のサブ一覧は題・状態・補足・実績・操作を扱い、本文は展開しない。本文は下部のサブカードで開く（ADR-0142 の本文表示を変更）。
- 未 Pick の issue・サブにはタイマーの位置に Pick を表示する。今日のボードに載せた後は再生・停止を表示する。記録中なら日付が変わっても停止できる。
- Next でないものを Pick するときは、プロパティの変更内容をダイアログで示す。キャンセルなら変更せず、承認されたら Next にしてからボードへ載せる。Next は確認もプロパティ更新も不要。
- issue は `status: open`・`clarified: true` とし、`scheduled`・`tickler`・`delegated_to`・`revisit` を解除する。サブは `status: open` とし、`scheduled`・`delegated_to` と将来の `start` を解除する。期限・期間の終わり・本文・worklog は保持する。
- 下部カードの余白を詰める。Live Preview の閉じたサブは末尾の空行まで表示上の置き換えに含める。ファイルの空行は削除しない。本文にカーソルがある間は本文を表示する（ADR-0161 の折り畳み範囲を変更）。
- Reading View のカスタムヘッダーは標準の `.mod-header` 内へ差し込む。仮想スクロールが管理する sizer の直下の並びに介入しない（ADR-0077 の差し込み位置を変更）。

## 理由

本文の表示場所をそろえ、Pick してから記録する操作の順を画面に反映する。Next に必要な変更を確認できるようにし、既存の Calendar などを黙って消さない。Reading View のスクロール位置や高さの計算と、ヘッダーを先頭へ戻す処理との競合を避ける。

## 却下した案

- ファイルの空行を削除する: 表示の改善のために本文を書き換える必要はない。
- Next でないものを確認なしに Pick する: Calendar や将来の開始日が変わることに気づけない。

## 影響

データ形式・依存は変えない。ヘッダー差し込みの変更は共有実装のため通常ノートの Reading View にも適用する。スクロールの実機確認はマージ後に行う。
