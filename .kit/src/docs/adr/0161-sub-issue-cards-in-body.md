# ADR-0161: サブの項目だけをカードにし、本文は issue 本体の Live Preview で直接編集する

- 状態: 一部置換（ADR-0165, ADR-0197, ADR-0239）
- 日付: 2026-11-15

## 背景

ADR-0158 は、本文のサブ領域（最初の `<!-- sub-issue` から後ろ）全体を 1 つのウィジェットに置き換え、サブの本文を textarea で編集する、と決めた。使ってみると次の困りごとがある（#161）。

- Live Preview で Notes を入力すると、入力が止まって 600 ms で保存される。保存すると本文は整形され（先頭の空行と末尾の空白を除く）、読み戻した値で欄が上書きされるので、直前に打った改行が消える。題も同じで、末尾の空白が消える
- 本文は素の Markdown なのに、Live Preview ではなく textarea で書く。リンク・リスト・チェックボックスが効かない
- カードの編集は `TaskWriter`（ファイルを書き換える）を通る。Obsidian のエディタが保存する前の入力と食い違うおそれがある

サブの md は、項目（`<!-- sub-issue` から `-->` まで。HTML コメントの中の YAML）の後ろに、素の Markdown の本文が続く形である（ADR-0135）。本文は HTML コメントの外にあるので、issue 本体の Live Preview がそのまま描ける。

## 決定

### 描く単位

置き換えるのは、サブ 1 件ごとの項目のブロック（マーカーの行から `-->` の行まで）だけにする。本文は置き換えず、issue 本体の Live Preview と Reading が描き、編集する。textarea はなくなる。対象は `issue/*.md` だけ。ソースモードでは描き替えず、md をそのまま見せる。ヘッダーの「Sub-issues」カードは変えない。

### 項目のカード

- 1 件 1 つ。行は status のアイコン・題・補足・「今日に載せる」（ADR-0158 の行と同じ）と、左に開閉の矢印
- 開くと、題・status・委任先・日付のチップ・見積もり・依存先の欄をカードの中に出す（ADR-0158 の欄から本文を除いたもの）。欄の下に「Show source」
- 読めなかったブロック（`-->` はあるが項目を読めないもの）は、警告の行「Could not read this block」のカードにする。開閉と編集はなく、「Show source」だけを置く。`-->` がないブロックは置き換えない（生の md のまま）
- 題は入力が止まって 600 ms か欄を離れたときに保存する（Reading は欄を離れたときだけ）。項目の選択は選んだ時点で保存する。検査（`touchedSubErrors`）は今までと同じで、通らなければカードの中に日本語の説明を出し、書かない
- 題の保存は `trim` した値を書くので、保存した値が入力中の値と「整形すれば同じ」なら欄を上書きしない（末尾の空白を消さない）

### 本文の開閉（アコーディオン）

- 開いているサブの本文はそのまま見える。閉じているサブの本文は、範囲（`-->` の次の行から、最後の空でない行の終わりまで）を中身のない block の置き換えで隠す。空の本文は隠すものがない
- Reading は、閉じているサブの本文のセクションに `display: none` の class を付ける。開閉を切り替えたら、描き直さずに class だけを付け外しする
- 既定は閉じている。開閉はこの端末に保存する（`data.json` の `subOpen`。ADR-0158 と同じ。md には書かない）。カードと本文で、開閉は 1 つ
- 閉じるときにカーソルが本文の中にあれば、カーソルを項目のカードの終わりに移してから隠す
- 隠した範囲にはカーソルが入らない（`EditorView.atomicRanges`）。選択がその範囲に重なるとき（全選択など）は、隠すのをやめて見せる

### 開いたサブの題の行を上端に浮かべる（2026-11-15 追記）

- 開いたサブの題の行（status・題と開閉・Pick）が、スクロールでスクロール領域の上端を越えたら、そのサブの本文の終わりまで上端に浮かべる。本文の終わりが近づいたら上へ押し出す（CSS の sticky と同じ見え方）。Live Preview と Reading の両方。項目の欄は浮かべない
- CSS の `position: sticky` は使わない。題の行はカードの中にあり、カードと本文は兄弟の要素なので、sticky では本文の終わりで止められない。画面外の要素は DOM から外れる（CodeMirror のビューポート、Reading の遅延描画）ので、カードが DOM にないこともある
- 代わりに、スクロール領域の親に、題の行と同じ部品の行を重ねる。どのサブを浮かべ、どれだけ押し出すかは位置の数値から決める（`core/sub-sticky.ts`）。位置は、Live Preview では CodeMirror の高さの情報（`lineBlockAt`）、Reading ではカードと本文のセクションの位置から求める
- 浮かべた行から閉じたときは、そのカードを上端に出す（本文が消えて、読んでいた位置を見失わないため）

### カードの編集は、エディタの文書を直接書き換える（Live Preview）

- カードを変えるときは、書き換え後の項目のブロックを作り、その範囲（マーカーの行から `-->` の行まで）だけを CodeMirror のトランザクションで置き換える。本文・カーソル・入力中の状態に触れず、Obsidian の通常の保存の流れに乗る。Ctrl+Z でカードの操作も戻せる
- 範囲と書き換え後の項目は、文書の今の文字列から求める（ディスクの内容ではなく、エディタが持つもの）。検査は文書の今の姿で行う
- status が変わったときの statuslog への記録と、closed / canceled のときのタイマーの停止は、書き込み方によらず同じにする（`TaskWriter` の後処理を取り出して共有する）
- Reading は今までどおり `TaskWriter.updateSub`（ファイルを書き換える）を使う。エディタがないので、食い違わない

### 見た目の判定と描き直し

- Live Preview のウィジェットは、文書とカーソルの変更のたびに、文書から項目の範囲と本文の範囲を求めて作り直す。同じサブのカードは DOM を作り直さず、Preact で中身だけを更新する（入力中のフォーカスを失わない）
- カーソルが項目のブロックの中（先頭と終わりの位置は除く）にあるときは、そのカードを外して生の md を見せる。領域に入る手段は「Show source」（ブロックの先頭の次の位置にカーソルを置く）

### 文言

ヘッダーのカードと同じく、常に出る文言は英語、エラーの説明は日本語（`docs/design.md`「文言」）。部品の表の「本文のサブの領域」の行を、サブごとのカードの行に置き換える。

## 理由

- 本文を issue 本体の編集に任せれば、textarea と、保存して読み戻して欄を上書きする往復がなくなり、改行が消える問題は構造ごとなくなる。リンク・リスト・チェックボックス・IME・Undo は Obsidian 本来の動きになる
- 項目の範囲だけを書き換えれば、入力中の本文を壊さない。ファイルを書き換えると、エディタの保存前の入力と食い違い、入力が消えるおそれがある
- ADR-0142 が Live Preview の描き替えを却下した理由は「CodeMirror の拡張は作るのが重い」だったが、ADR-0158 で拡張はもう作ってあり、粒度を小さくするだけで済む
- 開閉の保存先を端末にする理由は ADR-0158 と同じ（md が開閉で汚れず、同期の衝突が増えない）

## 却下した案

- **エディタ（Live Preview）を本文の欄に埋め込む**: 公開 API がなく、内部のクラスに依存して壊れやすい。ウィジェットの中でエディタが入れ子になり、キーと IME とフォーカスが外のエディタとぶつかる
- **textarea を残し、保存時の整形だけをやめる**: 改行の問題は直るが、素の Markdown を素の textarea で書く点は直らない。本文の欄が別にあるので、文書の中の本文と二重になる
- **閉じたサブの本文を Obsidian の折りたたみ（fold）で隠す**: 折りたたみの状態は Obsidian が持ち、開閉を端末に保存する仕組みと合わない
- **カードの編集も `TaskWriter` で行う**: 実装は少ないが、エディタに未保存の入力があると食い違う

## 影響

- ADR-0158 を置き換える（「描く場所と対象」「見た目」「開いたときの編集」「実装の方針」のうち、領域全体を 1 つのウィジェットにする部分と本文の textarea。ADR-0142 の「本文の見え方」の置き換えは ADR-0158 から引き継ぐ）。展開の状態の保持（`subOpen`）は残す
- 部品の表（`docs/design.md`）の「本文のサブの領域」を直す。`.vt-sub-area` / `.vt-sub-body` はなくなり、サブごとの `.vt-sub-card` になる
- `sub-issue.ts` の `subAreaStartLine` / `subAreaOffset` / `subAreaRole` を、項目の範囲と本文の範囲を返す関数に置き換える
- 設定の `data.json` は変わらない。子の Vault に手を入れないので移行は要らない。`.kit/changes/` に変更を 1 件書く
- Live Preview の描き替えは Obsidian の内部の描き方に依存するので、実機で確かめる（PR のあとの本番での確認）

## 追記（ADR-0181）

終わったサブ（closed / canceled）は md の末尾へ送られる。本文（Live Preview と Reading）では、終わったサブのカードと本文を隠し、「Show N closed」を押すまで出さない（状態は保存しない）。
