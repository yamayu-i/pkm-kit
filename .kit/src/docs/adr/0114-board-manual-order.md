# ADR-0114: task board のグループの中でカードを手で並べ替える

- 状態: 提案
- 日付: 2026-11-09

## 背景

task board のカードは、グループの中で「ボードに載せた順の issue → その日の routine」の順に出る（ADR-0009、ADR-0015）。順番を変える手段がなく、やる順や大事な順に並べられない。
グループへの移動はドラッグとカードのメニューでできるが（ADR-0034 で置き場所は翌日にも引き継ぐ）、同じグループの中の順番は選べない。

## 決定

### 並べ替えの操作

- グループ（サブグループと未分類を含む）の中で、カードを手で並べ替えられる
- PC: カードを別のカードの上に落とすと、そのカードの前に入る。グループの空いているところに落とすと末尾に入る。別のグループのカードの上に落とせば、移動と並べ替えを一度に行う
- モバイル（ドラッグが使えない）: カードのメニュー（`···`）に「Move up」「Move down」を足す。先頭・末尾では出さない
- 「Done」の欄は並べ替えない（終わった順のまま）

### 記録の形

ボードの操作ログ（ADR-0020）に `order` を足す。

```json
{"id":"bo_0123456789","at":"2026-11-09T00:00:00.000Z","date":"2026-11-09","op":"order","group":"午前/集中","tasks":["i-3","r-1","i-8"]}
```

| op | 追加の欄 | 再生したときの効果 |
|---|---|---|
| `order` | `group`（null で未分類）、`tasks`（そのグループでの並び。issue と routine の ID） | そのグループの並びを変える |

- 並べ替えるたびに、そのグループの並び全体を書く。同じグループへの操作は後の操作が勝つ（ほかの op と同じ）
- 書く `tasks` は、画面に出ている並びに、前の並びにあって今日は出ていない ID（今日は出ない routine、完了した issue など）を、前の並びで直前にあった ID の後ろに差し込んだもの。今日いない ID の位置を失わないため

### 並びの決め方

- グループの中の並びは、そのボードの日付までの `order` のうち、そのグループの最後のもの（ボードの日付 → 操作の時刻の順。ADR-0034 の置き場所の記憶と同じ）。**翌日以降のボードにも引き継ぐ**
- その並びにある ID はその順で出し、ない ID（新しく載ったもの、自動で載った今日の予定、別のグループから来たもの）は、これまでの順（載せた順の issue → routine）で**末尾**に出す
- グループを改名・削除すると、そのグループの並びは使われなくなる（置き場所と同じ）
- MCP の `get_board` も、グループの中のカードを同じ順で返す

## 理由

- 並び全体を書くと、再生の結果が操作の順だけで決まり、どの端末の組み合わせでも有効な並びになる。相対位置（「i-3 の前」）だけを書くと、i-3 が今日いないときや、2 台が同時に動かしたときの結果が分かりにくい
- 引き継ぐのは、毎日載る routine や持ち越した issue を毎日並べ直さずに済ませるため。置き場所の記憶と同じ仕組みにそろえると、人にも説明しやすい
- 新しいものを末尾に出すと、並べた順を崩さない
- ログに書くので、issue のファイルや `updated` は変わらない（ADR-0034 と同じ理由）

## 却下した案

- **`place` に `before`（前に来る ID）を足す**: 古い版でも `place` として読めるが、前に来る ID が今日いない・動いたときの並びが決まりにくい。並べ替えだけのときにも `place` を書くことになる
- **issue / routine の frontmatter に `order` の数値を持たせる**: 並べ替えるたびに複数のノートが変わり、`updated` とコミットが増える。グループごと・日ごとの違いも持てない
- **並びをその日だけにする**: 仕組みは小さいが、毎日載る routine を毎日並べ直すことになる
- **新しいカードを先頭に出す**: 自動で載る今日の予定が、並べた順の上に割り込む

## 影響

- pkm-task の `main.js`、`.kit/bin/` の CLI（MCP）が変わる。移行はない（既存のログはそのまま読める。`order` がなければこれまでの順）
- 古い版の pkm-task は `order` の行を「操作が不正です」として報告し、その行を飛ばす（並びは読まないが、ボードのほかの状態は壊れない）。プラグインは Vault と一緒に同期されるので、同期を終えれば消える
- ADR-0009 / ADR-0015 のグループの中の並び（載せた順）を、手で並べていないときの既定にする
