# ADR-0158: 本文のサブ領域をアコーディオンに描き、その場で編集する

- 状態: 承認（一部置換: 0161, 0190, 0239）
- 日付: 2026-11-15

## 背景

ADR-0142 で、サブイシューを親の issue 画面のヘッダーの「Sub-issues」カードで見る・作る・並べると決めた。そのとき本文のサブ領域（最初の `<!-- sub-issue` から後ろ）は、次のように扱うことにした。

- Reading では隠す
- Live Preview では描き替えない（「CodeMirror の拡張は作るのが重い」として却下）

使ってみると、次の困りごとがある（#158）。

- Live Preview では、本文の下にサブの md が生の文（HTML コメントと YAML）のまま見える
- Reading では本文の下が空に見え、サブがどこにあるか分からない

ヘッダーのカードは、Timeline と作業時間の記録（再生 / 停止）という別の役割を持つので、なくせない。本文の位置でも、サブを読める・直せるようにしたい。

## 決定

### 描く場所と対象

本文のサブ領域（最初のマーカーから後ろ）を、Live Preview と Reading の両方で、同じ部品（「Sub-issues の本文ビュー」）に描き替える。対象は `issue/*.md` だけ。ソースモードでは描き替えず、md をそのまま見せる（壊れたときに直せる）。ヘッダーのカードは今のまま残す。

### 見た目

- 1 件 1 行: status のアイコン（`StatusIcon`）と題。行を押すと開閉する。左に開閉の矢印を置く
- 読めなかったブロック（`invalid-sub-issue`）は、行に警告のアイコンと「Could not read this block」を出し、開くと md の原文を読み取り専用で見せる。書き換えない
- closed / canceled のサブも、本文の一覧には打ち消し線で出す（ヘッダーのカードのような「Show closed」はない）
- サブが 1 件もなければ何も描かない（領域がないので描くものがない）

### 開いたときの編集（その場で）

開いた行に、項目と本文を直接編集できる欄を出す。ダイアログは使わない。

| 項目 | 欄 |
|---|---|
| 題 | 1 行の入力 |
| status | メニュー（delegated は委任先を選ぶ。someday は予定と期限を外す。ヘッダーと同じ規則） |
| 委任先、期間、予定（Calendar）、soft deadline、deadline | 項目のチップ。押すと日付・委任先の選択（ADR-0142 の Edit ダイアログと同じ部品） |
| 見積もり | 小さい入力（`2h` など） |
| 依存先 | 同じ親のサブのチェック |
| 本文 | 複数行の入力欄 |

- 書き込みは既存の `TaskWriter.updateSub`（検査 `checkSubIssues` を通る）を使う。題・本文の入力は、Live Preview では入力が止まって 600 ms か、欄を離れたときに保存する。Reading では、保存でセクションが描き直されて入力中のフォーカスを失うので、欄を離れたとき（Enter を含む）だけ保存する。項目の選択は選んだ時点で保存する。検査に通らなければ行の中に日本語の説明を出し、書かない
- 削除と並べ替えはヘッダーのカードのメニューに任せ、本文のビューには置かない（二重にしない）。サブの追加もヘッダーの入力欄で行う
- 本文を保存すると md が変わり、ビューが描き直される。入力中の欄のフォーカスとカーソルは、描き直しで失わない（同じ行は DOM を作り直さず、値だけ更新する。入力中の欄の値は上書きしない）

### 展開の状態の保持

- 開いているサブの合成キー（`i-12#k3f9a2`）を、ノートごとに、この端末に保存する（プラグインの `data.json` の `subOpen`: `{ "issue/i-12.md": ["k3f9a2", ...] }`）。md には書かない（開閉のたびにノートが変わり、同期の衝突が増えるため）。端末間では同期しない
- 本文のビューとヘッダーのカードで、開閉は別々に持つ。ヘッダーのカードの開閉は今までどおり保存しない
- 消えたサブの id は、保存した値から、次に保存するときに取り除く

### 実装の方針

- Live Preview: pkm-task に CodeMirror の拡張（`registerEditorExtension`）を足す。サブ領域の範囲（`subAreaStartLine` から文書の終わり）を、block の `Decoration.replace` のウィジェットに置き換える。ウィジェットの中身は Preact で描く。カーソルがサブ領域の中（先頭と終わりの位置は除く）にあるときは描き替えを外し、生の md を見せる。領域に入る手段は、見出しの横の「Show source」ボタン（領域の先頭の次の位置にカーソルを置く）。文書の下をクリックして終わりにカーソルが来ても、描き替えは外れない。Live Preview のときだけ有効にし、ソースモードでは何もしない（`editorLivePreviewField`）
- Reading: Markdown の post processor で、サブ領域の最初のセクション（マーカーの行を含むもの）に同じ部品を 1 つ描き、後ろのセクションは隠す（今の「全部隠す」処理を置き換える）。Reading で本文の下の高さの見積もりと実際がずれて、一番下から上へのスクロールが引っかかる問題は、原因を「隠したサブ領域の高さの見積もりのずれ」と推測している（実機では未確認）。サブ領域を全部 `display: none` にする代わりに、最初のセクションに実際の高さの部品を置くことで、ずれを小さくすることを狙う。Obsidian の内部に依存するので、実機で確かめ、直らなければ別の対応を取る
- どちらも、親の md の本文からサブを読む `parseSubIssues`（ADR-0135）の結果を使う。索引（`TaskIndex`）の変更の通知で描き直す
- 部品は Preact で 1 つ作り、2 つの描き方から同じものを呼ぶ

### 文言

ヘッダーのカードと同じく、常に出る文言は英語、エラーの説明は日本語（`docs/design.md`「文言」）。部品の表（`docs/design.md`）に、本文のサブの行を足す。

## 理由

- どちらの表示でも同じ一覧が見えれば、本文の下に生の md が出る・何も出ない、という食い違いがなくなる
- その場で編集できれば、ダイアログを開かずに、サブの本文を書き足せる
- 保存先を端末にすると、md が開閉で汚れず、同期の衝突も増えない
- ヘッダーのカードを残すと、Timeline と作業時間の記録の役割を変えずに済む。削除と並べ替えを片方に寄せれば、操作の二重化も避けられる

## 却下した案

- **ヘッダーのカードを廃止して本文に移す**: Timeline と再生 / 停止の置き場がなくなる
- **展開の状態を md に書く（サブの項目に `open: true`）**: 開閉のたびにノートが変わり、同期の衝突が増える
- **Live Preview は生のまま、Reading だけ描く**: 食い違いが残る。要望は両方
- **本文のビューからダイアログを開いて編集する**: その場で直せるという要望に合わない
- **本文のビューにも削除・並べ替え・追加を置く**: ヘッダーのカードと二重になり、操作の置き場が分かりにくくなる

## 影響

- ADR-0142 の「本文の見え方」（Reading で隠す・Live Preview では描き替えない）を、この ADR が置き換える。ヘッダーのカードの扱いは変わらない
- pkm-task に CodeMirror の拡張が増える（`@codemirror/state` と `@codemirror/view` はすでに devDependencies にあり、esbuild では external。依存は増えない）
- 設定の `data.json` に `subOpen` が増える。子の Vault に手を入れないので、移行は要らない。`.kit/changes/` に変更を 1 件書く
- Live Preview の描き替えは Obsidian の内部の描き方に依存するので、実機で確かめる（PR のあとの本番での確認）
