# ADR-0017: 日付の入力は自作のカレンダーと、短い書き方の入力欄にする

- 状態: 承認（一部置換: 0078）
- 日付: 2026-11-01

## 背景

日付の入力はブラウザ標準の `input type="date"` / `datetime-local` を使っていて、操作の手数が多く、端末によって見た目も変わる。よく使う日付を少ない打鍵で入れられるようにしたい。

## 決定

日付の入力欄をすべて、テキストの入力欄と自作のカレンダーに置き換える。時刻を入れるときは、日付と時刻の入力欄を分ける。

入力はすべて今日を基準に解釈する（大文字と小文字は区別しない）。保存の形式（`YYYY-MM-DD`、worklog の日時）は変えない。

| 入力 | 解釈 | 例（今日が 2026-11-01 の日曜） |
|---|---|---|
| `dd` | 今月の dd 日 | `15` → 2026-11-15 |
| `mmdd` | 今年の mm/dd | `1224` → 2026-12-24 |
| `yymmdd` | 20yy/mm/dd | `270105` → 2027-01-05 |
| `yyyymmdd` | yyyy/mm/dd | `20270105` → 2027-01-05 |
| `yyyy-mm-dd` / `yyyy/mm/dd` | その日（保存値をそのまま読むため） | `2027-01-05` → 2027-01-05 |
| `+N` / `-N` | N 日後 / N 日前 | `+3` → 2026-11-04 |
| `mon` など | 次のその曜日（`+mon` と同じ） | `mon` → 2026-11-02 |
| `+mon` / `-mon` | 次 / 前のその曜日。今日と同じ曜日なら 7 日先 / 前 | `+sun` → 2026-11-08 |
| `+Nmon` / `-Nmon` | N 回後 / N 回前のその曜日 | `+2mon` → 2026-11-09 |
| `+w` / `+Nw`（`-` も同様） | 1 週間 / N 週間後（前） | `+2w` → 2026-11-15 |
| `+m` / `+Nm`（`-` も同様） | 1 か月 / N か月後（前）。その月にない日は月末にする | 01-31 の `+m` → 02-28 |

時刻は `hhmm`（4 桁）と `hh:mm` を受け付ける。

- 存在しない日付（`0231` など）と、上の表にない入力は、繰り上げたり推測したりせずエラーにする。保存はできない
- 入力欄の下に、解釈した日付を曜日付きで表示する。Enter で保存する
- カレンダーは新しい依存を足さず、既存の `CalendarForm` と同じ部品で作る
- 解釈の処理は `core/` に置き、テストで確かめる

## 理由

- 打鍵が少ない書き方は今日を基準にすると短くなり、よく使う相対日付に合う
- 標準の日付入力は端末ごとの差が大きく、`docs/design.md` のトークンで管理できない
- 入力の間違いで別の日付が保存されるより、保存できない方が気づける。解釈結果を表示すれば、保存の前に確かめられる

## 却下した案

- 標準の `input type="date"` を残す: 短い書き方を入れられない
- カレンダーのライブラリを使う: 依存が増える。必要な部品はすでにある

## 影響

- `core/` に解釈の処理を足す。`ui/forms.tsx` の `DateForm` と `WorklogForm` を変える
- `tue` のような入力は `+tue` と同じ意味になる
