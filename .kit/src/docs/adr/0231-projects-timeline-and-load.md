# ADR-0231: Project を横断するタイムライン（Projects）と、見積もりの入れやすさ・負荷の見通し

- 状態: 承認
- 日付: 2026-11-25

## 背景

#231。

- Project（サブを持つ issue。[ADR-0210](0210-gtd-list-badge-and-project-rules.md)）が増えると、サブのスケジュールの全体像が見えない。Timeline（[ADR-0143](0143-sub-issue-timeline.md)）は 1 つの親のサブだけを出し、issue をまたぐ表示は「必要になってから考える」としていた
- 使う人は「〇〇までにやります」と約束した期日に向けて、Project をまたいで作業を組み合わせたい。ただし期間の棒だけでは、時間が足りるかどうかが分からない（2 週間の棒が 3 本重なっても、1 日 2 時間ずつなら間に合い、6 時間ずつなら間に合わない）
- 容量を出すにはサブの `estimated` が要るが、サブごとに分で入れる手間が大きく、ほとんど入っていない

## 決定

### View「Projects」

- View「Projects」（`pkm-task-projects`、アイコン `chart-gantt`。古い Obsidian 向けの別名 `gantt-chart`）。左サイドバーの Scheduled の下と、コマンド「Open Projects」から開く
- 1 ページのタイムラインに、Project の行と、その下にその Project のサブの行を並べる
- 出す Project: closed・canceled でない Project。並びは、親の期限（`deadline`、なければ `soft_deadline`）の早い順 → 閉じていないサブの `end` のいちばん早い順 → ID の順。期限も期間もないものは最後
- 出すサブ: 親の画面と同じ（md の順。closed・canceled は、見出しの「Show N closed」のときだけ出す。[ADR-0181](0181-sub-done-to-bottom-and-hidden.md) と同じ文言。保存しない）
- Project の行: 左の列に題（ID のバッジと題）。押すと、その issue の詳細画面（issue のノート）を開く。右の日の列には、出しているサブの期間をまとめた棒（いちばん早い始まり〜いちばん遅い終わり。読むだけ）と、親の期限の印（`deadline` は red、`soft_deadline` は amber の縦の短い線）を出す。押しても何もしない
- サブの行: 親の画面の Timeline と同じ（棒・点・依存の矢印・今日の線・ドラッグ・キーボード・依存を引く・消す。ADR-0143・[ADR-0163](0163-timeline-edit-dependencies.md)・ADR-0210 の期間の規則）。題を押すと、親の issue のノートを開いて、そのサブの下部のカードを上端に出す（ADR-0179）
- 依存の矢印は、同じ親のサブの間だけ（`depends_on` は同じ親の中）。別の Project の棒へは依存を引けない
- 目盛り（Day / Week）は Timeline と同じく左上の角に置く。Projects の既定は Week（数か月を見渡すため）。保存しない
- Project が 1 つもなければ「No projects」

### 部品の使い回し

- 親の画面の Timeline と Projects は、同じ部品（`TimelineChart`）で描く。行の種類は「Project の行」と「サブの行」の 2 つで、親の画面はサブの行だけを渡す
- 部品の中では、サブを合成キー（`i-12#k3f9a2`）で区別する（サブの id は同じ親の中でしか一意でないため）

### 負荷の行（Projects だけ）

- 日の列の見出しのすぐ下に、行「Load」を置く。列ごと（Day は 1 日、Week は 1 週）に、その列にかかる見積もりの合計を時間で出す（`5h`）
- 見積もりを期間に割り振る: 閉じていない（closed・canceled 以外）サブの、期間（棒）の中の使える時間が 0 より大きい日に、そのサブの見積もり（下の「使う見積もり」）を等分する。使える時間が 0 の日しかない期間なら、期間のすべての日に等分する
- 使える時間: 設定「1 日に使える時間（平日）」（既定 6h）と「1 日に使える時間（土日）」（既定 0h）。端末ごとの設定（data.json）。Week は 7 日の合計
- 合計が使える時間を超えた列は error の色の面にする。ツールチップに「見積もり 7h / 使える時間 6h」と内訳（未見積もりの件数）を出す
- 見積もりのないサブは 0 として数えない。列にかかる未見積もりのサブがあれば、時間の後ろに `?` を付け（`5h?`。合計が 0 なら `?`）、ツールチップに件数を出す
- 期間のないサブは数えない（いつやるか決まっていないため）

### 使う見積もり（親の予算の割り振り）

- サブの `estimated` があれば、それを使う
- なければ、親の `estimated`（全体の予算。[ADR-0135](0135-sub-issues-in-issue-file.md)）の残りを、見積もりのない閉じていないサブで等分した値を使う。残り = 親の `estimated` − canceled 以外のサブの `estimated` の合計
- 親に `estimated` がない、または残りが 0 以下なら、見積もりなし（上の `?`）
- 割り振った値は保存しない（表示のときに毎回求める。[ADR-0002](0002-frontmatter-as-source-of-truth.md)）
- 実績（worklog）は引かない。負荷の行は計画を見るためのもので、実績による補正はしない

### 見積もりのサイズのチップ（S / M / L）

- サブの見積もりを入れる場所（Edit のダイアログ、本文のカード、プリセットのサブの行）に、チップ `S`（30m）・`M`（2h）・`L`（4h）・`XL` を置く。押すとその値を入れる。今の値のチップは選んだ状態に見せる
- `XL` は値を入れず、「4 時間を超える作業は、サブを分けてください」と出す（大きすぎる作業を分けるきっかけにする）
- 分の欄（`30m` / `2h`）は残す。チップは入れ方を足すだけで、保存する値は今までどおり分

### 近いうちの見積もりのないサブの印

- 閉じていないサブで、`estimated` がなく、期間が今日から 14 日のうちにかかるものは、Timeline（親の画面と Projects の両方）の棒の右に小さな印「Estimate」を出す。押すと S / M / L のメニューを開き、選ぶとそのサブの `estimated` に保存する
- 親の予算を割り振った値があっても印は出す（近いうちにやるものは、そのサブの見積もりを入れてほしいため）
- Projects の見出しに、その件数（「No estimate N」）を出す

### プリセットのサブの見積もり

- [ADR-0186](0186-issue-presets.md) の `sub_issues` の 1 件を、題の文字列か、`summary` と `estimated`（分）を持つ対応のどちらかにする。見積もりのない行は今までどおり文字列で書く

```yaml
sub_issues:
  - "Write the changelog"
  - summary: "Tag the version"
    estimated: 30
```

- プリセットの画面の各行に、サイズのチップ（S / M / L、もう一度押すと外す）を置く。保存は frontmatter の `sub_issues` の書き換え
- プリセットを当てたら、そのサブの `estimated` に既定値を入れる
- 書けない値（0 未満、数でない）は lint の問題（`invalid-preset-sub`、error）にし、その行は見積もりなしとして読む
- 今の md（文字列だけ）はそのまま読めるので、移行は要らない

### 文言

画面に常に出る文言（`Projects`、`Load`、`No projects`、`No estimate`、`Estimate`、`S` `M` `L` `XL`、ツールチップ）は英語、通知とエラーと設定の説明は日本語にする（docs/design.md「文言」）。

## 理由

- 1 つのページに Project と期限と負荷を並べると、どの週が詰まっていて、どの約束が危ないかを、棒をずらしながら確かめられる（期日に合わせたパズルができる）
- 期間の棒だけでは容量が分からない。見積もりを期間に割り振り、使える時間と比べて初めて、棒をずらすことが解くことになる
- 親の予算を割り振れば、サブの見積もりを 1 件も入れなくても負荷がおおよそ見える。精度を上げたいところ（近いうちのもの）だけ入れればよい
- 見積もりのないものを 0 にすると、未見積もりの多い週ほど空いて見える。`?` で、見えていないことを見えるようにする
- 粗い見積もりで容量の判断には足りる。S / M / L なら 1 回押すだけで入れられる
- 親の画面と同じ部品にすると、操作（ドラッグ・依存）がそろい、直す場所も 1 つになる

## 却下した案

- **棒だけの横断ガント（負荷の行なし）**: 重なりは見えても、時間が足りるかは分からない。見通しがついたように見えるだけ
- **Project の行を既定で閉じる**: 使う人はサブの並びを 1 ページで見たい。行が増えたら Week の目盛りと閉じたサブの非表示で減らす
- **Projects では期間を読むだけにする**: パズルのために棒は動かしたい。同じ部品なら操作をそろえる手間もない
- **実績から見積もりを補正する・既定値を出す**: 今は入れない（#231 の話し合い）。データがたまってから考える
- **見積もりのないサブを 0 として数える**: 未見積もりが多いほど空いて見え、誤った判断を招く
- **使える時間を Vault の設定ファイルに置く**: 端末間でそろうが、設定のファイルが増える。まず端末ごとの設定で試す
- **プリセットの見積もりを別のリスト（`sub_estimates`）で持つ**: 並べ替えのたびに 2 つのリストをそろえる必要があり、ずれやすい

## 影響

- ADR-0143 の「issue をまたぐガントチャートは作らない」を置き換える（一部置換: 0231）
- ADR-0186 の「サブの項目は題だけを持つ」を置き換える（一部置換: 0231）。見積もりは呼び出す日によって変わらないので、既定値として持てる
- `docs/design.md` の部品の表に、Projects・負荷の行・サイズのチップ・見積もりの印を足す
- `.kit/changes/` に子から見える変更を書く。移行はない
- サブの someday が要るかは別の Issue で考える（GTD の Someday/Maybe は Project の単位で、サブの単位では使いにくい）

## 追記（2026-11-25）: issue 画面の割り当てていない予算と、estimated の入力欄

使ってみて（#231 の続き）。

- issue 画面の、Calendar の日のストリップの場所（Project は Calendar の日を持たない。[ADR-0203](0203-pick-and-start-follow-next.md)）に、「unallocated」を出す。値は、親の `estimated` − 登録済みのサブの `estimated` の合計（canceled は除く。上の「使う見積もり」の残りと同じ）。負なら割り当てすぎで、error の色にする。親に `estimated` がなければ「—」。読むだけ
- estimated を選ぶメニュー（15m・30m・1h・2h・5h・8h・Enter…・Clear。[ADR-0012](0012-issue-screen.md)・[ADR-0034](0034-duration-input-auto-board-sticky-groups.md)）は使われず、値を直接入れていた。issue 画面・routine 画面の estimated は、その場で入れる入力欄にする（Enter か欄を離れると保存、Escape で戻す、空にすると消す。読めない値は保存せず説明を出す）。一覧（Issues などの列）と行のメニューからは、メニューを挟まず入力欄のダイアログを開く
- 却下: メニューの候補を S / M / L に変える。issue の見積もりはサブより幅が広く、候補で足りないことが多い
