# ADR-0253: スライド以外の HTML も OS のブラウザで開けるようにする（pkm-html）

- 状態: 承認
- 日付: 2026-11-27

## 背景

[Issue #253](https://github.com/yamayu-i/pkm-kit/issues/253)。pkm-html の View（[ADR-0037](0037-html-viewer.md)）は、スクリプト、`<link>`、外部の資源、`<iframe>` / `<object>` を取り除いてから表示する。そのため、Chrome で開くと出る要素（スクリプトで描くもの、別ファイルの CSS、動画など）が Obsidian の中では欠ける。元の見た目を確かめる手段がほしい。

いまは「Open in browser」をスライド（`slide/` の `index.html`）にだけ出している（[ADR-0117](0117-slides.md)。「ほかの HTML は、スクリプトを取り除くこの View で見る」）。

## 決定

- 「Open in browser」を、Vault の中のすべての `.html` / `.htm` に出す。出す場所はこれまでと同じ 3 つ: タブの右上のボタン、ファイルのメニュー、コマンド
- コマンドの ID は `open-slide-in-browser` のまま変えない（割り当てたホットキーを残す）。名前を「Open in browser」にし、開いている HTML ならどれでも使えるようにする
- アイコンは、スライドでは `presentation` のまま、ほかの HTML では `external-link`
- 開く方法はスライドと同じ（公開の API にない `app.openWithDefaultApp` を、あるときだけ使う）。開く前に確かめない。ない端末（スマホ）では通知で知らせる
- Obsidian の中の表示（View）の守り（ADR-0037 の 4 つ）は変えない。ブラウザで開くのは、使う人が押したときだけ
- pkm-slide が使う `openSlideInBrowser`（スライドだけを開く）は残し、中で HTML 全般を開く関数を使う

## 理由

- ブラウザで開くのは、使う人がファイルエクスプローラーや Finder で HTML をダブルクリックするのと同じ操作で、押したときだけ起きる。開いただけで何かが動くことはない（ADR-0037 の前提は守られる）
- View で欠ける理由はスクリプトと外部の資源なので、元の見た目を見るにはブラウザで開くのが確実
- コマンドの ID を変えると、子の Vault のホットキーが外れる（ADR-0120 と同じ扱い）

## 却下した案

- **開く前に確かめるダイアログを出す**: Markdown の外部リンクや OS のファイルを開く操作と同じく確かめない。毎回の確認は押す手間が増えるだけで、何が起きるかの判断材料を足さない
- **スライドとは別に、新しいコマンドを足す**: 同じ動きのコマンドが 2 つ並ぶ。スライドかどうかは使う人が区別しなくてよい
- **上流が作った HTML（体験定義書など）だけに出す**: 欠けて困るのは、むしろ外から持ち込んだ HTML。目印を決める必要も出る（ADR-0037 で任意の HTML を開くと決めたのと同じ理由）

## 影響

- ADR-0117 の「開けるのはスライドだけにする」を、この ADR で置き換える
- 変更: `.kit/src/packages/pkm-html/`（`src/obsidian/open-external.ts`、`html-view.ts`、`main.ts`、テスト）、ビルドの成果物 `.obsidian/plugins/pkm-html/`、プロダクトの文書（`surfaces/html-view.md`）
- 依存の追加なし。子の Vault の移行なし（プラグインの更新だけ）
- セキュリティ: ブラウザで開いた HTML のスクリプトは、ブラウザの `file:` の制限のもとで動く。押したときだけで、Obsidian の中の表示は変わらない
