# ADR-0110: PKM Git で、衝突を Obsidian の中で解き、ファイルの前の版に戻せるようにする

- 状態: 提案
- 日付: 2026-11-09

## 背景

[Issue #110](https://github.com/yamayu-i/pkm-kit/issues/110) で扱う。これは同期の再設計（[Issue #86](https://github.com/yamayu-i/pkm-kit/issues/86)）の第 5 段階で、最後の段階。

ここまでの段階で、次のことができるようになった。

- 同期は自動で、衝突しても止まらない（[ADR-0089](0089-git-auto-sync.md)）
- 衝突は、マーカー・別名の版・削除と編集の記録として、内容を失わずに残る。未解決の一覧に出る（[ADR-0103](0103-git-conflict-records.md)）
- 新しい端末は最新の版だけを持つ（[ADR-0106](0106-git-shallow-clone.md)）

残っている問題は 3 つある。

**一覧に出ても、解く手段がない。** 削除と編集の衝突には Keep / Delete がある（ADR-0103）。ほかの 2 つには解く手段がない。

- マーカー入りのノートは、本文のマーカーを手で消す。スマホでは、どこからどこまでが衝突か分かりにくい
- 別名の版（`… (conflict <端末> <日時>).ext`）は、手で中身を元のファイルに移して、別名の版を消す

**前の版に戻すには Git の CLI が要る。** ADR-0089 の 7 で、CLI でしかできない回復を Obsidian のコマンドに置き換えるとした。そのうち一番多いのは、「ほかの端末で、またはしばらく前に書いた版に戻す」こと。保存のたびの細かな版はファイル回復が端末内に持つ。ただし、ほかの端末の版と、ファイル回復の期間を過ぎた版は、Git にしかない。

**最新の版だけを持つ端末には、clone より前の版がない。** ADR-0106 で、取り足す方法はこの段階で決めるとした。

実依存（isomorphic-git 1.44.8）と git http-backend で、次の 2 つを確かめた。

- `git.log` の `filepath` で、ファイルを変えたコミットだけを新しい順に取れる。shallow の端末では、clone の版で止まり、エラーにならない
- `fetch` の `depth` と `relative: true` で、shallow の端末の履歴を後から N 個のコミット分だけ取り足せる。取り足した後も同期は今と同じく動く

## 決定

### 1. マーカー入りのノートを、塊ごとに選んで解く

- 未解決の一覧のマーカーの行に `Resolve` を付ける。開いているノートに対するコマンド「Resolve conflicts in this note」（`pkm-git:resolve-conflicts`）も足す
- モーダル（`Resolve conflicts`）は、マーカーの塊を順に出す。塊ごとに、ローカル側とリモート側の本文を上下に並べ、マーカーのラベル（端末名）を見出しにする。どちらも読み取り専用
- 塊ごとに 3 つのボタンから選ぶ
  - `Use local`
  - `Use remote`
  - `Use both`（ローカル、リモートの順に両方を残す）
- すべての塊を選ぶまで `Apply` は押せない。押すと、マーカーの部分だけを選んだ本文に置き換える。塊の外の本文は変えない
- 書き込みは、モーダルを開いたときの本文と、今の本文が同じときだけ行う。違えば（その間に編集や同期があった）書かずに知らせ、開き直してもらう
- マーカーの形が崩れていて読めない塊は、選ばせない。そのノートは手で直すよう知らせる（`Open note` だけを出す）
- 手で本文のマーカーを消すことも、今と同じくできる

### 2. 別名の版を、どちらかに決めて解く

未解決の一覧の、別名の版の行に、次の 2 つのボタンを付ける。どちらも確認のモーダルを出す。

| ボタン | すること |
|---|---|
| `Use this version` | 別名の版の中身を元のファイルに書き、別名の版を消す。元のファイルがもうなければ、別名の版を元の名前に改名する |
| `Discard` | 別名の版を消す。元のファイルはそのまま |

- 消すときは、Obsidian の「削除したファイル」の設定に従う（`fileManager.trashFile`）
- 元のファイルの名前は、別名の版の名前から ` (conflict …)` を除いて決める

### 3. ファイルの履歴を見て、前の版に戻す

- コマンド「Show file history」（`pkm-git:file-history`）と、ファイルのメニューの `Git: File history` で、そのファイルの履歴のモーダル（`File history`）を開く
- 一覧は、そのファイルを変えたコミットを新しい順に出す（`git.log` の `filepath`）。1 行に次のものを出す
  - 日時
  - 端末（コミットの author。既定は端末名）
  - 種類: `Synced`（snapshot）、`Kept`（Keep this version。名前も）、`Merged`、`Other`（Git CLI などのコミット）
- 1 度に 30 件まで出す。`Load older` でさらに 30 件を出す。手元の履歴の始まり（clone の版）に着いたら、`Load older` は履歴を取り足す（下の 4）
- 行ごとに `Preview` と `Restore` を付ける
  - `Preview`: テキストなら本文を読み取り専用で出す。それ以外は大きさだけを出す
  - `Restore`: 確認のモーダルを出してから、その版の中身をファイルに書く
- 戻す前に、今の内容を必ず Git に残す。同期のキューで `vault: keep before restore <パス> (<端末>)` の snapshot をコミットしてから書く。オフラインでもコミットは残る。戻した内容は、次の同期で共有される
- 戻すのは 1 つのファイルだけ。Vault 全体を前の版に戻す操作は作らない（ほかのファイルの新しい編集を巻き戻してしまう）
- モーダルの下に、保存のたびの細かな版は Obsidian のファイル回復にあることを添える

### 4. 最新の版だけを持つ端末で、必要な分だけ履歴を取り足す

- 手元の履歴の始まりに着いたときの `Load older` は、`fetch` の `depth: 30` と `relative: true` で、30 コミット分だけ取り足す。その後、一覧を続ける
- 取り足すのは、この操作のときだけ。自動の同期では取り足さない
- 取り足しも同期のキューで実行する（同期と重ねない）。オフラインや接続の失敗のときは、今の一覧のまま知らせる
- リモートにもそれより前がなければ、`Load older` を出さない

### 5. 失敗の扱い

- どの操作も、書く前に今の内容を確かめる。違えば書かずに知らせる（1 の書き込みの確かめ、3 の戻す前の snapshot）
- 履歴が読めない（壊れたオブジェクトなど）ときは、読めたところまでを出す。同期の記録に `warn` を残す
- 解決と戻すことは、ファイルを書くだけで、ブランチやリモートを直接は変えない。共有は次の同期が今の順（ADR-0089）で行う

## 理由

- 衝突は、ファイルを開いて全体を読むより、「どちらを採るか」を塊ごとに選ぶほうが、スマホでも確実に解ける。両方を残す選択肢があれば、迷ったときにも内容を失わない
- 別名の版は、ほとんどの場合「どちらか一方」で決まる。中身を見比べたいときは、今と同じく両方を開ける
- 戻す前に今の内容をコミットすれば、戻すことそのものを、後から戻せる。ファイル回復だけに頼らない
- ファイルを変えたコミットだけを出すと、Git の用語（コミット、ブランチ）を知らなくても「このファイルの前の版」として読める
- 履歴を取り足すのを使う人が履歴を見るときだけにすると、ADR-0106 の軽さを保てる

## 却下した案

- **Vault 全体の履歴ビュー（コミットの一覧）と、Vault 全体を戻す操作**: ほかのファイルの新しい編集を巻き戻す。ファイル単位の操作で、ほかの端末の版に戻すことは足りる
- **差分（diff）の表示**: 行単位の差分の表示は、狭い画面で読みにくい。解決は塊の上下の表示で、履歴は本文のプレビューで足りるので、今回は作らない
- **マーカーをエディタの中にボタンとして出す（エディタの拡張）**: Obsidian のエディタ（CodeMirror）の拡張になり、ライブプレビューと読み取りの表示の両方で作る必要がある。モーダルなら表示の方式によらない
- **消したファイルを戻す**: 消したファイルは開けないので、このモーダルの入口がない。消したファイルの一覧から選ぶ画面が要る。必要になったら別の ADR で決める

## 影響

- `src/merge/text-merge.ts` にマーカーの塊の読み取りと、選んだ本文での置き換えを足す（純粋な関数。テストしやすい）
- `src/git/engine.ts` に、ファイルの履歴（`fileHistory`）、版の中身の読み出し（`readVersion`）、履歴の取り足し（`deepen`）を足す。`src/git/` を変えるので、セキュリティチェックの対象（取り足しの接続先と認証は今の fetch と同じ）
- `src/main.ts`・`src/obsidian/modals.ts` に、コマンド（Resolve conflicts in this note、Show file history）、ファイルのメニュー、`Resolve conflicts` と `File history` のモーダル、一覧のボタンを足す。モーダルは今の pkm-git のモーダルと同じく、Obsidian の `Modal` と `Setting` で作る。文言はデザインルールの文言の言語（ADR-0076）に従う
- `src/sync/controller.ts` に、同期のキューで実行する操作（戻す前の snapshot、履歴の取り足し）を足す
- 移行はない。新しい依存はない
- `.kit/changes/` に書く
- 文書: `plugin-development.md`、プロダクトの [PKM Git](../../../harness/docs/product/surfaces/git-sync.md) と [同期と snapshot](../../../harness/docs/product/concepts/sync-snapshot.md)
- 受入テスト:
  - マーカーの塊の読み取り（複数の塊、塊の外の本文、崩れた形）と、3 つの選び方での置き換え
  - 開いた後に本文が変わっていたら書かない
  - 別名の版の `Use this version` と `Discard`。元のファイルがないときは改名する
  - ファイルの履歴（本物の git http-backend）: 変えたコミットだけが新しい順に出る。種類と端末が分かる
  - 戻す前に今の内容がコミットされる。戻した内容が次の同期で共有される
  - shallow の端末で、履歴の始まりから取り足して、より前の版を出せる。取り足した後も同期できる
- 第 5 段階で #86 の段階はすべて終わる。消したファイルを戻すこと、壊れたリポジトリからの復旧は、必要になったら別の Issue で扱う
