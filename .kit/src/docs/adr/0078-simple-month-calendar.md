# ADR-0078: 月のカレンダーを 1 つの部品にしてシンプルにし、すべての日付の選択で入力とカレンダーを使えるようにする

- 状態: 承認（ADR-0017・ADR-0030 のカレンダーの見た目と、ADR-0017 の入力の表を一部置換）
- 日付: 2026-11-08

## 背景

- 月のカレンダー（ADR-0017・ADR-0030）は、日ごとに角丸の四角の枠を付け、土日は枠を太く、今日は太字と下の点で示していた。大きく、印が多くて読みにくい
- pkm-task（`ui/forms.tsx`）と pkm-template（`DatePromptModal.tsx`、ADR-0065）が、同じ形のカレンダーを別々に持っていた
- 日付の選択には、短い書き方の入力（ADR-0017）とカレンダーの両方を使えるものと、片方しか使えないものがあった。調べた結果は次のとおり

| UI | 入力 | カレンダー |
|---|---|---|
| `DateForm`（Do Date の 1 日、期限、routine の日付、revisit） | ○ | ○ |
| worklog の開始・終了 | ○ | ○ |
| `CalendarForm`（issue の「calendar >」、Organize の Do Date。複数日） | × | ○ |
| `{{prompt-date}}` のダイアログ | ○ | ○ |

- `+1d` のように日の単位を書くと読めなかった（`+1` だけを受け付けていた）

## 決定

1. 月のカレンダーを `packages/shared/src/month-calendar.tsx`（と `month-calendar.css`）の 1 つの部品にし、pkm-task と pkm-template の両方で使う。CSS は各プラグインのビルドで `styles.css` に続ける
2. 見た目は Material 3 の日付の選択（Android 標準）に合わせてシンプルにする
   - 見出しは英語の月と年（`November 2026`）と ‹ ›。曜日は 1 文字（`S M T W T F S`）
   - 日は枠のない丸。今日は枠線の丸（primary）、選んだ日は塗りの丸（実行日の色 `--vt-scheduled`）
   - 月の外の日は描かない（空ける）。週は要る分だけ（4〜6 週）。土日の太枠と今日の点はなくす
   - 期限（soft_deadline・deadline）は、今までどおり丸の外側の色の輪で示し、期限より後の日は文字を一段弱くする。今日と期限は読み上げとツールチップでも伝える
3. すべての日付の選択で、入力とカレンダーの両方を使えるようにする。`CalendarForm` の上に入力欄を足し、Enter（か Add）でその日を選んだ日に足す（すでに選んでいれば外さない）。入力の欄と解釈の表示は `DateForm` と同じ部品を使う
4. 入力に日の単位 `d` を足す: `+d` / `+Nd` / `-Nd`（`+N` / `-N` と同じ）。pkm-template の日付のダイアログでは、単独の `-d` は今までどおり曜日を付ける指定で、前日は `-1d` と書く

## 理由

- 部品が 1 つなら、見た目と振る舞いが揃い、直すのも 1 か所で済む
- 選んだ日・今日・期限の 3 つだけを示せば、何が選ばれているかが一目で分かる。枠と点を減らすと、狭いペインやモバイルでも収まる
- 複数日のカレンダーだけ入力ができないと、「2 週間後」のような遠い日を選ぶのに月を送る必要がある。入力を同じ部品にすれば、覚える書き方が 1 つで済む
- `+1d` は `+2w`・`+m` と同じ形で書けるので、迷わない

## 却下した案

- **カレンダーのライブラリを使う**: 依存が増える（ADR-0017 と同じ理由）
- **月の外の日を薄く描いて押せるようにする**: 印が増える。月は ‹ › で送れる
- **M3 のように入力とカレンダーを鉛筆のボタンで切り替える**: 入力を開くのに 1 手増える。入力欄は常に出す
- **共有の CSS をデザインのトークン（`packages/design`）に入れる**: トークンは値の正本で、部品の CSS を置く場所ではない

## 影響

- `packages/shared` が preact に依存する（ワークスペースで使っている同じ版。新しい外部の依存ではない）。バンドルの preact は 1 つのまま（テストで確かめる）
- pkm-task と pkm-template の `esbuild.config.mjs` が、共有の CSS を `styles.css` に続ける
- 7 日のストリップ（issue の画面）の `.vt-day` はそのまま
- 子への移行はない。pkm-task・pkm-template の `main.js`・`styles.css` が変わる
