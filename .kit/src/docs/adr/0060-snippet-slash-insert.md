# ADR-0060: 行頭の / でスニペットを挿入する

- 状態: 承認
- 日付: 2026-11-08

## 背景

- pkm-template はファイル全体のテンプレート（`template/file/`、上流の既定は `.kit/templates/file/`）からノートを作る（ADR-0022、ハーネスの ADR-0009）。書いている途中のノートに、決まった書式の断片（日付の見出しなど）を差し込む手段はない
- Obsidian 標準の Templates コアプラグインと、コミュニティプラグインは使わない方針（ADR-0022）
- 入力中の補完は Obsidian の `EditorSuggest` で出せる。ただし `EditorSuggest` は「いま `/` を打ったか」を区別できず、カーソルを別の行から戻しただけでも候補が開いてしまう

## 決定

### 1. スニペットの置き場所と重ね方

| 置き場所 | 持ち主 |
|---|---|
| `template/snippet/*.md`（直下だけ） | その Vault（子） |
| `.kit/templates/snippet/*.md`（直下だけ） | 上流の既定（プリセット） |

- 同じファイル名なら、その Vault のものを使う（ファイル全体のテンプレートと同じ重ね方。ADR-0009）
- 上流のプリセットは `t1`（`today-h1`）・`t2`（`today-h2`）・`t3`（`today-h3`）。今日の日付と曜日の見出し（`#` / `##` / `###`。例: `# 2026-11-08 SUN`）と空行 2 つ

### 2. スニペットの書式

```md
---
name: today-h1
alias: t1
---
# {{date:YYYY-MM-DD DDD}}


```

- frontmatter は `name` と `alias` の 2 つ。どちらも必須の単一文字列で、ケバブケース（`^[a-z0-9]+(-[a-z0-9]+)*$`）。満たさないファイルは候補に出さず、コンソールに理由を出す
- 本文は frontmatter を閉じる `---` の行の直後から、ファイルの終わりまで。改行も含めてそのまま挿入する（前後を削らない）
- 本文の `{{...}}` はファイル全体のテンプレートと同じ規則で展開する（`{{date}}`、`{{time}}`、`{{title}}`・`{{path}}`・`{{folder}}` は挿入先のノートのもの）。`{{cursor}}` があればそこにカーソルを置き、なければ挿入した末尾に置く。`{{prompt:…}}` は入力欄がないので既定値になる
- スニペットは `type` を持たず、ノートの規約（共通 frontmatter）の対象外（`template/` と隠しパスは対象外。ADR-0007）

- 日時の書式に `DDD`（曜日の英大文字 3 字。`SUN`〜`SAT`）を足す。今の `ddd` は小文字（`sun`）。moment.js の `DDD`（年の通算日）とは意味が違うが、このプラグインの書式は moment.js ではなく、`ddd` の大文字版として読める方を選ぶ

### 3. いつ候補を出すか

- **行頭で `/` を打った直後から**候補を出す。行頭とは行の 1 文字目で、前に空白があれば対象外
- 打った `/` から続けて入力しているあいだ（カーソルの前が `/` とケバブケースの文字だけ）は、その文字列で絞り込む
- 次のどれかで終わる。終わったあとは、同じ `/` の後ろにカーソルを戻しても候補を出さない（ただの文字の `/`）
  - カーソルがその範囲の外に出た（別の行、`/` より前、範囲を選択した）
  - ケバブケース以外の文字（空白など）を打った、または `/` を消した
  - Escape で閉じた、または候補を選んだ
- 判定は CodeMirror の `StateField` で行う。入力の種類（`input.type`）と変更の中身で「`/` を行頭に打った」ことを見分け、その位置を覚える。判定の規則は Obsidian に依存しない `src/core/` に置いてテストする

### 4. 検索と挿入

- 絞り込みは `name` か `alias` の前方一致（大文字小文字は区別しない）。`/` だけなら全件
- 候補の表示は `alias: name`。並びは alias の順
- 選ぶと、行頭の `/` から入力した文字列までを展開した本文に置き換える。本文の後ろに改行は足さない

## 理由

- 行頭の `/` は Markdown の書式と重ならず、打つのも速い。行頭に限ると、パスや日付の中の `/` で候補が開かない
- 「打った直後だけ」に限ると、すでにある `/` で始まる行を編集し直すときに候補が邪魔をしない
- 置き場所と重ね方をファイル全体のテンプレートとそろえると、上流のプリセットを子が同じ名前のファイルで差し替えられ、覚えることが増えない
- 変数の規則を共有すると、スニペットのために新しい記法を覚えなくてよい

## 却下した案

- **`EditorSuggest` の `onTrigger` だけで判定する（カーソルの前の文字が行頭の `/` なら出す）**: カーソルを戻しただけで候補が開き、決めた挙動にならない
- **行の中のどこでも `/` で出す**: URL・パス・日付の入力で毎回候補が開く
- **スニペットを 1 つの JSON に書く**: 複数行の本文を書きにくく、テンプレートと書き方がそろわない
- **`template/file/` のテンプレートをそのまま挿入に使う**: ファイル全体のテンプレートは frontmatter（type、created など）を含み、本文の途中に入れる断片と目的が違う

## 影響

- pkm-template に `@codemirror/state` と `@codemirror/view` を開発用の依存として足す（型のため。実行時は Obsidian のものを使い、バンドルしない。pkm-task と同じ版で、lockfile に新しいパッケージは増えない）
- 実行時に `@codemirror/state` を Obsidian から読む（`external`）。ビルド済み `main.js` のテストの「obsidian 以外を require しない」と、`security-scan.mjs` の pkm-template の `allowedRequires` を、pkm-task と同じく `@codemirror/state` も許すように変える
- `.kit/templates/snippet/` は上流の既定（`.kit/**` に当たる）。子の `template/snippet/` は子のもの
- 子のものを書き換える移行は要らない。`.kit/changes/` に変更を書く
- 入力のたびに動くので、モバイル（iOS / Android の入力方式）でも候補の出方を確かめる
