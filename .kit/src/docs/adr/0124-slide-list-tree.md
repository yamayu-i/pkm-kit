# ADR-0124: Slides の一覧を、フォルダを展開する木とデッキの行にする

- 状態: 承認
- 日付: 2026-11-12

## 背景

[Issue #124](https://github.com/yamayu-i/pkm-kit/issues/124)。[ADR-0120](0120-slide-list-view-and-patterns.md) の Slides の View（左に整理のフォルダの木、右に選んだフォルダの下のデッキのカード）を使ってみて、次の問題が分かった。

1. 選んだフォルダの行が、行全体（「…」のボタンを含む）を secondary-container の面で塗られる。基本の色（[ADR-0121](0121-vault-theme.md)）で primary だけを変えた Vault では、そこだけ上流の色味が残り、統一感がない
2. 一覧ペインはサイドバーの役割を持つ。その中にもう 1 つサイドバー（フォルダの木）を置くと、ペインが二重に分かれて見づらい
3. カードの題は `deck.html` の `<title>` で、話し始めの 1 文のように長いことがある。メニューの Rename で変えるのはフォルダ名なので、一覧の名前と、変えられる名前が違う

## 決定

ADR-0120 の決定 1 の表のうち「左: フォルダ」「右: デッキ」「並び」を、次のとおりに置き換える。ほかの決定（フォルダとデッキの操作、動かし方、縮小の作り方、`data-deck` の書き換え）は変えない。

| 部分 | 内容 |
|---|---|
| 木 | `slide/` を 1 本の木で見せる。フォルダの行を押すと開閉し、中のフォルダとデッキの行を 1 段ずつ字下げして並べる。開いているフォルダは端末ごとに覚える（Obsidian の localStorage。Vault には書かない） |
| デッキの行 | 名前（フォルダ名。Rename で変える値）、枚数（ビルドしていなければ「Not built」）、更新日時、「…」 |
| カード | 1 枚目の縮小・題（`<title>`）・パスは、PC で行にホバーしたときだけカードで出す。スマホでは出さない |
| 並び | 1 段の中は、フォルダ（名前の順）を先に、デッキを後に。デッキは更新日時の新しい順（既定）か名前の順 |
| 検索 | 名前・題・パスで探し、当たったデッキを平らな行で並べる（行にフォルダの位置を出す） |
| 色 | 行の状態は、ホバーが state-hover、落とす先が primary-state-hover の面 + primary の枠。secondary-container は使わない。選んだフォルダという状態はなくす |

- 落とす先: フォルダの行に落とすとそのフォルダへ、行のない所に落とすと `slide/` の直下へ動かす（PC）
- 「New folder」のボタンは `slide/` の直下に作る。フォルダの中に作るのは、フォルダのメニュー

## 理由

- 一覧ペインの中を分けずに 1 本の木にすると、ファイルの一覧と同じ読み方になり、狭いペインでも並びが崩れない
- 名前を Rename の値にそろえると、一覧で見た名前をそのまま変えられ、リンク（`slide/<…>/index.html`）の名前とも一致する。長い題と縮小は、選ぶ前の確かめにだけ要るので、ホバーに回す
- primary から作る色だけを使えば、基本の色を変えた Vault でも追従する

## 却下した案

- **2 段のまま、選んだ行の色だけを primary に変える**: 色の不統一は直るが、サイドバーの中のサイドバーの見づらさが残る
- **カードを残し、題を名前にする**: 縮小は大きく場所をとり、数が増えると一覧として読みにくい
- **選んだフォルダの行だけを塗る（今の形の色を直す）**: 木を開閉する形では、選んだフォルダという状態が要らない

## 影響

- 変更: `pkm-slide` の View（`SlidesView.tsx`、`styles.css`）、`core/decks.ts`（木の 1 段を出す `childrenOf` とテスト）、プロダクトの文書（`surfaces/slide.md`）、ADR-0120 の状態（一部置換）
- 子の Vault: 移行は要らない。`.kit/changes/` に書く
- 実機で確かめること: PC とスマホでの開閉、ホバーのカード（PC）、ドラッグでフォルダと `slide/` の直下へ動かす（PC）、基本の色を変えた Vault で紫が残らないこと
