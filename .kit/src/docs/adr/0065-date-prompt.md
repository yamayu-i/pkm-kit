# ADR-0065: テンプレートとスニペットで、ダイアログから日付を選んで入れる

- 状態: 提案
- 日付: 2026-11-08

## 背景

- pkm-template の `{{date}}` / `{{date:…}}` は展開したときの日時（今日）しか入らない（ADR-0022）。会議の日や締め切りなど、特定の日付を入れるには、展開した後に手で書き換えるしかない
- 文字を尋ねる `{{prompt:ラベル[:既定値]}}` はあるが、入力欄があるのはノートを作るモーダルだけで、スニペットでは既定値になる（ADR-0060）。日付の短い書き方も解釈しない
- pkm-task には、短い書き方の入力欄（`15`、`1224`、`+3`、`mon`、`+2w` など）と月のカレンダーで日付を選ぶ入力がある（ADR-0017）。同じ操作でテンプレートにも日付を入れたい

## 決定

### 1. 変数

- `{{prompt-date}}` と `{{prompt-date:ラベル}}` を足す。ラベルはダイアログの題に出す（省略時は「日付」）
- 同じラベルの `{{prompt-date}}` が複数あれば、ダイアログは 1 回で、すべて同じ値になる（`{{prompt:…}}` と同じ）。ラベルが違えば、出てくる順にダイアログを 1 つずつ開く
- ファイル全体のテンプレート（本文と frontmatter）とスニペットの両方で使える。frontmatter の引用符の中なら、ほかの変数と同じく YAML としてエスケープする。生成先のフォルダ・ファイル名のパターン（`.kit/templates/config.json`）では展開しない（そのまま残る）

### 2. いつダイアログを開くか

| 使う場所 | 開くとき | キャンセルしたら |
|---|---|---|
| ファイル全体のテンプレート | ノートを作るモーダルで「作成」を押した後、ファイルを作る前 | ノートを作らない。モーダルは開いたまま |
| スニペット | 候補を選んだ後、挿入する前 | 挿入しない。打った `/…` はそのまま残す |

`{{prompt-date}}` がなければ、ダイアログは開かず今までどおり動く。

### 3. ダイアログ

- 短い書き方の入力欄と、月のカレンダーを並べる（pkm-task の日付の入力と同じ操作）。開いたときは入力欄にフォーカスする
- 入力欄の解釈は ADR-0017 の表と同じ（今日が基準。大文字小文字は区別しない。読めない入力と存在しない日付はエラーで、挿入できない）。加えて:
  - 空白で区切った `-d` を付けると、曜日付きにする（`+2 -d`、`-d mon`）。`-d` だけなら今日の曜日付き
  - 空のままなら今日
- 「曜日を付ける」のチェックボックスを置く。入力欄に `-d` があるか、チェックが入っていれば曜日付き
- 入力欄の下に、入る文字列をそのまま出す（`2026-11-10` / `2026-11-10 TUE`）。Enter か「挿入」で決める
- カレンダーの日を押すと、その日で決める（曜日はチェックボックスに従う）

### 4. 出力の形式

`YYYY-MM-DD` か `YYYY-MM-DD DDD`（`2026-11-08` / `2026-11-08 SUN`）の 2 通りだけにする。曜日は `{{date:DDD}}` と同じ英大文字 3 字（ADR-0060）。

### 5. 共有する処理

- 短い書き方の解釈（`parseDateInput`）は pkm-task の `src/core/date-input.ts` から `packages/shared/src/date-input.ts` に移し、pkm-task と pkm-template の両方から使う。pkm-task の `core/date-input.ts` は shared のものを再び公開するだけにし、動きは変えない
- `-d` の読み取りと出力の形式は pkm-template の `src/core/` に置いてテストする
- ダイアログとカレンダーは pkm-template に作る（クラス名は `vt-tpl-`。値はトークンから取る。`docs/design.md`）

### 6. 上流の既定のスニペット

`d1`（`date-h1`）・`d2`（`date-h2`）・`d3`（`date-h3`）を足す。選んだ日付の見出し（`#` / `##` / `###`）と空行 2 つ。`t1`〜`t3`（今日の見出し）と同じ形で、日付だけを尋ねる。

```md
---
name: date-h1
alias: d1
---
# {{prompt-date}}


```

## 理由

- `{{prompt:…}}` と同じ `prompt-` の名前にすると、「展開するときに尋ねる変数」と分かり、同じラベルで値をまとめる規則も同じにできる
- 形式を 2 通りに絞ると、テンプレートごとに書式を書かずに済み、Vault の中の日付の書き方がそろう（`YYYY-MM-DD` は ADR-0007 の日付、曜日付きは `t1`〜`t3` の見出しと同じ）
- 曜日の有無は、テンプレートを書く人ではなく入れる人が、その場で決めたいことがある（見出しには付け、本文の中では付けない）。入力欄の `-d` は打鍵が少なく、カレンダーで選ぶ人にはチェックボックスがある
- 解釈の処理を共有すると、pkm-task と同じ書き方が同じ日付になり、表がずれない
- キャンセルで何も作らない・挿入しないと、中途半端な日付（今日や空）が入らない

## 却下した案

- **`{{date:ask}}` のように `{{date:…}}` に意味を足す**: `{{date:…}}` の後ろは書式で、`ask` は今も文字として出る。意味を変えると既存のテンプレートの読み方が変わる
- **変数に書式を書けるようにする（`{{prompt-date:ラベル:YYYY/MM/DD}}`）**: 依頼は 2 通りへの統一。書式が増えると Vault の中の日付の書き方がばらつく。必要になったら足す
- **ノートを作るモーダルの中に日付の欄を並べる**: スニペットにはモーダルがなく、2 か所で別の入力になる。同じダイアログを順に開く方が、どちらでも同じ操作になる
- **pkm-task の `DateForm` を shared に移して使う**: CSS はプラグインごとにあり（pkm-task は `.vt-ui`、pkm-template は `vt-tpl-`）、部品を移しても両方に CSS が要る。`DateForm` はクリアや「今日・明日・来週」など pkm-task の用途の部品も持つ。解釈の処理だけを共有する
- **キャンセルでも今日の日付を入れる**: 選んでいない日付が入り、気づきにくい

## 影響

- pkm-template: `src/core/` に `{{prompt-date}}` の取り出しと展開、`-d` の読み取りを足す。`CreateNoteModal` と `SnippetSuggest` から日付のダイアログを開く。`styles.css` にダイアログとカレンダーを足す。ビルド済み `main.js` も変わる
- pkm-task: 解釈の処理の置き場所が変わるだけで、動きは変えない（今のテストがそのまま通ること）
- `.kit/templates/snippet/` に `date-h1.md`・`date-h2.md`・`date-h3.md` を足す（上流の既定）
- 依存は増えない。子のものを書き換える移行は要らない。`.kit/changes/` に変更を書く
- モバイル（スニペットを選んだ後のダイアログ、カレンダーの押しやすさ）でも確かめる
