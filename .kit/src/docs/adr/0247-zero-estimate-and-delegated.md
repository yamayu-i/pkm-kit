# ADR-0247: estimated の 0 の入力と、delegated を未見積もりに数えないこと

- 状態: 承認（ADR-0034 の「0 以下は受け付けない」を一部置換）
- 日付: 2026-11-27

## 背景

- estimated の入力欄（issue・routine・サブイシューの欄、routine を作るフォーム）は 0 を受け付けなかった（ADR-0034）。delegated の issue のように自分の手間がほぼないものに、「見積もり済みで 0」を入れられなかった
- 保存とデータの検査（frontmatter の読み込み、サブイシュー、MCP、プリセット）は、すでに 0 以上を受け付けていた。入力欄だけが 0 を弾き、0 で作った issue・routine には estimated が書かれず、routine の一覧は 0 を表示しなかった
- そのため delegated のサブは、Projects の「Estimate」「Budget」の印と負荷の `?` に残り続けた。ボードの負荷（未完了の見積もりと未見積もりの件数）は、もともと waiting・delegated を未完了に数えていない

## 決定

### 0 を入力できる

- 期間の入力（`parseDurationInput`）で、0（`0` / `0m` / `0h` / `0d` など）を 0 分として読む。負と読めないものはこれまでどおり受け付けない
- 0 は「見積もり済みで手間なし」、空（null）は「未見積もり」。両者を区別する
- 0 で作った issue・routine にも `estimated: 0` を書く。一覧や画面は 0 を `0m` と表示する

### delegated を未見積もりに数えない

- status が delegated で estimated がないサブは、未見積もりに数えない（自分の手間は 0 とみなす）
  - Projects のサブの「Estimate」の印と件数、親の「Budget」の印
  - 負荷の行の `?`（数えない。時間にも足さない）
  - 親の予算（estimated）の残りを割り振る先（delegated のサブには割り振らない）
- estimated があれば、delegated でもその値を使う。waiting は対象にしない
- ボードの負荷は変えない（waiting・delegated はもともと未完了に数えない）

## 理由

- 0 と null を分ければ、「考えた結果 0」と「まだ考えていない」が画面と集計で区別できる。データの検査はすでに 0 を許していたので、入力をそろえるだけで済む
- delegated は他人がやるので、自分の手間を毎回 0 と入れさせるより、status から分かる分は自動で外すほうが手間が少ない
- waiting は、待ちが明けたら自分が続きをやる。残りの手間は自分のもので、見積もりを促す意味がある

## 却下した案

- **0 を入力できるようにするだけ**: delegated のたびに 0 を入れる手間が残る
- **delegated を自動で外すだけ**: delegated 以外で手間がほぼないもの（確認するだけのタスクなど）に 0 を付けられない
- **waiting も外す**: 上の理由のとおり、待ちのあとに自分の作業が残る

## 影響

- データの形は変わらない。移行はない
- 容量の設定は 0 を別扱いで受け付けていたが、`parseDurationInput` が 0 を読むようになるので別扱いをなくす
- 見積もりと実績の比（estimated が 0 以下のものは除く）は変わらない
