# ADR-0004: worklog は端末別・月別の jsonl

- 状態: 承認
- 日付: 2026-10-31

## 決定

- 保存先: `worklog/<端末名>/YYYY-MM.jsonl`（月は `from` の月）
- 1 行 = 1 件:

  ```json
  {"id":"wl_V1StGXR8","task_id":"i-12","from":"2026-10-31T10:00:00+09:00","to":"2026-10-31T10:45:00+09:00","description":"調査"}
  ```

  - `id`: 個々のログを編集やスキルから指すための ID（nanoid 形式）
  - `task_id`: issue（`i-N`）か routine（`r-N`、ADR-0010）。最初の構想の `issue_id` から改名した
  - `to`: 動いている間は `null`
- 端末名はプラグインの設定に持つ（vault-git の端末名と同じ値を推奨）
- 書き込むのは、そのログを作った端末だけを原則とする。例外は、PC から過去のログを直すとき（worklog の見直しスキル）

## 理由

- 1 つのファイルに書くのが 1 台だけなら、末尾に追記してもコンフリクトしない
- 月で分けておけば、ファイルが大きくなりすぎない

## 却下した案

- **1 つの jsonl に全端末で追記する**：2 台が末尾に追記すると必ずコンフリクトし、片方のログが別名ファイルに逃げる
- **issue の md 本文に書く**：再生 / 停止のたびに、編集中かもしれない md に書き込むことになる

## 影響

- 他の端末で**動いているログ**を直すときは、その端末で同期してから直す
