# ADR-0045: tmp/ のファイルの一覧 View を pkm-template に足し、一覧から開く・消す

- 状態: 承認
- 日付: 2026-11-08

## 背景

[Issue #45](https://github.com/yamayu-i/pkm-kit/issues/45)。`tmp/`（[ADR-0038](0038-tmp-folder.md)）は、git で管理しない一時ファイルの置き場で、外部共有用の書き出し（pkm-drawio の書き出し、[ADR-0044](0044-html-standalone-export.md) の HTML）と、自分が一時的に見るファイルを置く。

`tmp/` のファイルは Markdown とは限らず（HTML、SVG など）、frontmatter も持たない。今の一覧 View（Notes、Sources など。[ADR-0026](0026-note-views.md)）は Markdown の `type` で絞り込むので、`tmp/` のファイルは出ない。ADR-0038 は、自動では消さず人が消すとし、一覧 View を別の Issue に送った。

## 決定

### 1. 実装の場所

- pkm-template の一覧 View に **Temporary files**（`pkm-template-tmp-list`）を足す。開くコマンドは「Open Temporary files」
- ほかの一覧と同じく、左の固定ペイン（[ADR-0033](0033-list-pane.md)）に開く。pkm-view-selector（[ADR-0072](0072-view-selector.md)）には、コマンドの名前の規則で自動で候補に出る
- リボンのボタンは足さない（頻繁に開くものではない。必要なら pkm-ribbon の並びの表で後から足す）

### 2. 一覧に出すもの

- 対象は `tmp/` の下のすべてのファイル（サブフォルダの中も。Markdown 以外も）。フォルダそのものは出さない
- 列: **Name**（`tmp/` からのパス）、**Type**（拡張子）、**Modified**（更新日時）、**Size**（大きさ。KB / MB）、削除のボタン
- 既定の並びは Modified の新しい順。Name・Modified・Size の見出しで並べ替えを変えられる（ほかの一覧と同じ操作）
- 上の検索欄で、Name を部分一致で絞り込む
- 空のときは「No temporary files」。`tmp/` がないときも同じ

### 3. 開き方

- Name を押すと、ほかの一覧と同じく右のノートペインに開く（`openInNotePane`）。Obsidian か自作プラグインが開ける拡張子（md、html〈pkm-html〉、画像、PDF、svg など）は、その View で開く
- Obsidian が開けない拡張子は、PC では OS の既定のアプリで開く（`openWithDefaultApp`）。スマホでは開けない旨を通知に出す

### 4. 一覧からの削除

- 各行に削除のボタンを置く。押すと確認のダイアログ（ファイルのパスと「Delete」「Cancel」）を出し、Delete で消す
- 消すのは `app.fileManager.trashFile`。Obsidian の「削除したファイル」の設定（システムのゴミ箱・Vault の `.trash`・完全に削除）に従う
- まとめて消す（全選択・一定期間より古いもの）は入れない。自動でも消さない（ADR-0038 の 4）

### 5. ほかの一覧と検索からの除外

- ほかの一覧 View（Notes、Daily notes、Sources など）は、`tmp/` の下の Markdown を出さない（`tmp/` の md に `type` が書いてあっても）。pkm-template の一覧が集める段階で除く
- Obsidian の検索・クイックスイッチャーからは除かない。除くには子の `.obsidian/app.json` の「除外するファイル」を変える必要があり、移行が要るうえ、`tmp/` のファイルを探す手段もなくなる

## 理由

- **pkm-template に足す**: ノートの一覧 View の仕組み（左の固定ペイン、並べ替え、検索欄、Preact の部品）がすでにあり、同じ見た目と操作になる。新しいプラグインにするほど性質は違わない（HTML の表示のような守りは要らない）
- **すべての拡張子を出す**: `tmp/` は Markdown 以外が主（書き出した HTML など）。Markdown だけに絞ると、この View を作る意味がなくなる
- **Modified の新しい順**: 一時ファイルは、直前に書き出したものを開く・渡すことが多い
- **削除を 1 件ずつ、確認つきで入れる**: ADR-0038 は人が消すとしているので、一覧の場で消せると手間が減る。確認があれば誤って消さない。`trashFile` なら、ゴミ箱の設定によっては戻せる
- **ほかの一覧から除く**: `tmp/` は規約の対象外（ADR-0038 の 3）なので、ノートとして一覧に出すと規約に従うノートと混ざる

## 却下した案

- **pkm-task に足す**: タスク管理のプラグインで、ファイルの一覧とは関係がない
- **新しいプラグインにする**: 一覧 View の仕組みを二重に持つことになる。有効にする移行も要る
- **`tmp/` の Markdown だけを出す**: 書き出した HTML や SVG が出ない
- **まとめて消す・古いものを自動で消す**: 共有する前のファイルや、まだ見ているファイルを消すおそれがある（ADR-0038）。量が増えて困るようになったら考える
- **確認なしで消す**: 1 回の押し間違いで消える
- **クイックスイッチャーと検索から除く**: 移行が要り、`tmp/` のファイルを名前で探せなくなる

## 影響

- pkm-template: 一覧 View を 1 つ、確認のダイアログを 1 つ足す。`tmp/` を除く処理を、ほかの一覧が集める段階に足す。`main.js` をビルドする
- テスト: 一覧の集め方・並べ替え・絞り込み・大きさの表示（純粋な関数）と、ほかの一覧から `tmp/` の md を除くこと。`preview/`（あれば）でライト / ダーク × 広い / 狭いのスクリーンショット
- プロダクトの文書: `surfaces/` に一覧 View の節を足す
- 子の Vault: プラグインの更新だけで、子のものは変えない（移行なし）。`.kit/changes/` に書く
- 実機で確かめること: スマホでの表示と削除、Obsidian が開けない拡張子の扱い
