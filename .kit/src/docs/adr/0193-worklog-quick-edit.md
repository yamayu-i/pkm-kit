# ADR-0193: ボードと Tasks Now から、記録の開始・終了を短い書き方で直す

- 状態: 承認
- 日付: 2026-11-16

## 背景

再生ボタンの押し忘れ（始めたのに押していない、遅れて押した、止め忘れた）が多い。直すには issue 画面の Worklog まで行き、行を開いて日付と時刻を別々に入れ直す必要がある（ADR-0012, 0017）。記録を始め・止めるボード（ADR-0137）と Tasks Now（ADR-0154）のその場で、少ない打鍵で直したい。

## 決定

### 1. 置く場所と見た目

- タスクボードのカード（`.vt-task`）と Tasks Now の各行の、再生 / 停止（`.vt-play`）のすぐ左に、アイコンボタン「Edit times」（`.vt-icon-button.vt-time-edit`、アイコン `history`）を置く。24px の丸で色を付けない（`.vt-play` より目立たない）
- 記録中でも記録していないときでも、再生 / 停止のある所にはいつも出す（Done のカードにも出す。済んだ後に記録を足すことがある）。再生 / 停止のない Watch のカードと、Tasks Now の Paused の行（Resume で群をまとめて始める所）には出さない
- 幅 480px 以下のボードでは、題を残すためにボタンを隠す。ボードのカードの `⋯` のメニューにも「Edit times」を置き、狭いときはそこから開く
- サイドバーの Running と issue 画面には足さない（issue 画面は既存の Worklog の編集がある）

### 2. ダイアログ

モーダル「Edit worklog times」。上から:

- **From** と **To** の 2 つの入力欄。欄の右にカレンダー（`calendar`）と時計（`clock`）のアイコンボタン、欄の下に解釈した日時（`11/16 MON 21:38`）かエラー
- 初めの値: 記録中なら From は動いている記録の開始（同じ鍵に複数あればいちばん新しいもの）、To は空。記録していないなら両方空
- 下に **再生**（`.vt-play`、緑）と **停止**（`.vt-play.is-running`、赤）のボタン

| 状態 | 再生（To が空のときだけ押せる） | 停止（To があるときだけ押せる） |
|---|---|---|
| 記録中 | 動いている記録の from だけを直し、計測を続ける | 動いている記録の from と to を直して止める |
| 記録していない | From を開始にして記録を始める（open の issue とサブは in-progress。ADR-0031） | From〜To の記録を 1 件足す（終わった記録なので status は変えない） |

- 検査: From は必須。From も To も今より後にはできない。To は From より後。読めない入力があるあいだは、どちらのボタンも押せない
- 記録中に停止するとき、1 分未満でも残す（手で入れた長さなので。ふだんの停止の下限 ADR-0004 は、押してすぐ止めたものを消すため）
- 書き戻すファイルは、記録中の行はその行のあるファイル（既存の Worklog の編集と同じ。ADR-0012）、新しく足す行は開始日の月のファイル

### 3. 短い書き方

入力は欄を離れたとき（Enter・Tab・クリック）に解釈し、読めれば欄の文字を `yyyy-mm-dd hh:mm` に書き換える。読めなければ文字を残してエラーを出す。基準は「今」。

| 入力 | 解釈 | 例（今が 2026-11-16 23:00） |
|---|---|---|
| `-Nm` | N 分前 | `-22m` → 22:38 |
| `-Nh` / `-NhMm` | N 時間（M 分）前 | `-1h10m` → 21:50 |
| `hhmm` | 今日の hh:mm | `2200` → 11/16 22:00 |
| `hhmm-Nd` | N 日前の hh:mm | `2200-1d` → 11/15 22:00 |
| `ddhhmm` | 今月の dd 日 hh:mm | `152200` → 11/15 22:00 |
| `mmddhhmm` | 今年の mm/dd hh:mm | `08262200` → 2026/08/26 22:00 |
| `yymmddhhmm` | 20yy/mm/dd hh:mm | `2608262200` → 2026/08/26 22:00 |
| `yyyy-mm-dd hh:mm` | その日時（書き換えた後の文字をそのまま読む） | |

- 表にない形（`+10m`、`262200-1d`、単位のない `-30`）と、存在しない日時はエラーにする（ADR-0017 と同じく、推測しない）
- 解釈は `core/` に置き、テストする

### 4. フォーカスと Enter

- 開いたら From にフォーカスし、文字を選んだ状態にする
- From で Enter: 解釈して To に移る
- To で Enter: To が空なら再生に、To があれば解釈して停止に移る
- 再生 / 停止のボタンで Enter: そのボタンの操作をして閉じる（ふつうのボタンの動き）

### 5. カレンダーと時計

- カレンダーのボタンで、その欄の下に月のカレンダー（`MonthCalendar`、ADR-0078）を開く。日を選ぶと、時刻はそのままで日付を変える（空なら今の時刻）
- 時計のボタンで、その欄の下に時計を開く。Material 3 の時刻ピッカー（Android の時計のダイヤル）にならう
  - 上に時と分の大きい欄（`22` : `38`）。押した方を選び、選んでいる方は secondary-container の面
  - 下に丸いダイヤル（surface-container-high の面）。24 時間で、外の輪が 0〜11、内の輪が 12〜23。分は 5 分おきの数字。針と選んだ数字の丸は primary
  - ダイヤルを押す・なぞると値が変わる。時を決めると分に移る。分は 1 分きざみでなぞれる
  - 下に「OK」で閉じる。時計の操作は欄の値（日付はそのまま）を変えるだけで、記録は書かない
  - キーボードでは、ダイヤルに矢印キー（↑→ で 1 増やす、↓← で 1 減らす）
- 新しい依存を足さない。時計は pkm-task の `ui/` に置く（クラス名 `vt-clock-`）

## 理由

- 押し忘れは「始めた時刻が違う」「止めた時刻が違う」「押していない」の 3 つで、どれも開始と終了の 2 つの時刻で直せる。同じダイアログで記録中・記録なしの両方を受けると、覚えることが 1 つで済む
- 押し忘れに気づくのはボードと Tasks Now を見たときなので、そこに置く。目立たないボタンにして、ふだんの再生 / 停止を邪魔しない
- 短い書き方は、直す時刻の多くが「さっき」か「今日の何時」なので、今を基準にすると短い。日付の短い書き方（ADR-0017）と同じく、読めないものは推測しない
- 欄を離れたときに書き換えると、保存の前に解釈を確かめられ、もう一度欄に入ったときにも読める形になっている

## 却下した案

- **既存の WorklogForm（日付と時刻の欄が別々）を開く**: 欄が 4 つで、Enter の流れを要望どおりにできない。説明の欄も今は要らない
- **ブラウザ標準の時刻入力**: 端末ごとに見た目が違い、トークンで管理できない（ADR-0017）
- **時計にライブラリを使う**: 依存が増える。ダイヤルは SVG と数行の計算で作れる

## 影響

- pkm-task: `core/` に短い書き方の解釈、`ui/` にダイアログと時計、writer に「開始を指定して始める」を足す。`Board.tsx` と `TasksNowDialog.tsx` にボタンを足す。styles・`docs/design.md` の部品の表・`surfaces/` を更新する
- worklog の形式は変えない。子のノートや設定は変えないので、移行は付けない
- 文言は画面に出るものは英語、通知は日本語（ADR-0076）
