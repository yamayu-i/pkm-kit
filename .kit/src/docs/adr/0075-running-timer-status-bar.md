# ADR-0075: 記録中のタイマーを、PC のステータスバーに出す

- 状態: 承認
- 日付: 2026-11-08

## 背景

記録中のタイマーが見えるのは、task board のカード（経過時間）と、左サイドバーの Tasks の「記録中」だけだった。ノートを書いているとき、サイドバーを閉じているときは、タイマーが動いていることが見えない（[#37](https://github.com/yamayu-i/pkm-kit/issues/37)）。止め忘れは worklog-review で後から直す決まりで（ADR-0009）、警告も自動停止もしない（`.kit/harness/docs/product/strategy.md` の「やらないこと」）。ここで扱うのは警告ではなく、今の状態が見えるかどうかである。

ADR-0037 は別の内容ですでにあるので、この ADR は [#75](https://github.com/yamayu-i/pkm-kit/issues/75) の番号で書く（ADR-0056）。

## 決定

- pkm-task が、Obsidian のステータスバーに項目を 1 つ足す（`addStatusBarItem`）。記録中の worklog（`to` が空）がなければ、何も出さない（項目を隠す）
- 記録中のタスクが 1 つ: `● <ID> <summary> <経過時間>`（例: `● i-12 見積もりを直す 42m`）。summary は 24 文字で切って `…` を付ける。経過時間の表記は `formatMinutes`（ADR-0034）
- 記録中のタスクが 2 つ以上: `● <件数> running <いちばん長い経過時間>`。ツールチップにタスクを 1 行ずつ並べる
- 押すと、1 つならその issue / routine のノートを開き、2 つ以上なら Tasks サイドバーを開く
- 表示は索引が変わったときと 30 秒ごとに更新する（サイドバーと同じ間隔）
- 状態を見せるだけにする。色で急かさない、音を出さない、一定時間で止めない
- スマホ版は対象にしない（Obsidian のスマホ版にはステータスバーがない。ユーザーと合意）

## 理由

- ステータスバーは、どの View やノートを開いていても PC の画面の下に出る。pkm-git もここに状態を出しているので、置き場所として慣れている
- 1 つのときに ID と summary を出せば、どの作業の記録なのかがその場で分かる。2 つ以上はまれで、幅を取らないように件数だけにする
- 押して開けるので、止めるための操作（カードやサイドバーの停止ボタン）までの距離が短くなる。止める操作そのものをステータスバーに置くと、押し間違えで記録が止まるので置かない

## 却下した案

- **ステータスバーの項目を押すと記録を止める**: 押し間違えると記録が切れる。止めるのはカードかサイドバーで行う
- **一定時間を超えたら色を変える・通知する**: 見張らない方針（ADR-0009、strategy.md）に反する
- **スマホで見える場所を作る（リボンのバッジなど）**: スマホのリボンは常には見えず、効果が小さい。ユーザーがスマホ版は気にしないと決めた

## 影響

- pkm-task: `src/core/running.ts`（表示の文字列を作る純粋な関数）と、`main.ts` でのステータスバーの登録。テストを足す
- 文書: `.kit/harness/docs/product/surfaces/` にステータスバーの surface を足し、[作業しながら残す](../../../harness/docs/product/jobs/task-work.md) の困りごとから #37 を外す
- 子: 移行はない。プラグインを更新すると、PC のステータスバーに表示が増える
