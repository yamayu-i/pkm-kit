# ADR-0137: task board のグループを廃止し、status とタイマーで決まる 1 列の欄とサブイシューのカードにする

- 状態: 承認
- 日付: 2026-11-15

## 背景

task board のグループ・サブグループ（ADR-0014, 0015, 0034, 0114）は、カードを分ける手間の割に、利点を感じられていない。グループは並べて見せるだけで、時刻・順番・状態のどれとも結びついていない（Issue #137）。
サブイシュー（ADR-0135）を入れたので、ボードでもサブを 1 件ずつ扱いたい。

## 決定

### 欄

ボードは 1 列にし、上から次の欄に分ける。どの欄に入るかは status・タイマー・★ から自動で決まり、手で欄を選ぶことはない。

| 欄（画面の名前） | 入る条件 | 並び |
|---|---|---|
| 作業中（`Working`） | タイマーが動いているもの。in-progress は条件にしない | 始めた順 |
| ★今日の最重要（`Top 3`） | その日に ★ を付けたもの。最大 3 件 | 並び（下）の順 |
| 次にやる順（`Up next`） | 残り全部（open も in-progress も）。status のバッジで区別する | 並び（下）の順。手で並べ替える |
| 待ち・委任（`Waiting`） | waiting / delegated。たたまずに件数を出す | 並び（下）の順 |
| 片付いた（`Done`） | closed / canceled / someday の issue とサブ、結果のある routine、持ち越したもの（carried）。たたむ | 終わった順（これまでどおり） |

- 欄は上の表の順で判定し、最初に当たった欄に入れる（作業中 → 片付いた → 待ち・委任 → ★ → 次にやる順）。★ を付けたまま waiting にしたものは「待ち・委任」に出し、open に戻すと ★ に戻る
- 作業中の件数に上限は設けない。欄がタイマーだけで決まるので、同時に手を付けているものだけが入る
- AI エージェントに任せた作業は、結果を待つ間 `waiting` にして「待ち・委任」に出す
- 毎日ボードに載せるかどうかは、これまでどおり `scheduled` で決まる（ADR-0034）
- 下の「Not done」の一覧と「Close board」はこれまでどおり（ADR-0009, 0018）

### カード

- カードは issue・サブ・routine の 1 件ごとに 1 枚。欄・並び・★ もこの単位で決まる
- カードに出すのは、status のバッジ（押すと status のメニュー）・題・再生ボタン・`···` のメニューだけ。priority のバッジと「次の status」のボタン（ADR-0031）は出さない。ボードは一覧性が大事なので、カードを大きくしない
- 同じ欄で隣り合った、同じ親のサブは、親の見出し（`i-12` と親の題。押すと親を開く）の下にまとめて出す。間に別のカードが入ると、見出しをもう一度出す
- 親のカードは、親の issue がボードに載っているときだけ出る（ADR-0034 の自動では、親自身の `scheduled` が今日のとき）。サブの `scheduled` だけでは親のカードは出ない。親のカードの再生ボタンは、親に直接付ける作業の記録に使う
- `···` のメニュー: `Add to Top 3` / `Remove from Top 3`、`Move up` / `Move down`（同じ欄の中。先頭・末尾では出さない）、`Open`、`Remove from board`
- PC ではドラッグもできる。「★」と「次にやる順」の間と中だけ（ほかの欄は自動で決まるので落とせない）。別のカードの上に落とすとその前に入り、欄の空いているところに落とすと末尾に入る。★ の欄に落とすと ★ が付き、外に出すと外れる。★ が 3 件あるときは ★ の欄に落とせない

### サブをボードに載せる

- 今日が `scheduled` のサブは、issue と同じく DailyTaskView が `add` で自動でボードに載せる（ADR-0034）。open なら「次にやる順」の末尾に入るので、朝に決めた順を乱さない
- その日にボードから外したサブは、`scheduled` が残っていても自動では載せ直さない（issue と同じ）
- その日が `scheduled` でないサブは、ボードの「Add issue」の候補に `i-12 › 題` の形で出す。選ぶと、そのサブの `scheduled` に今日を足してから、ボードに載せる
- 載せた後は issue と同じ扱いにする。持ち越し（Do Tomorrow、Move Do Date）で `scheduled` が変わっても、その日のボードには「片付いた」として残る
- サブを消した、別の親に移した、などで合成キーが指すサブがなくなったら、そのカードは出さず、未完了にも数えない。締めるときにも止めない
- 「Not done」の一覧のサブには、Close・Cancel・Do Tomorrow・Move Do Date を出す。Inbox はサブにはない（サブは親の中にあり、Inbox に送る意味がない）

### 記録の形（ボードの操作ログ。ADR-0020）

カードの鍵は、issue は `i-N`、サブは合成キー `i-N#xxxxxx`（ADR-0135）、routine は `r-N`。`add`・`remove`・`carry`・`close` の `task` / `tasks` も、この鍵で書く。

★ は新しい op `star` で書く。

```json
{"id":"bo_0123456789","at":"2026-11-16T00:00:00.000Z","date":"2026-11-16","op":"star","task":"i-12#k3f9a2","on":true}
```

並びは `order` から `group` を除いた形にする。ボード全体で 1 つの並びを持つ。

```json
{"id":"bo_0123456789","at":"2026-11-16T00:00:00.000Z","date":"2026-11-16","op":"order","tasks":["i-3","i-12#k3f9a2","r-1"]}
```

| op | 追加の欄 | 再生したときの効果 |
|---|---|---|
| `star` | `task`、`on`（true で付ける、false で外す） | その日のボードの ★ を変える |
| `order` | `tasks`（ボードの並び） | 並びを変える。書き方と引き継ぎは ADR-0114 と同じ |

- ★ はその日だけのもので、翌日には引き継がない。毎朝選び直す（Ivy Lee method、MIT）
- ★ の 3 件は、付けるときに画面と MCP が止める。2 台が同時に付けて 4 件以上になったら、そのまま全部出す（再生の結果を操作の順だけで決めるため）
- 並び（`order`）は、そのボードの日付までの最後のものを翌日以降にも引き継ぐ（ADR-0114 と同じ）。1 つの並びを、★・次にやる順・待ち・委任の 3 つの欄がそれぞれの中の順に使う。並びにないもの（新しく載ったもの）は、載せた順で末尾に出す
- 以前の形式の `place` と、`group` の欄を持つ `order` は、読んでも捨てる（問題として報告しない）。既存のデイリーノートの frontmatter の `board.groups` も読まない。追記だけの記録なので書き換えない
- 移行したサブ（`migrated_from`。ADR-0135）の以前の ID を指すボードのログは、worklog と同じく、そのサブの合成キーとして読む

### グループを廃止する

- `issue/board-groups.json`、routine の `group`、Board groups の画面（GroupManagerView）と開くコマンド・ボタン（`Edit groups`）、グループごとのまとめて再生 / 停止、MCP の `move_card` の `group` を廃止する
- 移行 `0137-board-lanes` を付ける: `issue/board-groups.json` を消し、routine の frontmatter から `group` を消す。`check.mjs` は残っていれば報告する

### MCP

- `get_board`: 欄ごとのカードの一覧（`working` / `top` / `next` / `waiting` / `done`。それぞれ上の並び）を返す。サブは `key`（合成キー）・`parent`・`summary`・`status` を持つ。`groups` は返さない
- `move_card` を、並べ替えの `order_card`（`date`・`key`・`before`。`before` が null なら末尾）と、★ の `star_card`（`date`・`key`・`on`）に置き換える
- `add_to_board` はサブの合成キーも受け付け、その日が `scheduled` でなければ足してから載せる
- `close_board` の要約（デイリーノートの `## Task board`）は、サブを `i-12 › 題` の形で書く

## 理由

- 欄が status とタイマーで決まると、カードを分ける操作がいらない。決まっていることは仕組みが行う（プロダクトの方針「決めることを減らす」）
- 「作業中」をタイマーだけで決めると、少しずつ進める in-progress が何日も続いても欄が膨らまない。作業の切り替えには損失があり（Rubinstein, Meyer & Evans, 2001）、同時に手を付けているものが一目で分かる
- ★ を 3 件に限るのは、その日に最も大事なものを先に決めて、そこから手を付けるため（Ivy Lee method・MIT・Final Version。どれも経験則）。毎朝選び直すので引き継がない
- 「待ち・委任」をたたまずに件数を出すと、AI に任せた結果のレビュー待ちを見落とさない（Personal Kanban の「見える化」。Benson & DeMaria Barry, 2011）
- 並びを 1 つにすると、★ を外したものは元の位置に戻り、欄を移っても順番を失わない。ADR-0114 の書き方（並び全体を書く・今日いない ID の位置を残す）をそのまま使える
- ★ を `star` の op にすると、並びと独立に付け外しでき、どの端末の組み合わせでも再生の結果が決まる
- サブをカードの単位にすると、ガント（ADR-0143）で計画したサブを、その日のボードでそのまま記録できる（worklog の `sub`。ADR-0135）
- 隣り合ったサブを親の見出しでまとめると、カードを小さくしても、どの issue の作業かが分かる

## 却下した案

- **グループを残し、欄を足す**: カードを分ける手間が残る。欄とグループの 2 つの軸が重なり、どこに出るかが分かりにくい
- **in-progress を「作業中」の条件にする**: 少しずつ進めるタスクが何日も欄に残り、同時に手を付けているものが分からなくなる
- **★ を `order` の先頭 3 件とみなす**: 並べ替えるだけで ★ が変わり、★ を外したものの位置も失う
- **★ を翌日にも引き継ぐ**: その日に最も大事なものを毎朝決める、という目的に合わない。持ち越したものは「次にやる順」の並びで上に残る
- **欄ごとに別の並びを持つ**: ★ や待ちから戻ったときの位置が決まらない。記録の形も増える
- **サブを、その日が `scheduled` のものだけ出し、載せる操作を持たない**: 持ち越しで `scheduled` が変わると、その日のボードからカードが消え、片付けたことが残らない。issue と扱いが分かれる
- **親のカードの中にサブを入れ子で出す**: カードが大きくなり、サブごとの欄（作業中・待ちなど）に分けられない
- **以前の `place` を読み、グループを ★ や欄に写す**: グループの意味は Vault ごとに違い、写す先が決まらない

## 影響

- pkm-task の `main.js`、`.kit/bin/` の CLI（MCP）、`styles.css` が変わる。pkm-updates の `main.js` も pkm-task の読み込みを含むのでビルドし直す
- 移行 `0137-board-lanes` を付ける（`issue/board-groups.json` と routine の `group` を消す）。子の Vault でグループを使っていたら、その分けは失われる（`.kit/changes/` に書く）
- 古い版の pkm-task は、`star` と `group` のない `order` を「操作が不正です」として報告し、その行を飛ばす（ボードのほかの状態は壊れない）。プラグインは Vault と一緒に同期されるので、同期を終えれば消える
- ADR-0014 / 0015 のグループとボードの配置、ADR-0034 のカードの置き場所の記憶、ADR-0114 のグループの中の並び、ADR-0031 のカードの「次の status」ボタンを置き換える。それぞれの状態に「一部置換: ADR-0137」を書く
- プロダクトの文書（`surfaces/task-board.md`、`surfaces/task-board-groups.md`、`concepts/task-board.md`、`concepts/task-board-group.md`、`jobs/task-plan-day.md` など）と `.kit/src/docs/design.md` の部品の表を直す
