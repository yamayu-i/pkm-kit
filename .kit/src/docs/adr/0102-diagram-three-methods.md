# ADR-0102: AI が描く図を Mermaid / D2 / SVG の 3 方式にし、デザイン規約・PNG のコピーと保存・大きい図の拡大を共通にする

- 状態: 承認
- 日付: 2026-11-09

## 背景

[ADR-0064](0064-drawio-diagrams.md) は図を Draw.io の編集可能 SVG（`asset/*.drawio.svg`）に決めた。目的は、Mermaid より自由で見やすい図を描くことだった。[ADR-0085](0085-drawio-cli-build-render.md) は、Claude Code が図を作れるように CLI に `build` / `render` を足した。Issue #100 は、Draw.io の embed が重いので自前のエディタを作ることを提案した。

ところが、図の使い方のほとんどは「AI が描いて、人が見る」。手で直すことはまれで、直すときも AI に頼めばよい。自前のエディタは「編集が重い」ことへの投資で、見やすさには効かない。

同じ構成図（グループ 4、ノード 15、辺 16）を、5 つの方法で 1 回ずつ描いて比べた（Issue #102）。

| 方法 | 結果 |
|---|---|
| `build`（drawio、自動配置） | 線が箱を貫通し、流れが逆向きになり、迂回線が束になった |
| Mermaid（自動配置） | グループを使えば読める。配置は思いどおりにならない |
| D2（ELK の自動配置） | 線は箱を避けるが、大回りと交差が多い |
| Typst（fletcher。格子の位置を AI が決める） | 線が斜めに交差し、ラベルが重なった |
| SVG を AI が直接書く | 線が箱を通らず、流れが読める |

見やすさを決めているのは「誰が配置を決めるか」だった。AI が配置と線の経路まで決めた SVG だけが、狙った見た目になった。

## 決定

### 1. AI は内容に応じて 3 つの方式から選ぶ

| 方式 | 使う場面 | 置き場所 |
|---|---|---|
| a. Mermaid | 手順・分岐の流れ図、シーケンス図、状態遷移、ガント。ノードは約 12 まで。人がテキストで直すかもしれない図 | ノートの ` ```mermaid ` のコードブロック |
| b. D2 → SVG | ノードが多い構成図・関係図で、自動配置でよく、中身がよく変わる図 | `asset/<名前>.d2`（ソース）と `asset/<名前>.svg`（描画）。ノートは SVG を参照する |
| c. SVG を AI が直接書く | 配置に意味がある図（概念図、レイヤー図、比較、マトリクス、説明の一枚）。a・b で表せない図。描いたらあまり変えない図 | `asset/<名前>.svg` |

- 迷ったら a → b → c の順に検討する（作る手間と、直しやすさの順）
- 選び方と手順はスキルに書く。ADR-0085 の「Claude Code が図を作るときは `build` か `render` を通す」は、既存の `.drawio.svg` を直すときだけに狭める
- c は、描いたあとブラウザがある環境では画像にして AI が見て確かめる（重なり・はみ出し）

### 2. 見た目はトークンから生成したテーマで揃える

AI は色の値（hex）を書かず、役割の名前（`blue`、`amber` など、トークンの色の名前）だけを使う。テーマは `tokens.json` から生成する（[design.md](../design.md) の「値は正本に 1 か所、ほかは生成する」）。

| 方式 | 合わせ方 |
|---|---|
| a. Mermaid | Obsidian は Mermaid を本文の中に SVG として描くので、CSS が効く。トークンから作るスニペット（`pkm-theme.css`）に Mermaid 用の CSS を足す。ダークテーマにも自動で追従する |
| b. D2 | トークンから D2 のテーマの設定（`theme-overrides` / `dark-theme-overrides`）を生成し、描くたびに読み込む |
| c. SVG | トークンから SVG 用のスタイル（決まったクラスと色）を生成する。AI はクラスだけを書き、CLI がスタイルを差し込む。検査で、決まったクラスと色しか使っていないかを確かめる |

- b・c はノートから画像として読み込まれるので、Obsidian の CSS が届かない。ダークの色は SVG の中の `prefers-color-scheme` で切り替える。これが Obsidian のテーマ設定（OS の設定ではなく）に従うかは実機で確かめる。従わなければ、背景を透明にしてどちらのテーマでも読める色に絞るか、プラグインで SVG を本文に埋め込む

### 3. PNG のコピーと保存を、図すべてで使えるようにする

- pkm-drawio の図の操作バー（ADR-0064）を、図すべて（`asset/` の SVG、Mermaid のコードブロック、既存の `.drawio.svg`）に広げる
- 操作は「コピー」「PNG で保存」「拡大」の 3 つ。`.drawio.svg` は今の「SVG・XML のコピー」「編集」も残す
- PNG は、ノートをダークテーマで見ていても常にライトの色で作る（貼り付け先の多くは白い背景）
- Mermaid は、Obsidian の API（`loadMermaid`）でラベルを `<text>` にする設定で描き直してから PNG にする。Obsidian が描いたものは、ラベルが `foreignObject` で Canvas が汚染されるうえ、CSS の色が SVG を取り出すと消えるため
- 保存先: PC は保存のダイアログ。モバイルは共有シート。どちらも使えなければ `tmp/<図の名前>.png` に書いて通知する

### 4. 大きい図は、予防・印・拡大表示の 3 段で扱う

| 段 | すること |
|---|---|
| 描くとき（予防） | ノートの幅（約 700px）で読める大きさに収める。収まらなければ図を分けるか向きを変える。b・c は CLI の検査で警告する（幅に縮めたときに文字が約 9px を下回るなど） |
| ノートの中 | 幅に合わせて縮めて全体を見せる（今と同じ）。縮めすぎて文字が読めないときだけ「拡大して見る」の印を出す |
| 拡大表示 | 操作バーの「拡大」かタップで、全画面のモーダルを開く。ホイールとピンチで拡大・縮小し、ドラッグで動かす。「全体を表示」「100%」を付ける。PC とモバイルで同じ部品にする |

### 5. drawio は既存の図のために残す

- 既存の `.drawio.svg` の表示・コピー・編集（embed）・`render` はそのまま。移行はしない
- 新しい図は 1 の 3 方式で作る。drawio の新しい機能（自前のエディタ、`build` の配置の改善）は作らない
- プラグインは pkm-drawio のまま広げる。ID を変えると子の Vault の設定に移行が要るため、名前は変えない

### 6. 安全性

- b・c の SVG は、書く前に CLI で検査する: `<script>`、イベントの属性（`on*`）、外部の参照（`href` の `http(s):`・`javascript:`、外部の `@import`・フォント）、`foreignObject` を許さない
- Mermaid は Obsidian の描画に任せる（プラグインは描き直すだけで、内容を足さない）

## 理由

- 「AI が描いて、人が見る」が主な使い方なら、見やすさは描く段階で決まる。AI に配置まで任せる c が最も見やすく、a・b は手間と直しやすさで勝る。場面ごとに選べば、すべてを 1 つの方式でまかなうより良い
- テーマを生成すれば、方式が違っても色と形が揃い、AI が色を選ぶ手間とばらつきがなくなる
- 操作バーは pkm-drawio にすでにあり（コピー、PNG の作成）、広げるだけで済む
- drawio を残せば、既存の図と、手で細かく直したいときの逃げ道を失わない。新しい開発をしなければ、費用は増えない

## 却下した案

- **自前の軽量な図のエディタを作る（#100）**: 編集の重さは解決するが、見やすさには効かない。手で直すことはまれ
- **SVG を直接書き、自前の SVG エディタを作る**: 使い方に対して過剰。直すのは AI に頼めばよい
- **`build` の自動配置を改善する**: 線が箱を避ける経路の計算とグループをまたぐ配置が要り、作るものがグラフ配置のエンジンになる。試した中で最も見にくかった
- **`build` に座標と経由点を書けるようにし、drawio の形式で AI が配置する**: drawio で開けることを残すためだけに作るものが増える。手で直すことがまれなら、価値が小さい
- **Typst（fletcher）**: AI が位置を決める点は SVG と同じで、変換の手間とパッケージの取得が増える
- **D2 をプラグインで描画する（WASM 版）**: モバイルでも描けるが、プラグインが約 8MB 重くなる。描画済みの SVG を置けば、モバイルは表示だけで足りる

## 影響

- スキル: `drawio-diagram` を、3 方式から選んで描く手順に変える（名前を変えるかは実装時に決める）。子向けの規約（`.claude/docs/vault-conventions.md`）の図の規則を変える
- CLI: `.kit/bin/` に、c の SVG へのスタイルの差し込みと検査、b の D2 の描画（テーマの読み込み）を足す。D2 は外部のコマンド（`d2`）を使い、リポジトリの依存には足さない。Claude Code の環境に入れる
- デザイン: `tokens.json` から、Mermaid の CSS（`pkm-theme.css`）、D2 のテーマ、SVG のスタイルを生成する
- pkm-drawio: 操作バーを図すべてに広げ、PNG の保存と全画面の拡大表示、大きい図の印を足す
- ADR-0064 と ADR-0085 は一部置換になる
- 子の Vault のファイルは変えないので、移行はない。子から見える変更は `.kit/changes/` に書く
