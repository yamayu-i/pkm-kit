# ADR-0239: 本文のサブのカードの題は、題の横の編集アイコンボタンでその場で直す

- 状態: 承認
- 日付: 2026-11-27

## 背景

#239。

- issue 画面の本文のサブのカード（[ADR-0161](0161-sub-issue-cards-in-body.md)）を開くと、題の行（status・題と開閉・Pick）の下の欄の先頭に、Summary の入力欄が出る
- 題が、行の表示と Summary の入力欄の 2 か所に出る。開くたびに同じ文字が上下に並び、カードが重く見える

## 決定

- 開いたカードの欄から、Summary の入力欄をなくす。ほかの欄（委任先、日付のチップ、見積もり、Size、依存先、Show source）は今のまま
- 開いたカードの題の行で、題の右（Pick の前）に編集アイコンボタン（鉛筆。`aria-label` は「Edit title」）を出す。閉じたカードには出さない（閉じたカードは題を押すと開く、のまま）
- 押すと、題の文字がその場で 1 行の入力欄に変わり、フォーカスが入る。status のアイコンと開閉の矢印、Pick は残す。入力中は題を押しても開閉しない
- 保存の規則は今の Summary の欄と同じ: Live Preview は入力が止まって 600 ms か欄を離れたとき、Reading は欄を離れたとき（Enter を含む）。`trim` して書き、空は書かない。検査に通らなければカードの中に日本語の説明を出す
- Enter か欄を離れたら表示に戻る。Escape は入力前の題に戻して表示に戻る（Live Preview で 600 ms の保存が済んでいれば、その題に戻す）。IME の変換中の Enter では戻らない
- 上端に浮かべる題の行（`StickySubRow`）には編集アイコンボタンを出さない。直すのはカードで行う
- ヘッダーの「Sub-issues」カード（ADR-0142）は変えない

## 理由

- 題を 1 か所にだけ出すので、開いたカードが軽くなる
- 題を直す頻度は、日付や見積もりより低い。ボタンを 1 回押す手間は小さい
- 題の横の鉛筆で直す形は、note・source・wiki のヘッダー（ADR-0238）と揃う
- 浮かべた行は、スクロールで出たり消えたりする重ねた部品なので、入力欄を置くとフォーカスを失いやすい

## 却下した案

- **開いたカードでは常に題を入力欄にする**: 押して開閉する行と入力欄が重なり、どこを押せば開閉するか分かりにくい
- **開いたカードの欄をすべて畳み、編集アイコンボタンで出す**: 日付や見積もりはよく直すので、手数が増える
- **題の文字を押したら入力欄にする**: 題を押すと開閉する今の操作とぶつかる

## 影響

- ADR-0161 の「開くと、題・status・…の欄をカードの中に出す」のうち、題の欄を置き換える（一部置換）。ADR-0158 の表の「題 | 1 行の入力」も同じ
- `docs/design.md` の部品の表の、本文のサブのカードの行を直す
- データの形式は変わらないので、移行は要らない。子から見える変更として `.kit/changes/` に書く
