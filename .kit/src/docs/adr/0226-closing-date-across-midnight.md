# ADR-0226: 締めの日付を Close board で決め、夜中の 0 時から決めた時刻までは前日を締める

- 状態: 承認
- 日付: 2026-11-24

## 背景

Closing の画面（[ADR-0206](0206-closing-view-and-routine-category.md)）と Close board は、端末の暦の今日（`localToday`）を使い、1 分ごとに読み直している。夜中に締めると、次のことが起きる（Issue #226）。

- 23:50 に Close board を押し、締めている途中で 0 時を過ぎると、画面が翌日の Closing（翌日のボード・作業・ノート）に変わる。Closing routine の結果と Finish closing の記録は、翌日のボードに書かれる
- 0:30 などに初めて Close board を押すと、最初から翌日のボードの締めになり、翌日のデイリーノートに振り返りの型が入る
- 未完了のない過去のボードは、0 時を過ぎると Today が開いているだけで自動で締められる。前日の Closing routine を片付ける前に記録が書かれることがある

一日の終わりが 0 時より後になる使い方は普通にある。一方で「今日」は Calendar・Pick・ボード・タイマー・MCP など多くの場所で使っていて、暦の日付で動いている。

## 決定

### 締めの日付を Close board で決める

- Close board を押したときに、締める日（以下、締めの日）を決めて覚える。Closing の画面は、← Board で戻るまでこの日を使い続ける。0 時を過ぎても変わらない
- 締めの日の Closing routine の結果・Finish closing の記録・振り返りの型は、締めの日のボードとデイリーノートに書く（今と同じ処理に、締めの日を渡す）
- 見出しは今と同じ `Closing · 11/23 MON` で、締めの日を出す。締めの日が暦の今日でないときは、見出しの横に `yesterday` の小さい付記を出す

### 0 時から締めの猶予の時刻までは、前日を締める

- 設定に「締めの猶予（時）」を足す（端末ごと。`data.json`）。0〜6 の整数で、既定は 4。0 にすると今と同じ（猶予なし）
- 暦の今日の 0 時から猶予の時刻までの間（猶予の間）に、前日のボードがあって締めていないなら、ボードの末尾のボタンは前日を締める。ボタンの文言は `Close 11/23 MON` にして、どの日を締めるかを示す。押すと締めの日を前日にして Closing の画面に移り、前日のデイリーノートを開いて型を入れる
- 前日のボードがない、または締めてあるときは、今と同じく今日を締める
- Today の他の段階（Calendar・Pick・ボード）とタイマーは、暦の今日のままにする。猶予の間に変わるのは、ボードの末尾のボタンが指す日だけ

### 締めの日に含めるもの

- 締めの日を D として、Tasks の「その日に closed / canceled にしたもの」（statuslog）と Notes の「その日に変えたノート」は、D の 0 時から D の翌日の猶予の時刻まで（猶予が 0 なら D の終わりまで）を数える。0:20 に閉じた issue や書いたノートが、前日の締めに出る
- 作業時間（worklog）は、今と同じく記録の始めた日で数える。範囲を広げると、前日と今日の締めで同じ記録を二重に数えるため
- Notes の `new`（created）も同じ範囲で決める

### 前日のボードの自動の締め

- 未完了のない過去のボードを自動で締める処理は、猶予の間は前日のボードを締めない。猶予が過ぎてから、今と同じ条件で締める

## 理由

- 締めの途中で日付が変わる問題は、押したときに日付を決めれば、設定なしで直る。締めは押してから終わるまでの一続きの作業なので、その間は同じ日を指すのが自然である
- 0 時を過ぎてから締めるのは、前日の続きの作業である。ただし「今日」の定義を全体で変えると、Calendar の日・期限・タイマーの記録・MCP・pkm-template のデイリーノートなど、暦の日付で動くものとずれる。締めのボタンが指す日だけを変えれば、影響を締めの中に閉じ込められる
- ボタンの文言に日付を出すのは、ボードは今日のものを見せたまま、別の日を締めることになるため。何を締めるかを押す前に分かるようにする
- 猶予の間の statuslog とノートを前日に含めるのは、締めの直前にした片付け（0:20 に閉じた issue、書いた振り返りのメモ）を、その締めの一覧に出すため
- 猶予を端末ごとの設定にするのは、生活の時間が端末ではなく人で決まるとしても、既存の設定（端末名など）と同じ置き場所で済み、Vault の共有の設定を新しく作らずに済むため。既定の 4 は、夜更かしの締めを拾い、早朝の作業を前日に混ぜない値

## 却下した案

- **一日の始まりの時刻を Today 全体（「今日」の定義）に入れる**: Calendar の日・期限・routine の予定日・タイマー・MCP・pkm-template のデイリーノートの日付と、どこで暦の日付を使い、どこで論理の日付を使うかを全部決め直すことになる。困っているのは締めだけで、影響が大きすぎる
- **締めの日を押したときに固定するだけにする（猶予を作らない）**: 0 時を過ぎてから初めて押す場面が直らない
- **Closing の画面に日付の選び直し（前の日へ）を置く**: 毎回選び直す手間がかかり、選び忘れると翌日のデイリーノートに型が入る。型は入れた後に消す必要がある
- **猶予の間は Today 全体を前日として見せる**: 前日のボードに新しいカードを載せたり、タイマーの記録が前日のカードに付いたりする。0 時を過ぎてからの作業は今日のもの
- **worklog も猶予の範囲で数える**: 前日と今日の締めで、0 時から猶予の時刻までの記録を二重に数える

## 影響

- pkm-task: DailyView に締めの日の状態、ボードの末尾のボタンの日付、自動の締めの条件。`core/closing.ts` の statuslog とノートの範囲。設定に「締めの猶予（時）」
- 子への移行はない（設定の既定で動く。今の挙動に戻すなら 0 にする）。子から見える変更なので `.kit/changes/` に書く
- プロダクトの文書（Closing、ボード、一日の締めの場面）と task-coach の夕の手順で、夜中の締めに触れる
- ADR-0206 の「上の見出しの日付」「Notes はその日に変えたノート」の範囲を、この ADR で一部置き換える
