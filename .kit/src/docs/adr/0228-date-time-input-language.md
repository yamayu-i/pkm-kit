# ADR-0228: 日付・時刻・期間の入力を 1 つの書き方（入力言語）にまとめる

- 状態: 提案
- 日付: 2026-11-24

## 背景

日付・時刻の入力の書き方が、欄によって分かれている。

| 欄 | 書き方 |
|---|---|
| pkm-task の日付の欄、pkm-template の `{{prompt-date}}` | ADR-0017 の短い書き方（`1224`、`+1d`、`+m`、`fri`）。テンプレートは `-d` を足す（ADR-0065） |
| issue 画面の worklog の編集・追加 | 日付の欄（ADR-0017）と時刻の欄（`hhmm` / `hh:mm`）を分ける |
| ボードと Tasks Now の Edit times | ADR-0193 の書き方（`-22m`、`2200`、`2200-1d`、`ddhhmm`、`mmddhhmm`、`yymmddhhmm`） |
| 見積もり（estimated） | `30` / `2h` / `1h30m` / `0.5d`（ADR-0034） |

このため、次のことが起きている。

- 同じ入力でも欄によって意味が違う。`1224` は日付の欄では 12/24、Edit times では 12:24。`m` は日付の欄では月、見積もりと Edit times では分
- worklog の開始・終了を直す画面が 2 つあり、書き方も見た目も違う
- 解釈の結果の表示が 3 通りある（`2026/11/24 (tue)`、`11/24 TUE 22:05`、`Inserts: 2026-11-24 TUE`）
- 「今より後は入れられない」「空なら今日」などの欄ごとの決まりが、書き方の規則と混ざっている

使われ方がはっきりしてきた。日時の入力は、ほとんどがその日の時刻で、ときどき日をまたぐ。日付は、今日からの相対か曜日が多い。

## 決定

### 1. 入力言語と欄の設定を分ける

- **入力言語**: 書き方と意味。すべての欄で同じにする
- **欄の設定**: 欄ごとに決める
  - 種類: 日付・日時・期間
  - 空欄のとき: クリアする、今日にする、入力が必須
  - 時刻だけのときの日（日時の欄）
  - 制約: 今より後は不可、Tickler の上限（ADR-0210）など
  - 欄だけの修飾（テンプレートの `-d`）

入力言語は 1 つの処理（`shared/`）で解釈し、欄の設定は引数で渡す。

### 2. 入力言語

大文字と小文字は区別しない。前後の空白は無視する。語と語は空白で区切る。

#### 日付

| 区分 | 書き方 | 例（今日が 2026-11-24 の火曜） |
|---|---|---|
| 絶対 | `dd` | `15` → 2026-11-15 |
| | `mmdd` | `1224` → 2026-12-24 |
| | `yymmdd`（20yy 年） | `270105` → 2027-01-05 |
| | `yyyymmdd` / `yyyy-mm-dd` / `yyyy/mm/dd` | `2027-01-05` → 2027-01-05 |
| 相対 | `±N`（日） | `+3` → 2026-11-27 |
| | `±Nd` / `±Nw` / `±Nmo` / `±Ny` | `+2w` → 2026-12-08、`+mo` → 2026-12-24 |
| | 単位の組み合わせ（各単位は 1 回まで。順は問わない） | `+1w2d` → 2026-12-03 |
| 曜日 | `fri`（`+fri` と同じ） / `+fri` / `-fri` / `+2fri` | `fri` → 2026-11-27、`+tue` → 2026-12-01 |
| 語 | `today` / `tomorrow` / `yesterday` | `tomorrow` → 2026-11-25 |

- 数字を省くと 1（`+w` は `+1w`）。ただし単位のない `+` / `-` だけはエラー
- `mo` と `y` で、その月にない日になるときは月末にする（01-31 の `+mo` → 02-28）
- 曜日の名前は英語の 3 字（`sun` 〜 `sat`）だけ。`+tue` / `-tue` は、今日と同じ曜日なら 7 日先 / 前（ADR-0017 と同じ）
- 語は省略しない（`tom` は読まない）

#### 時刻

| 区分 | 書き方 | 例（今が 2026-11-24 23:00） |
|---|---|---|
| 絶対 | `hhmm` / `hh:mm` / `h:mm` | `2200` → 22:00、`9:30` → 09:30 |
| 相対（今から） | `-Nm` / `-Nh` / `-NhMm`。欄が今より後を許すときは `+` も | `-22m` → 2026-11-24 22:38 |
| 語 | `now` | `now` → 2026-11-24 23:00 |

- 相対の時刻は、秒を切り捨てた今から数える（ADR-0193 と同じ）。日付も含めて決まるので、日付と組み合わせない
- `m` は分。月は `mo` にする

#### 日時

```
日時 = 時刻 [ 日付 ]
```

| 入力 | 解釈（今が 2026-11-24 の火曜 23:00） |
|---|---|
| `2200` | 時刻だけ。日は欄の設定で決める（下の表） |
| `2200 -1d` | 2026-11-23 22:00 |
| `0930 fri` | 2026-11-27 09:30 |
| `2200 1224` | 2026-12-24 22:00 |
| `-1h10m` / `now` | 相対の時刻（日付は付けられない） |
| `2026-11-24 22:00` | 保存の形。`-` を含む日付だけは時刻の前に書いてよい |

- 時刻を先に書く。数字だけの語が 2 つ並んでも、前が時刻、後が日付と決まる
- 日付だけ（`fri`）はエラーにする。日時の欄には時刻がいる

時刻だけのときの日（欄の設定）:

| 欄の向き | 日の決め方 | 例 |
|---|---|---|
| 過去向き | 今か今より前で、いちばん近いその時刻 | 今が 01:00 なら `2330` → 前の日の 23:30 |
| 基準より後 | 基準の日時より後で、いちばん近いその時刻 | From が 23:30 なら `0040` → 次の日の 00:40 |

#### 期間

`[Nd][Nh][Nm]`。各単位は 1 回まで、数は小数でもよい（`0.5d`）。単位のない数は分。`1d` は 24 時間（ADR-0034 と同じ）。

#### 読めない入力

表にない形、存在しない日付・時刻（`0231`、`2460`）は、推測しないでエラーにする（ADR-0017）。

### 3. 表示

- 欄を離れたとき（Enter・Tab・クリック）に、読めた入力を保存の形に書き換える。日付は `yyyy-mm-dd`、日時は `yyyy-mm-dd hh:mm`。読めなければ、入力した文字を残してエラーを出す（ADR-0193 と同じ）
- 欄の下の解釈の結果: 日付は `2026-11-24 TUE`、日時は `2026-11-24 TUE 22:00`。曜日はすべて英大文字 3 字にする（デイリーノートの題、`{{date:DDD}}` と同じ）。読めないときは `日付として読めません` / `日時として読めません`

### 4. 欄の設定

| 欄 | 種類 | 空欄のとき | 時刻だけのときの日 | 制約 |
|---|---|---|---|---|
| soft_deadline、deadline、Calendar、Tickler、revisit、サブの日付、routine の start・end | 日付 | クリア | — | Tickler の上限（ADR-0210） |
| 日付を聞くダイアログ（`askDate`。移動、Organize、Someday） | 日付 | 入力が必須 | — | — |
| テンプレートの `{{prompt-date}}` | 日付 | 今日 | — | 修飾 `-d`（曜日を付ける。ADR-0065） |
| worklog の開始（From、Start） | 日時 | 入力が必須 | 過去向き | 今より後は不可 |
| worklog の終了（To、End） | 日時 | 記録中 | 開始より後 | 今より後は不可。開始より後 |
| 見積もり（estimated） | 期間 | クリア | — | 0 より大きい |

issue 画面の worklog の編集・追加も、Edit times と同じ日時の欄（1 つの欄に、カレンダーと時計のボタン）にする。日付と時刻の欄を分けるのはやめる（ADR-0017 の「時刻を入れるときは入力欄を分ける」を置き換える）。

### 5. 範囲の外

- routine の月の日の指定（`15`、`last`、`2th-tue`）。くり返しの規則で、日時を 1 つ決めるものではない。曜日の名前だけ、この言語とそろえる
- MCP と CLI の引数。保存の形（`YYYY-MM-DD`）だけを受け付けたままにする
- 言語仕様の説明の画面（入力欄の横の ? から開く）。別の ADR で決める

### 6. 使われていない部品を消す

`CalendarForm`（`pkm-task/src/ui/forms.tsx`）は、プレビューからしか使われていないので消す。

## 理由

- 書き方を 1 つにすると、覚えることが 1 つで済み、欄によって同じ入力が別の値になることがなくなる
- 「今より後は不可」などは欄によって違う。言語から外して欄の設定にすると、言語の規則が少なく、説明しやすい
- 日時の入力の多くはその日の時刻なので、時刻を先に書き、日付は必要なときだけ後ろに付ける。日をまたぐ場合も、欄の向きで日を決めれば時刻だけで入れられる
- 数字だけの語の意味を、位置（前が時刻、後が日付）で決めると、迷いがない
- `m` を分に、月を `mo` にする。見積もりと記録の時刻では分を多く使い、月の相対は少ない
- 曜日の表示を英大文字 3 字にすると、デイリーノートの題やテンプレートの出力と同じになる

## 却下した案

- **欄の種類で `m` の意味を変える**（日付の欄では月、時刻の欄では分）: 「どの欄でも同じ言語」にならず、説明が 2 通りになる
- **日付を先に書く**（`-1d 2200`）: その日の時刻を入れるだけの場合が多いのに、日付を付けるときに打つ順が不自然になる。数字だけが 2 つ並んだときの決め方も必要になる
- **日付と時刻の順を自由にする**: 数字だけが 2 つ並んだときに、見分ける規則がもう 1 つ要る
- **ADR-0193 の書き方（`2200-1d`、`ddhhmm` など）を別名として残す**: 規則が増え、説明が長くなる。使う人が限られ、読めない入力は保存されない（エラーになるだけ）ので、すぐにやめる
- **語の省略（`tom`、`yes`）や前方一致**: 規則が 1 つ増える。相対の書き方（`+1`、`-1`）の方が短い
- **時刻だけのときは今日にし、今より後ならエラー**（ADR-0193 の今の動き）: 深夜をまたいだ記録を直すたびに日付を付けることになる

## 影響

- `shared/src/date-input.ts` を入力言語の解釈にする。日付・日時・期間と欄の設定を受け取る。`pkm-task/src/core/worklog-times.ts` の `parseTimeInputAt` と `pkm-task/src/core/format.ts` の `parseDurationInput` は、これに置き換える
- 日付の欄・日時の欄・解釈の結果の表示を、pkm-task と pkm-template で共通の部品にする（`shared/`）。`DateForm`、`DatePromptModal`、`WorklogForm`、`WorklogTimesForm` はこれを使う
- 今の書き方のうち、`+m`（月）、`2200-1d`、`ddhhmm`、`mmddhhmm`、`yymmddhhmm` は読めなくなる（エラーになる）。`.kit/changes/` に書く
- 保存の形（frontmatter の `YYYY-MM-DD`、worklog の日時）は変えない。子のノートや設定は変えないので、移行は付けない
- ADR-0017 と ADR-0193 を一部置換にする
- 画面に出る文言は英語、エラーは日本語（ADR-0076）
