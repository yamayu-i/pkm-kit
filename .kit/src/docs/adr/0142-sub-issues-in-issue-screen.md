# ADR-0142: 親の issue 画面でサブイシューを見る・作る・並べる

- 状態: 承認
- 日付: 2026-11-15

## 背景

ADR-0135 で、サブイシューを親の issue の md の中に持つことにした。画面（ヘッダーの一覧、本文の扱い、編集のダイアログ）は実装の Issue（#142）で決めることにしていた。ユーザーからは次の要望がある（#135）。

- サブを簡単に作れる。1 行の入力で、続けて何件も作れる
- サブを並べ替えられる
- closed のサブは、展開しない限りヘッダーに出さない

## 決定

### 置き場所

issue 画面のヘッダーの、予定（日付のストリップと期限）のカードの後ろ、実績のタイルの前に、カード「Sub-issues」を置く。見出しの横に、未完了の件数と全体の件数のチップ（`2 / 5`）を出す。サブがなくても、カードと追加の入力欄は出す。

### 1 件の行

ボードのカード（#137 の方向）と同じく、1 行に収める。

| 位置 | 中身 | 操作 |
|---|---|---|
| 左 | status のアイコン（`StatusIcon`） | 押すと status のメニュー。delegated は委任先を選ぶ（issue と同じ） |
| 中 | 題 | 押すと、行の下に本文と項目を開く（アコーディオン） |
| 中の右 | 補足 1 つ: 期間（`11/16–11/20`）、なければ次の予定日、なければ期限。弱い文字 | なし |
| 右 | 実績（そのサブの分）、再生 / 停止のボタン（`.vt-play`）、メニュー（`⋯`） | メニュー: Edit・Move up・Move down・Delete |

- 行はドラッグできる（デスクトップ）。落とす位置は、ボードと同じく primary の線で出す（ADR-0114 の `.is-drop-before`）。モバイルは HTML のドラッグが効かないので、メニューの Move up / Move down で並べる
- 開いた行には、本文を Markdown として描き（読み取り専用）、項目（期間、予定、期限、見積もり、依存先、委任先）と Edit ボタンを出す

### closed のサブ

- closed と canceled のサブは、既定では出さない。一覧の最後に「Show 3 closed」の text ボタンを出し、押すと md の並びの位置に弱い文字で出す（「Hide closed」で戻す）。開いたかどうかは保存しない
- 並べ替えは、出していないサブも含めた md の並びで行う（出ている行の前に置く）

### 作る

- 一覧の最後に、素早い追加の入力欄（`.vt-quick-add`、プレースホルダ「Add a sub-issue」）を置く
- Enter で 1 件作り、入力欄を空にしてフォーカスを残す。続けて打てば何件でも作れる
- 複数行を貼り付けたら、空でない行ごとに 1 件ずつ、その順に作る
- 作るサブは status が open で、ほかの項目は空。直すのは Edit で行う

### 直す（Edit のダイアログ）

モーダル「Edit sub-issue」に、題、status、委任先、期間（start / end）、予定（カレンダー）、soft deadline、deadline、見積もり、依存先（同じ親のサブから選ぶ）、本文（複数行の入力欄）を置く。Save で検査（ADR-0135 の規則。#141 の `checkSubIssues`）を通してから書き、通らなければダイアログの中に日本語の説明を出して書かない。Delete は確認のモーダルの後に消す（ほかのサブが依存していれば消せない）。

### 本文の見え方

- リーディング表示では、親の md のサブの領域（最初のマーカーから後ろ）を隠す。サブはヘッダーの一覧で読むため、親の本文の後ろに、題のない文が続いて見えるのを避ける
- 編集表示（ソース / Live Preview）では隠さない。md が正本で、手で直せるようにする

### 文言

画面に常に出る文言（見出し、ボタン、メニュー、ツールチップ、`aria-label`、プレースホルダ、空の表示）は英語、通知・エラーの説明・確認の文は日本語にする（`docs/design.md`「文言」）。

## 理由

- 1 行の行と、開くと詳しく見えるアコーディオンにすると、サブが多くても一覧が長くならず、全体を見渡せる
- 入力欄に続けて打つだけで作れると、思いついた順に分けられる。項目はあとで Edit で足せばよい
- closed を既定で隠すと、残っているものだけが見える。並べ替えを md の並びで行えば、隠したサブの位置も崩れない
- モバイルでもドラッグに頼らずに並べられる
- リーディング表示で隠すと、同じ内容が 2 か所に出ない

## 却下した案

- **行の中ですべての項目を直す**: 行が大きくなり、一覧性が落ちる
- **サブ専用の View を作る**: 親と離れ、ADR-0135 の「1 か所で全体像を見る」に反する
- **Live Preview でサブのブロックを部品に描き替える（CodeMirror の拡張）**: 作るのが重く、md を直接直したいときの邪魔になる。必要になってから考える
- **closed を一覧の最後にまとめる**: md の並び（作業の順）が見えなくなる

## 影響

- ヘッダーに「Sub-issues」のカードが増える。`docs/design.md` の部品の表に、サブの行と開いた中身を足す
- リーディング表示の後処理（Markdown の post processor）を pkm-task に足す
- ボード（#137）とガントチャート（#143）は、それぞれの ADR で決める
