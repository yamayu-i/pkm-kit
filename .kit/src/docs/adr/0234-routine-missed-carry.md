# ADR-0234: 積み残したら今日やる routine を、今日のボードに持ち越す（missed: carry）

- 状態: 提案
- 日付: 2026-11-26

## 背景

[ADR-0206](0206-closing-view-and-routine-category.md) で、routine の積み残し（予定日を過ぎて、その日のボードに結果のないもの）を、Today の Calendar の段階の Missed の「Routines」の節に、予定日ごとの行で出すことにした（Issue #234）。

ただ、routine には性質の違う 2 種類がある。

- 抜かしたら、その日の分はもう終わりのもの（毎日のストレッチなど）。積み残しは、あとで結果（たいていは canceled）を付けて片付けるだけ
- 抜かしたら、遅れてでも今日やらなければいけないもの（週報、月末の精算、週 1 の掃除など）。積み残しは、今日の作業になる

後者は、今日のボードに載っていないと見落としやすい。Calendar の段階は「Next」で一度通り過ぎると、段階表示ではチェック（済み）と小さい点だけになる。そのため、日中にボードを見ている間は、積み残しがあることに気づきにくい。

ADR-0206 は「積み残しをボードの routine の欄に出す」案を却下している。理由は次の 2 つ。

- 同じ routine が今日の分と過去の分で 2 枚になり、カードの鍵（routine の ID）がぶつかる
- 過ぎた予定は Calendar の Missed で扱う、という考えに合わない

この ADR は、カードを 1 枚にまとめて鍵のぶつかりを避ける。そのうえで、「今日やらなければいけない」routine だけを例外として、ボードに持ち越す。

## 決定

### frontmatter

- routine の frontmatter に `missed`（単一の文字列）を足す。値は `carry` だけ
- 書かないもの（null）は、今までどおりの扱い（積み残しを Calendar の Missed に出す）
- 知らない値は、検査が問題（warning）を出し、書かないものとして扱う
- テンプレートの `routine.md` は変えない（任意の項目。既存の routine は今までどおり動く）

### 持ち越し（carry）の判定

`missed: carry` の routine について、ある日 D の「持ち越し」を次のように決める。

- 予定日 d（`routineOccursOn` が真の日）のうち、d < D で、d から D の前の日までのどのボードにも、その routine の結果（closed / canceled）がないもの。これを「片付いていない予定日」とする
- 片付いていない予定日があれば、D に持ち越す。持ち越しの起点は、そのうち一番古い日
- 数え始めは ADR-0206 と同じ（routine の `start`（なければ作った日）と、積み残しを数え始める日（定数）の遅いほう）。一時停止した routine は出さない。`end` を過ぎた日は予定日にならない（`end` の前の片付いていない予定日は、片付くまで持ち越す）

結果は、その日（D）のボードにだけ書く。過去の日のボードには書かない。D の結果は、D より前の片付いていない予定日をすべて片付けたことにする。

- 例: 週 1 の routine を月曜に抜かした。火曜のボードに持ち越しで出る。火曜に closed にすると、月曜の分も片付いたことになる。水曜には出ない
- 例: 月曜と、次の月曜の両方を抜かした。カードは 1 枚で、起点は古い方の月曜。閉じると両方とも片付く

「抜かした回数だけやる」ことは扱わない。何回分を抜かしても、1 回やれば済むものとする。

### ボード

- D に予定がある日、または D に持ち越しがある日は、その routine のカードを D のボードの routine の欄に出す。予定と持ち越しが重なっても 1 枚にする（鍵は routine の ID のまま）
- 持ち越しのカードには、起点の日を `↻ 11/24` のように付記で出す（注意の色）。結果を付けた後も、その日のボードでは付記を出したままにする（何を片付けたかが分かるように）
- routine の欄の中では、持ち越しのカードを先に並べる。その中は、起点の古い順、同じ日は routine の並び順。持ち越しでないカードは、今までどおり並び順
- 結果の付け方（status のボタン・メニュー）は、今までの routine のカードと同じ。結果を外す（open に戻す）と、また持ち越しになる
- category が `closing` の routine も同じ扱いで、Closing の画面の Closing routines に出る
- ボードの未完了（自動の締め、Closing の Not done）にも、結果のない持ち越しのカードを含める

### Calendar の Missed

- `missed: carry` の routine は、Calendar の Missed の Routines の節に出さない（ボードに出るので、二重に出さない）。段階の件数にも入れない

### routine の画面

- routine の画面（ヘッダー）で、積み残しの扱いを選べるようにする（`missed`: なし / `carry`）。category の欄と同じ形にする
- 表示の名前は、なしを `list`（Calendar の Missed に並べる）、`carry` を `carry`（今日のボードに持ち越す）とする。`list` は表示だけの名前で、frontmatter には書かない

### MCP

- `get_overview` の `missedRoutines`・`missedRoutineCount` から、`missed: carry` の routine を除く（Calendar の Missed と同じ）
- `get_board` の routine のカードに、持ち越しの起点 `carriedFrom`（日付。持ち越しでなければ null）を足す
- 結果は、既存の `set_routine_result` で、`date` にその日を入れて付ける（今も予定日でない日に付けられるので、変えない）
- `get_routine_stats` で `missed` を返す（routine を書く MCP の操作は今もないので、足さない）

## 理由

- 「今日やらなければいけない」かどうかは routine の性質で、日ごとに選ぶものではない。frontmatter に書いておけば、毎日の操作が要らない
- カードを 1 枚にまとめれば、ADR-0206 が却下した理由のうち、鍵のぶつかりはなくなる。もう 1 つの「過ぎた予定は Calendar の Missed」という考えは、`carry` の routine では「過ぎた予定は、今日の作業」と読み替える。今日やるものの置き場所はボードなので、ボードに置く
- 結果を今日のボードにだけ書けば、過去の日のボードに「その日にやった」と書かずに済み、記録は事実のままになる。締めた後の過去のボードの記録を書き直さない、という ADR-0206 の決まりにも合う
- 判定を、ボードに書いた結果から都度計算すれば、新しい保存先が要らない（[ADR-0002](0002-frontmatter-as-source-of-truth.md) の派生値を保存しない考え）
- 値を固定（`carry` だけ）にするのは、category と同じく、値によって出す場所が決まるため

## 却下した案

- **積み残しの日ごとに、カードを分けて出す**: 鍵がぶつかる（ADR-0206 と同じ理由）
- **閉じたときに、積み残した過去の日のボードに結果を書く**: その日にやっていないのに、やったと記録することになる。締めた後のボードの記録とも食い違う
- **一番古い日の分だけを閉じ、残りは次の日にまた出す（抜かした回数だけやる）**: 当てはまる routine がほとんどない。ボードに 1 枚しか出ないので、何回分残っているかを別に見せる必要があり、仕組みが重くなる。必要になったら値を足す
- **すべての routine の積み残しをボードに出す**: 抜かしたらその日の分は終わりの routine まで、今日の作業として出てくる。ボードが過去の始末で埋まる
- **Calendar の Missed の行に「今日のボードに載せる」ボタンを足す**: 毎回手で選ぶ必要があり、選ばなければ見落とす。見落としを防ぐという目的に足りない
- **ボードに「Missed routines N」のお知らせの行だけを出す**: 気づけはするが、今日の作業としてボードで片付けられない

## 影響

- ADR-0206 の「積み残しをボードの routine の欄に出す」の却下を、`missed: carry` の routine については、この ADR で一部置き換える。ADR-0206 の状態を `承認（一部置換: 0234）` にする
- 変更するもの: `core/schema.ts`（`missed` の読み取りと検査）、`core/routine-order.ts`（持ち越しの判定、その日に出す routine、積み残しから carry を除く）、`core/board-lanes.ts`（カードの付記と並び）、`views/Board.tsx`（付記）、`views/ClosingView.tsx`（付記）、`header/RoutineHeader.tsx`（選ぶ欄）、`cli/mcp.ts`
- routine の frontmatter に任意の項目を足すだけなので、子への移行はない。`.kit/changes/` に子から見える変更を書く
- プロダクトの文書（routine、ボード、Today）と、task-coach の夕の手順を直す
