# ADR-0245: サブの期間は start と end を必ずそろえ、1 つのダイアログで選ぶ

- 状態: 承認（一部置換: 0255）
- 日付: 2026-11-27

## 背景

サブの期間（`start` / `end`。ADR-0135・0190）は、Edit のダイアログと本文のカード（ADR-0161）で、Start と End を別々の欄で入れる。片方だけのサブができ、Timeline（ADR-0143）は片方だけのものを 1 日の棒として描いている（`barOf`）が、データとしては期間になっていない（#245）。

`end` はサブの期限を兼ねる（ADR-0190）ので、`end` だけのサブは「期限だけ」として Daily の期限の表に出る。`start` だけのサブは期限の表にも出ず、Timeline だけで 1 日の棒になる。

## 決定

### 規則

- サブの `start` と `end` は、両方あるか、両方ないかのどちらか。`end` は `start` より前にできない（今までどおり）。同じ日は 1 日の期間
- 期限だけを持つサブは、`start` と `end` を同じ日にする

### 期間のダイアログ

- Edit のダイアログと本文のカードの Start・End の 2 つの欄を、Period の 1 つの欄（チップ）にまとめる。チップは行の補足と同じ形の `11/03–11/07`（同じ日なら `11/03`）、なければ `Not set`。Calendar（`scheduled`）の欄は別のまま
- 押すと期間のダイアログを開く
  - 上に Start と End の 2 つの入力欄。入力言語（ADR-0228）で書ける。End は Start を基準に読む（`+3d` は Start の 3 日後）
  - 下に月のカレンダー（`MonthCalendar`）。1 回目に押した日が Start、2 回目に押した日が End になり、その間を塗る。2 回目に Start より前の日を押したら、その日を Start にして選び直す
  - Clear は両方を消す。Save は両方そろい、End が Start より前でないときだけ押せる。片方だけ・逆転は、理由を欄の下に出す
  - Inbox の Project・Tickler の規則（ADR-0210）は、今の `subDateRules` と同じく、選ぶ前に止めて理由を出す
- Timeline は今までどおり両方を書く（棒を作る・動かす・端をずらす）

### 書く前の検査

- `checkSubIssues` に「start と end は両方入れるか、両方空けてください」を足す。画面・本文のカード・MCP（`create_sub_issues` / `update_sub_issue`）の、書く前の検査がすべてこれを通る
- MCP の `update_sub_issue` は、変えた後の姿で検査する。`start` だけを渡しても、もう `end` があれば通る
- lint は、片方だけのサブを `sub-period-half` で知らせる

### 移行

- 移行 0245 が、片方だけのサブのもう片方を同じ日にする（Timeline が今描いている 1 日の棒と同じ）。直したサブを移行の報告に出す

## 理由

- 1 つのダイアログで始まりと終わりを続けて選ぶと、片方だけの入力が起きにくく、期間が目で分かる
- 片方だけを許すと、`start` だけのサブが Timeline にしか出ないなど、画面ごとに扱いが割れる
- 移行で同じ日にすると、今 Timeline に見えている姿が変わらない

## 却下した案

- **片方だけを入れたら、もう片方を自動で同じ日にする**: 入れたつもりのない日が書かれ、気づきにくい
- **期間に触れる変更のときだけ検査する**: 片方だけのサブが残り続け、規則が守られない。移行で今のデータをそろえるので、常に検査してよい
- **Start と End の欄を残し、保存のときに検査だけする**: 2 つの欄を行き来するので、期間を選ぶ操作にならない

## 影響

- ADR-0142・0158・0161 の編集の欄（Start・End）を Period にまとめる。ADR-0143 の Timeline の片方だけの棒は、移行の後は出なくなる（`barOf` は外で編集したものに備えて残す）
- ADR-0190 の「期限」は、同じ日の期間でも持てる
- 子の Vault の issue の md が変わるので、移行 0245 を付ける。`.kit/changes/` に変更を 1 件書く
