# ADR-0230: 入力言語の書き方を、入力欄の横の ? から開く説明画面で見せる

- 状態: 提案
- 日付: 2026-11-24

## 背景

ADR-0228 で、日付・時刻・期間の入力を 1 つの書き方（入力言語）にまとめた。いまの画面には次の説明しかない。

- 入力欄の下の例（`e.g. 15 / 1224 / +1d / fri / +2w / +mo / tomorrow`）
- 入力欄の placeholder

このため次のことが起きる。

- `+1w2d`、`+2fri`、`2200 -1d` のような書き方があることに、画面からは気づけない
- 欄ごとに違う決まりが分からない。時刻だけのときの日（開始は今より前、終了は開始より後）、空欄の意味（クリア、今日、記録中）、テンプレートの `-d` など
- 書き方を確かめるには ADR を読むしかない

## 決定

### 1. ? のボタン

- 入力言語を読む欄の右に、? のアイコンボタン（`.vt-icon-button`、アイコン `circle-help`（古い Obsidian では `help-circle`）、aria-label と title は `Input syntax`）を置く。対象は次の欄
  - 日付の欄（`DateForm`）
  - 日時の欄（`DateTimeField`。カレンダーと時計のボタンの右）
  - テンプレートの日付のダイアログ（`DatePromptModal`）
  - 見積もりの欄（issue のダイアログ、サブの編集、サブのカード、routine の一覧）
- 押すと、いま開いているダイアログの上に説明のダイアログを重ねて開く。閉じる（Esc・×）と、元の入力欄にフォーカスを戻す。入力した文字は消えない
- Tab の順は、入力欄の後、カレンダーの前にする

### 2. 説明のダイアログ

- 題は `Input syntax`
- 上に「この欄では」の節を置く。開いた欄の設定を、短い日本語の文で書く。例えば worklog の開始の欄なら次の 2 行
  - 時刻だけなら、今より前でいちばん近いその時刻
  - 今より後の日時は入れられない
- その下に、日付・時刻・日時・期間の 4 つの節を置く。開いた欄で使う節を先に出し、使わない節は畳む
  - 日付の欄: 日付を開き、ほかは畳む
  - 日時の欄: 時刻と日時を開き、日付を後ろに続ける（日時の日付の部分になるため）。期間は畳む
  - 期間の欄: 期間だけを開く
- 各節は 3 列の表（`Input`、`Meaning`、`Now`）で示す
  - `Input`: 書き方（等幅）
  - `Meaning`: 意味（日本語の短い文）
  - `Now`: 今日・今を基準に解釈した結果（`2026-11-27 FRI` など）。開いたときに入力言語の解釈で計算する
- 表の下に、読めない入力の扱いを 1 行で書く（推測しないでエラーにする）
- 言葉は ADR-0076 に従う。題・列の名前・ボタンは英語、意味と「この欄では」の文は日本語

### 3. 説明の内容の正本

- 説明の表は、`shared/` に置くデータ（節・行・欄の設定ごとの文）1 つから作る。手で書いた HTML や文書を別に持たない
- テストで次を確かめる
  - 表の例がすべて入力言語で読める
  - `Now` の列が、解釈の結果と一致する
  - 欄の設定ごとに「この欄では」の文がある
- 書き方を足したり変えたりしたら、このデータも同じ変更で直す（テストが落ちる）

### 4. 置く場所

- ダイアログと ? のボタンは、pkm-task と pkm-template の両方で使うので `shared/` に置く（`input-help.tsx`、`input-help.css`。CSS は各プラグインのビルドで `styles.css` に続ける。ADR-0078 と同じ）
- 新しい依存は足さない

## 理由

- 書き方を確かめたいのは入力している最中なので、欄の横から開き、閉じたら入力に戻れるのがよい
- 欄ごとの決まりは言語の外（欄の設定）にあるので、言語の表だけでは分からない。開いた欄の決まりを先に書けば、知りたいことに最短で届く
- `Now` の列を実際の解釈で計算すると、例が今日の日付で具体的に分かる。仕様と説明の食い違いもテストで止められる
- 使わない節を畳むと、狭いペインやモバイルでも長くならない

## 却下した案

- **入力欄の下の例を増やす**: 欄が縦に長くなり、ダイアログが窮屈になる。欄ごとの決まりは例では伝わらない
- **Obsidian のノート（pkm-guide）にリンクする**: 入力中のダイアログを離れることになる。内容が仕様と食い違っても気づけない
- **説明のダイアログに試しの入力欄を置く**: 元の欄の下に解釈の結果がすでに出る。同じ働きが 2 つになる
- **ツールチップ（ホバー）で見せる**: モバイルにホバーがなく、表を載せられない

## 影響

- `shared/` にデータ・ダイアログ・CSS を足す。pkm-task（`ui/forms.tsx`、`ui/DateTimeField.tsx`、見積もりの欄）と pkm-template（`DatePromptModal.tsx`）にボタンを足す
- 各プラグインの `esbuild.config.mjs`、`packages/design/node/paths.ts`、preview の CSS の読み込みに、共有の CSS を足す
- `docs/design.md` の部品の表に、? のボタンと説明のダイアログを足す
- 子のノートや設定は変えないので、移行は付けない
