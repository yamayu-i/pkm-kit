# Reading View と Live Preview の表示差

issue 本文とサブの本文は、どちらも Obsidian 本体が描く。項目のカードは pkm-task の共通部品を使う。本文の表示は pkm-markdown と Vault の必須設定で整える。

## 今回そろえるもの

| 対象 | 原因 | 修正 |
|---|---|---|
| 通常の改行 | 必須設定の `strictLineBreaks: true` は Reading View で通常の改行をつなぐ | `false` にする。既存 Vault は設定の移行で更新し、本文は変更しない。issue 以外にも適用 |
| H2 の上余白 | pkm-markdown は Reading だけに余白を指定し、さらに本体の「段落の次の見出し」の規則に負けていた | Reading は本体の規則と同じ詳細度で余白を指定し、Live Preview は行の上 padding を指定。どちらも同じトークンの余白にする |
| リストの行間 | Reading だけに行の上下 padding を指定していた | リストの上下 padding を両モードで同じ値にする |
| 深いリストの記号 | Live Preview は深さ 9 まで ● → ○ → – を繰り返すが、Reading の指定は深さ 6 までだった | Reading も深さ 9 までそろえる |

改行の仕様: [Obsidian の基本構文](https://obsidian.md/help/syntax)。設定の移行後は Obsidian を再起動する。

## 残る差

| 対象 | Reading View | Live Preview | 理由 |
|---|---|---|---|
| 編集用の記号 | Markdown の記号を隠す | カーソル付近は見出し・強調・リンクなどの記号を表示 | その場で編集するため |
| 連続空行 | 空行を段落の区切りとしてまとめる | 文書内の空行を編集する行として保持 | 通常の改行設定を変えても空行の数までは一致しない |
| 見出し・段落間の実際の高さ | HTML のブロックの margin | エディタの行・空行と padding | 同じ余白指定でも文書の空行の数などによる差は残る |
| リストの補助線 | 同じ深さの記号の間をつなぐ | Obsidian のインデント線を薄く表示 | HTML の入れ子と、エディタの行ごとの構造が異なる（ADR-0128） |
| インラインコードのコピー | ホバー、スマホではタップで表示 | デスクトップのホバー時だけ表示。コードを編集中は隠す | スマホのタップは編集カーソルの移動に使う（ADR-0128） |
| サブの項目の保存 | ファイルに保存。題は欄を離れたとき | エディタの文書を更新。題は入力停止後 600 ms と欄を離れたとき | 入力中の文書とカーソルを守る（ADR-0161） |
| サブの原文表示 | 読めない項目を読み取り専用で表示 | Show source から元の Markdown を編集できる | 編集モードでだけ原文を直せる（ADR-0161） |
| サブの閉じた本文 | 本文セクションを隠す | 表示を折り畳む。本文にカーソルを入れた場合は表示 | 編集中の本文を隠さない（ADR-0165） |

表・コードブロック・引用などの描画も本体へ委ねる。すべての表示が同一であることは保証しない。ライブラリの HTML を独自生成して本文を置き換えると、リンク・埋め込み・他のプラグイン・編集操作との互換性を失うため、今回の修正では行わない。

## マージ後に試すこと

1. 移行後に再起動し、1 回の Enter、空行 1 つ、連続空行、末尾空白 2 つによる改行を含む本文を両モードで開く。1 回の Enter が Reading View でも残ることを確かめる。
2. issue の親の本文と、開いたサブの本文に同じ例を置き、同じ扱いになることを確かめる。
3. 段落に続く H2、箇条書き・番号付き・チェックリスト、深さ 7〜9 のリストを両モードで見比べる。H2 の追加余白とリストの行間・記号が適用されることを確かめる。
4. 長い本文のスクロールと、サブの開閉・本文編集を試し、揺れやカーソルの移動の不具合がないことを確かめる。
