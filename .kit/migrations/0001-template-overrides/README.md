# 0001: 子の template/ を、上流の既定への上書きだけにする

## 何が変わったか

テンプレートの既定が `.kit/templates/` に移り、vault-template は上流の既定に子の `template/` を重ねて読むようになった（pkm-kit #2、ADR-0009）。

切り出す前から使っている Vault には、上流と同じ中身の `template/file/*.md` と、全項目を書いた `template/config.json` が残っている。そのままでも動くが、子が全部を上書きしている状態になる。上流がテンプレートを直しても、その Vault には届かない。

## スクリプトが行うこと（migrate.mjs）

- `template/file/*.md` のうち、切り出した時点の上流（`baseline.json` のハッシュ）と同じ中身のものを消す。子が変えたもの、子だけのものは残す
- `template/config.json` を、上流と違う項目だけの形（`{ "file": … }` と、違う項目）にする。並び順を保つため、ファイル名はすべて残す。並び順も値も上流と同じなら、ファイルを消す
- 空になった `template/file/` と `template/` を消す

基準は切り出した時点の上流で、今の上流ではない。上流が後でテンプレートを変えても、子の古い写しを「子が変えたもの」と取り違えない。

## スクリプトで扱えない場合（AI が行うこと）

`check.mjs` が失敗したら、次を確かめて直す。

- `template/config.json` が JSON として読めない: 人が編集中に壊した可能性が高い。直し方をユーザーに確かめる（勝手に消さない）
- 子が変えたテンプレートが、上流の新しい項目を持っていない: このときは `check.mjs` は失敗しない。ただし `vault-upgrade` の PR の本文に「上書きしているテンプレート」として一覧を書き、上流の版との差をユーザーに見せる

## 確かめ方（check.mjs）

- 切り出した時点の上流と同じ中身の `template/file/*.md` が残っていない
- `template/config.json` があれば、上流と同じ項目が残っていない
