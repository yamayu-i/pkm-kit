## 評価

### プラグイン

- うまくいっていること: 11 月だけで機能の PR が多く（feat 24）、CI は落ちていない。ビルド成果物の再現の検査と security:scan が毎回動いている。preview でブラウザの守り（vault-html の CSP）を確かめられた
- うまくいっていないこと: preview がクラウドのセッションで毎回そのままでは動かない（4 件）。vault-html だけに `CHROMIUM_PATH` があり、パッケージ間で揃っていない。ビルドの順が依存関係で保証されていない（#8）。実機（Obsidian）での確認の手順がなく、テストが通っても実機で壊れた例がある（#6）。Obsidian 1.13 の Settings API の変更の影響を確かめていない

### LLM wiki の仕組み

- 子がまだ上流を取り込んでいないので、観測がない。wiki に関するエスカレーションと訂正は 0 件

### ハーネス

- うまくいっていること: kit-note が作業ごとに書かれ、評価の入力になった（7 件）。dev-pr の main の取り込みのように、気づきの場で直したものもある。CLAUDE.md は子向け 74 行・上流 77 行で、100 行以内
- うまくいっていないこと: 大きい変更で Issue を飛ばす訂正が 4 回繰り返した。文書に「大きい変更は Issue」とあっても、チャットで承認されたとき・途中で大きくなったときに守られていない。手順だけでは止まらないので、検査を足す。番号の重なりは手順で 1 回直したが、移行で再び起きた（検査にできる）。セキュリティの残課題（#11）が、3 回のチェックで「引き続き」のまま進んでいない
- 開発環境の差（Node・Chromium）が、作業のたびに同じ回避を生んでいる

### 更新の取り込み

- 子がまだ取り込んでいないので、移行の失敗・衝突の観測はない。移行は 5 件たまっており、最初の取り込み（vault-upgrade）が最初の実地の確認になる
