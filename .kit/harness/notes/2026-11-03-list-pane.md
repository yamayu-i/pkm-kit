## 訂正

- 起きたこと: PR（#25）を出したとき、main とのコンフリクトに気づかなかった。ユーザーに「コンフリクトあるよ。PR 作成時に気づけるといいなー」と言われた。同じ日に main に入った PR（#23）が ADR-0032 を使っていて、こちらの ADR も 0032 にしていた（番号の衝突）。CHANGELOG の先頭と ADR の一覧の末尾も、両方が書き足す場所なのでぶつかった
- 原因: dev-pr の手順は `git fetch origin main` と `git diff origin/main...HEAD` だけで、main を取り込んだときにぶつかるかを確かめていなかった。ADR の番号は、作業を始めたときの手元の main を見て決めた
- 改善案: dev-pr の最初に、main を merge してコンフリクトを解く手順を入れる（直した）。ADR の番号は、PR を出す前の最新の main で空いているかを確かめる（同じ手順に入れた）

- 改善案: dev-plan の 2 の判断を、実装を始める前に必ず書き出す（チャットに「大きい変更なので Issue を作る」と一言出す）
