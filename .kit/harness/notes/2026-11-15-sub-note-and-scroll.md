# 2026-11-15 サブの Note とスクロール

## 訂正

- 起きたこと: 「下部のサブの開閉の挙動が微妙」を、展開の中身・アニメーション・自動スクロールの問題と読んで方針を提案した。ユーザーが言う「挙動」はスクロール位置のことだった
- 改善案: UI の「挙動」の相談では、提案の前に、何が不自然か（位置・速さ・中身・見た目）を 1 問で確かめる。dev-plan の「依頼が曖昧なら質問する」に、UI の動きの例を足す

## つまずき

- 起きたこと: 上部のサブ一覧（`SubIssues.tsx`）から本文のカードの処理（`sub-cards.ts`）を直接 import したら、`pnpm check` は通ったが、`preview:ui` のビルドがモックにない export（`editorInfoField` など）で止まった。ヘッダーの部品が CodeMirror・エディタの API に依存してはいけないことが、文書にない
- 改善案: プラグインの設計と開発の文書に「ヘッダー・ビューの部品はエディタの拡張を直接読み込まない。必要なら登録口（例: `header/sub-reveal.ts`）を挟む。`preview:ui` で確かめる」と書く
- 起きたこと: 手元のサンドボックスで `node .claude/scripts/verify.mjs` の移行のテスト（`--dry-run` の出力を見るもの）が、出力が空になって失敗した。同じ fixture を手で `--dry-run` すると出力は正しく、main の CI は通っている。一時フォルダ（`os.tmpdir()`）に置いた子の Vault で子プロセスを動かすところが、サンドボックスで制限されているとみられる
- 改善案: 手元で移行のテストだけが失敗するときの見分け方（CI の結果を見る、fixture を手で `--dry-run` する）を進め方に書く
