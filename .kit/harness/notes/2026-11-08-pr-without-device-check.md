# 2026-11-08 実機での確認を待たずに PR を出す

## 食い違い

- 起きたこと: dev-implement の手順は「設定・CSS・View を変えたら、PR を出す前に実機で確かめる」だったが、実際には実機での確認をすべて飛ばして PR を作っていた。ユーザーから、これを定常にして PR 作成まで走り切るようハーネスを直すよう頼まれた
- 改善案: 実機での確認はユーザーが PR の後・マージの前に行うものとし、エージェントは PR の本文の「実機で確かめること」に挙げるだけにする（dev-implement の 4、dev-pr、進め方、プラグインの設計と開発を直した）

## 訂正

- 起きたこと: 最初の修正で「実機での確認はユーザーがマージの前に行う」と書いた。ユーザーに「実際にはマージ後まで確認しない。初期構築期なので多少のバグやデグレは許容し、本番で試して課題を見つけ解決する速さを重視する」と直された
- 改善案: 確認はマージ後に本番で行うと書き直し、PR の節を「マージ後に試すこと」にした（直した）。初期構築期を抜けたら、この方針を見直すかを kit-review で決める
