# 2026-11-15 体験定義書の HTML 配布

## 食い違い

- 起きたこと: Issue #42 の設計に際して、体験定義の `surfaces/task-issue-screen.md` を実装と照合した。正本の操作一覧に Parent / Children が残っているが、現在の `IssueHeader.tsx` は `SubIssues` を描画している。Markdown を全文変換しても、仕様書の内容が現状と合うとは限らない。
- 改善案: 今回の仕様補完で各面を実装と照合し、画面例と現在の説明を揃える。自動検査で文書・見出し・画面例の欠落を止めることと、説明の意味が正しいかを人・LLM が確認することを区別する。

## 画面例の条件

- 起きたこと: Previous boards の対象がない fixture では、段階を押しても実装が Calendar に戻り、画像のラベルと画面が一致しなかった。過去の未完了を持つ合成データを追加し、撮影時に現在の段階名が条件と合うことを検査した。
- 対応: 共通 HTML の CSS と本文の変更では UI を撮り直さず、実際の描画入力が変わったときだけ画像を更新するようにした。

## 完了条件の変更

- 起きたこと: 生成基盤と全成果物の整合を同時に揃える作業が長くなり、ユーザーから「成果物自体は実装と合わなくても、成果物を作る仕組みができていれば完了」と指示された。
- 対応: 生成・配布・検査の仕組みを完了条件にし、成果物の意味上の整合を追い続けず PR に進める。今後は基盤と成果物の網羅・整合を別々の完了条件として最初に定める。
