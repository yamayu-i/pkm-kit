# 2026-11-08 プラグインの改名（pkm-*）

## 移行

- 起きたこと: プラグイン ID を改名すると、過去の移行 0002（`vault-ribbon` を足す）と 0005（`vault-html` を足す）が、新しい Vault や記録を消して実行し直した Vault で古い ID を足し直してしまうことが、fixture のテスト（冪等性と fresh）で分かった。過去の移行に、新しい ID も「入っている」と扱う判定を足して直した
- 改善案: 移行の書き方（`.kit/harness/docs/migrations.md`）に「後の変更で、過去の移行が足す・探す名前を変えるときは、過去の移行も新しい名前を受け入れるようにする」と書く

## 移行

- 起きたこと: 端末ごとの `data.json`（git に入れない）は移行を実行した端末の分しか扱えない。移行の書き方に、git に入らない子のものの扱いが書かれていなかったので、プラグインの起動時に引き継ぐ処理を別に足した。また `.gitignore` を新しい名前だけにすると、ほかの端末に残る古い `data.json` が同期のコミットに入ることに、実装の途中で気づいた
- 改善案: 移行の書き方に「git に入らないファイル（`data.json` など）は、移行では実行した端末の分しか扱えない。ほかの端末の分はプラグイン側で引き継ぐ。`.gitignore` の古いパスも残す」と書く

## つまずき

- 起きたこと: マージ済みのブランチを main から作り直したあと、push に `--force-with-lease` を付けて拒否された（force push は禁止）。リモートのブランチは main の祖先だったので、通常の push で済んだ
- 改善案: なし（ルールどおり。作り直しの前に、リモートのブランチが main の祖先かを見る）
