# 2026-11-12 ノートの表示（pkm-markdown）

## 訂正

- 起きたこと: 見出しと箇条書きの案を HTML のプレビューで見せたとき、チェックボックスと文字の縦位置がずれていると 2 回指摘された。1 回目は箱の位置を計算で直したが、別の規則（`.note input[type="checkbox"] { margin: 0 }`）のほうが詳細度が高く、直したつもりの指定が効いていなかった。2 回目に気づいた
- 改善案: プレビューを直したら、直した部分をスクリーンショットで必ず確かめてから「直した」と伝える（1 回目は確かめた画像が小さく、ずれを見落とした）
- 起きたこと: コピーボタンを、枠と面のあるボタンで作って PR を出したところ、「アイコンにしてほしい。透明なアイコンボタン」と言われた。アイコンは使っていたが、枠と面が付いていた。本当に透明にすると、ボタンが上の行の文字に重なって読めないので、面をノートの面と同じ色にして透明に見せた
- 改善案: design.md の「部品」の表に、文中に浮かせるアイコンボタン（枠なし、面は下の面と同じ色）を足すと、次から迷わない

## 質問

- 起きたこと: ADR-0128 で、ノートの見出しの大きさを本文の倍率（H1 2 倍など）で決めると合意してから実装に入ったところ、デザインの検査（`css-lint.ts`）が文字の大きさ・行の高さを px のトークンに、余白・位置を px の 4 刻みに限っていて、通らないと分かった。ユーザーに質問し、見出しの大きさは Obsidian の既定のままにした。design.md にも検査にも、Obsidian が描くノートの本文に効かせる CSS の規則がなかった
- 改善案: design.md に「ノートの本文」の節を足した（直した）。ノートの本文の CSS を ADR で決めるときは、先に design.md のその節と css-lint の規則を読む、と dev-plan に書くとよい

## つまずき

- 起きたこと: Obsidian 本体の CSS（ノートの本文の要素の構造と既定の規則）がリポジトリにも環境にもなく、記号の位置やチェックボックスの縦位置を本体の規則と照らせなかった。公開の配布物から取り出そうとしたが、このセッションでは許可されなかった。似せた HTML で計算だけを確かめ、本体とのぶつかりはマージ後の実機の確認に回した
- 改善案: 自動の検査で確かめられないことは、dev-implement の「マージ後に試すこと」に回すのが今の決まり。ノートの本文の CSS が増えるなら、Obsidian の要素の構造（`.list-bullet`、`.HyperMD-list-line-N`、`.cm-hashtag` など）を文書にまとめておくと、次から推測が減る
