# 2026-11-08 ファイル名の英語化（Issue #15）

## 訂正

- 起きたこと: Issue #15 の「新規作成のときにタイトルとファイル名を別々に入力できるようにする」を文字どおり読み、入力欄を分けて既存ノートを移行で 1 回改名する計画を出した。ユーザーから「作るときは日本語のタイトルを 1 つ入力するだけにしたい（入力値 = ファイル名 = title）。ファイル名だけを、あとでスキルで英語のケバブケースに定期的に直したい」と訂正された
- 改善案: Issue の「やりたいこと」が手段まで書いていても、計画の前に、使う人がどの場面で何をしたいかを確かめる。[プロダクト](../docs/product/README.md) の場面と照らし、手段が場面の手間を増やしていないかを見る

## つまずき

- 起きたこと: 計画の時点で、`sources/` は「コミット済みのものは変えない」ことを考えていなかった。実装の途中で、改名の対象から外し、`sources/` から指されたノートは改名せずに止める形にした（計画の範囲内の判断として、ユーザーには結果で伝えた）
- 改善案: dev-plan の「文脈を読む」に、ファイルを動かす・書き換える変更では、所有の区分（`.claude/docs/llm-wiki.md`）の表を見るよう足す

## つまずき

- 起きたこと: `git diff-tree -M` は、小さいノートに title を 1 行足して改名すると、改名と見なさず削除と追加にした。`check-append-only.mjs` の改名の検査は、削除と追加を自分で組にする形にした
- 改善案: なし（コードのコメントに書いた）

## 迂回

- 起きたこと: `verify.mjs --plugin` の 1 回目で、pkm-git のテストが `ENOTEMPTY: directory not empty, rmdir '.kit/src/node_modules/.vitest-cache'` で起動できず失敗した。変更していない箇所で、再実行では通った。並行するパッケージのテストが同じキャッシュのフォルダを消し合っているように見える
- 改善案: 各パッケージの vitest のキャッシュの置き場所を分けるか、`pnpm check` のテストを並行させない。上流の Issue にする
