# 2026-11-20 GTD の分類のバッジと Project の規則（#210）

## 訂正

- 起きたこと: 「Inbox のサブに期間を入れられない」を、Inbox に戻ったときに今ある期間を消すかどうかの話と読み、「止めるのは新しく書くときだけ」と返した。ユーザーの意図は「消さない。入力の段階で弾く」で、消す案は最初からなかった
- 改善案: 「〜できない」という規則は、まず入力の検査（どの経路で弾くか）として読み、データを消す案は相手が言っていなければ持ち出さない

## 訂正

- 起きたこと: Project を「active なサブを持つもの」のまま考え、サブがすべて閉じたら通常の issue に戻ると書いた。ユーザーに「サブの status に関わらず、あれば Project」と直された。ADR-0203 の Calendar の排他（core/calendar-subs.ts）はすでに閉じたサブも数えていて、DailyTaskView の Pick（core/daily.ts）と判定が食い違っていた
- 改善案: 同じ概念の判定がコードの 2 か所にあるときは、提案の前に両方を読み、違いを示す。ADR-0210 で isProject を 1 か所にまとめる
