# 中断と再開

会話の履歴には頼らない。再開に必要なことは、ブランチと Issue（なければ PR か、ブランチの最後のコミットの本文）に残す。

## 中断するとき

1. 途中の変更をコミットして push する。動かない状態でもよい

   ```sh
   git add -A
   git commit -m "wip: <ここまでにやったこと>"
   git push -u origin HEAD
   ```

2. 引き継ぎを書く。Issue があれば Issue のコメント、なければ PR の本文か、wip のコミットの本文に書く
   - **完了したこと**
   - **残っていること**
   - **次の一手**: 再開したら最初にやること。ファイルやコマンドまで
   - **未解決の疑問**: ユーザーに確認が要ること。試してうまくいかなかったこと
   - **会話の中だけで決まったこと**: ここに書かないと失われる

3. 記録していない気づきがあれば [気づきを記録する](../kit-note/SKILL.md)。そのファイルも wip のコミットに含める

## 再開するとき

1. 状態を読む

   ```sh
   git fetch
   git switch <ブランチ>
   git log --oneline origin/main..HEAD
   git status
   ```

   Issue・PR の引き継ぎ、最後のコミットの本文を読む。

2. 引き継ぎをそのまま信じない。main が進んでいたら取り込み（`git merge origin/main`。履歴は書き換えない）、`node .claude/scripts/verify.mjs` で今どこまで通るかを確かめる
3. 未解決の疑問を最初にユーザーに確認し、次の一手から [実装する](../dev-implement/SKILL.md) を続ける

## 出力の段階

出力は [write-for-reader](../../../../.claude/skills/write-for-reader/SKILL.md) に従う。下は既定で、上げ下げはその場で判断する。

| 出力 | 読み手 | 段階 |
|---|---|---|
| 中断の引き継ぎ | LLM だけ（再開するセッション） | - |
