# 上流の更新の取り込み

- 種類: 手順（AI 経由）
- 開き方: セッションの開始時の知らせ、または「更新を取り込みたい」と頼む
- 場面: [仕組みの更新を取り込む](../jobs/kit-upgrade.md)

## 今の振る舞い

- SessionStart フックが、未取り込みの上流の更新と未適用の移行を知らせる
- AI が子向けの vault-upgrade の手順で、ブランチで上流を merge し、移行を実行し（スクリプトで済まない部分は移行の README に従って直す）、検査を通して PR にする
- PR の本文は、取り込む範囲で増えた `.kit/changes/` のファイルから書かれ、子への影響（移行、モバイルで確かめること）が入る
- 未適用の移行があると、検査と CI が失敗する

## 使う概念

[同期と snapshot](../concepts/sync-snapshot.md)

## 根拠

[ハーネスの ADR-0010](../../adr/0010-upstream-updates-and-migrations.md)、[ADR-0056](../../adr/0056-conflict-free-numbering.md)、子向けの [ハーネスの設計](../../../../../.claude/docs/harness.md)

## 入力と制約

子のブランチから upstream/main を merge します。未適用の移行を確認し、上流の正本を子で独自に直しません。

## 操作と保存

migrate が子に必要な変更を適用し、取り込んだ上流の commit を記録します。定義書は上流の生成物として merge で更新され、子で画像を作り直しません。

## 失敗時と戻し方

衝突では子のファイルを捨てずに双方を確認します。同じ pkm-guide/ のパスに独自ファイルがあれば退避して解決します。移行が止まったら README の手順に従い、verify が通るまで取り込みを完了しません。

## 端末の違い

更新の取り込みと移行は PC で行い、マージ後は他の端末で同期します。モバイルでビルドする必要はありません。


## 結果を確認する例

取り込み後に node .claude/scripts/verify.mjs を実行し、「体験定義書」が成功することを確かめる。pkm-guide/user-experience.html と ui/ の画像は上流の生成物なので、子では capture や build を実行して直さない。失敗した場合は取り込み漏れ・衝突の解決漏れを確認する。
