# 体験定義と仕様を確認する

- 端末: PC / スマホ
- 望む成果: [1](../strategy.md#望む成果)、[2](../strategy.md#望む成果)

## ジョブ

何ができるかを知りたいとき、操作の意味や保存結果を確かめたいときに、今の体験と仕様を画面と並べて読みたい。

## 今の流れ

1. ファイル一覧の pkm-guide/user-experience.html を開く（[HTML の表示](../surfaces/html-view.md)）。
2. 最初は全体像を読み、したいことに合う場面へ進む。特定の画面や用語が分かっていれば目次から直接引く。
3. 画面の開き方、入力と制約、操作後に保存されるもの、失敗時の戻し方を確かめる。
4. 実装の画面例と説明を見比べる。追加の状態は折りたたみを開く。画像を押すと全体を開ける。
5. 細かい決定の理由が必要なら根拠を開く。根拠のリンクは GitHub なので、オフラインでは定義書に収録した本文を参照する。

## 始める条件と期待する結果

上流のセットアップか更新を取り込んであり、PKM HTML が有効なこと。期待する結果は、どの画面で操作し、何が保存され、困ったときにどう戻すかを説明できること。

## つまずいたとき

HTML が開けなければ PKM HTML の有効化を確認する。画像が欠けたら同期を完了させる。本文と画面の違いを見つけたら子のエスカレーションで上流へ伝える。子で定義書を直接修正しない。

## 関わる概念

[ノートの type](../concepts/note-type.md)（定義書はノートではない）、[同期と snapshot](../concepts/sync-snapshot.md)

## うまくいっている兆し

- 操作の結果を推測せず、定義書から確認できる。
- 画面例と条件を見て、自分の現在の状態との違いが分かる。
- スマホの幅でも本文と表を読める。

## 知られている困りごと

画面例は実装の部品と CSS を描画したプレビューであり、Obsidian 本体の枠や個別の端末を完全に再現するものではない。
