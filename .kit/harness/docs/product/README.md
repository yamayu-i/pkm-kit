# プロダクト

pkm-kit を使う人の体験に責任を持つための文書（[ADR-0012](../adr/0012-product-responsibility.md)）。誰のどんな場面のために、何を、どういう考え方で作るかを書く。

- 人: 価値の最終判断と戦略の承認、どの機会を解くかの決定
- Claude: 機会（困りごと）を自分で見つけて起票する（[product-review](../../skills/product-review/SKILL.md)）。場面・概念・今の体験の正本を保ち、全体の一貫性を点検する

使う人は、当面は本人だけ（[戦略](strategy.md)）。上流は公開なので、ここには個人のノートの内容を書かない。本人の使い方から分かったことは、一般的な場面として書く。

## 文書の種類

| 種類 | 置き場所 | 書くこと | 体験の層（Garrett） |
|---|---|---|---|
| 戦略 | [strategy.md](strategy.md) | ビジョン、使う人、望む成果、原則、やらないこと、当たり前の品質 | 戦略 |
| 場面 | [jobs/](jobs/README.md) | 使う人の状況・したいこと・期待する結果と、今の流れ | 範囲 |
| 概念 | [concepts/](concepts/README.md) | 使う人が頭に置くもの（issue、Do Date など）の目的・状態・操作と、用語の対応表 | 構造 |
| 今の体験の正本 | [surfaces/](surfaces/README.md) | 画面・コマンド・MCP などの面ごとの、今の振る舞い | 構造・骨格 |
| 見た目 | [デザインルール](../../../src/docs/design.md) | 色・文字・部品・アクセシビリティ | 骨格・表面 |
| 機会 | GitHub の Issue（ラベル `ux`） | 場面、困りごと、根拠 | — |

ADR は「なぜそう決めたか」の履歴で、書き換えない。`surfaces/` は「今どうか」の正本で、振る舞いが変わるたびに書き換える。

## 育て方の規則

構成を変えずに大きくできるようにしている（[ADR-0012](../adr/0012-product-responsibility.md) の 2）。

- 1 単位 = 1 ファイル。増えるのはファイルの数で、既存のファイルを分割しない。1 単位が大きくなったら単位を分け、元のファイルは親の単位として短く残す
- パスは変えない。ディレクトリの中はフラットにし、まとまりは各 `README.md` の一覧の見出しで表す。サブフォルダを作らない
- ファイル名（slug）は英語の短い名前。領域を接頭辞にする（`task-`、`note-`、`sync-`、`wiki-`、`kit-`）。番号は振らない
- 新しい種類が要るときは、ディレクトリと `README.md` を足し、上の表に 1 行足す
- `strategy.md` は分けない。200 行を超えそうなら、絞れていない兆候として削る
- 各種類の書式は、その種類の `README.md` にある。どのファイルも、その種類の `README.md` からリンクする（`check-docs.mjs` が、辿れないファイルとリンク切れを検査する）
- 単位どうしは相対パスでリンクする（場面 → 面・概念、面 → 概念・場面・ADR）

## いつ書き換えるか

| きっかけ | 書き換えるもの |
|---|---|
| 利用者に見える振る舞いを変える PR | 変えた面の `surfaces/`。概念や用語が変わるなら `concepts/` |
| 新しい場面に応える機能を足す | `jobs/` に場面を足す |
| [product-review](../../skills/product-review/SKILL.md) | 歩き通しで見つけた食い違いを直す。機会を起票する |
| 望む成果や原則を変える | `strategy.md`（人が承認する） |
