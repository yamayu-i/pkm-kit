# ADR-0015: ノートは日本語のタイトルで作り、あとでファイル名だけを英語のケバブケースに改名する

- 状態: 承認
- 日付: 2026-11-08

## 背景

ノートを作るときは急いでいるので、日本語のタイトルを入力するだけで作りたい。一方、LLM wiki としては、ファイル名が英語の方が扱いやすい。リンクのパスが読みやすく、エンコードも要らず、検索や対応付けもしやすい。

ヘッダーと一覧 View はタイトルを frontmatter の `title` から出すので、ファイル名とタイトルは一致しなくてよい（[プラグインの ADR-0026](../../../src/docs/adr/0026-note-views.md)、[ノート規約](../../../../.claude/docs/vault-conventions.md)）。ところが今の `note.md` テンプレートには `title` がなく、note のタイトルはファイル名から出ている。このままファイル名を変えると、タイトルも変わってしまう。

すでに決まっているファイル名は、どれも英小文字・数字・ハイフンでできている。`wiki/large-language-model.md`、`sources/YYYY-MM-DD-<名前>.md`、`daily/.../YYYY-MM-DD.md`、`issue/i-N.md` など（[LLM wiki の仕組み](../../../../.claude/docs/llm-wiki.md)）。

[Issue #15](https://github.com/yamayu-i/pkm-kit/issues/15)。

## 決定

1. **作るとき**: 新規作成の画面は変えない。入力した文字がファイル名と `title` の両方になる。`note.md` テンプレートに `title: "{{title}}"` を足す
2. **ファイル名の形式**: 最終的な形は英語のケバブケース（英小文字・数字・ハイフン。`^[a-z0-9]+(-[a-z0-9]+)*\.md$`）とする。日本語の名前は「改名を待っている」状態として認め、誤りとは扱わない
3. **改名は子向けのスキル `note-rename` で行う**（`.claude/skills/note-rename/`）。ユーザーに頼まれたときだけ実行する。SessionStart フックでの通知や、定期的な実行はしない
   1. 対象を挙げる: ファイル名が 2. の形式に合わないノート。`daily/`、`issue/`、`routine/`、`member/`、`asset/`、`tmp/`、`template/`、隠しパス、`README.md` は対象にしない
   2. AI が英語の名前の案を作り、対応表をユーザーに見せて確かめる。確かめられた名前だけを改名する
   3. 改名する。`title` がなければ、もとのファイル名（拡張子を除く）を `title` に書き込む。同じフォルダの中で名前だけを変え、フォルダは移さない
   4. そのノートを指すリンクを、Vault のすべてのノートで書き換える
   5. 検査を通し、`main` に直接コミットする。件名は `note(rename): …`
4. **DailyNote の本文の例外**: 改名にともなう、本文のリンク先のパスの書き換えだけを、本文の保護（[ADR-0007](0007-note-format.md)）の例外にする。リンクの表示文字列とほかの文字は変えない
5. **main に直接コミットしてよいもの**に、改名（`note(rename):`）を足す（[ADR-0002](0002-workflow-by-size.md) の wiki の操作と同じ扱い）
6. **検査**
   - `check-append-only.mjs` は、件名が `note(rename):` のコミットについて、次のことを確かめる: ファイルは改名だけで、改名したノートは frontmatter の `title` を足したこと以外を変えていない。ほかのノートで変わった行は、リンク先のパス以外が同じである
   - `wiki-lint.mjs` は、形式に合わないファイル名を誤りにしない。改名を待っているノートの件数を、情報として出す

## 理由

- 作る手間を増やさずに、ファイル名だけをあとから揃えられる。急いでいる場面の入力は 1 つで済む
- ケバブケースなら、すでにある wiki・sources・daily・ID の名前とそのまま揃う。対象から外す名前も、検査の例外も要らない
- 英語の名前を決めるには判断が要る。自動で作らず、AI が案を出してユーザーが確かめる
- 改名は Obsidian で行ってもリンクが自動で書き換わり、daily の本文も変わる。リンク先のパスだけを例外にすれば、Obsidian で改名したときと同じ結果になり、本文の意味は変わらない
- 改名はノートの操作で、仕組みは変えない。wiki の操作と同じく、PR にしなくてよい

## 却下した案

- **作るときにタイトルとファイル名を別々に入力させる**: 急いでいるときの入力が増える。作る場面で英語の名前を考えさせたくない
- **スネークケースにする**: すでにある名前がハイフン区切りなので、規則が 2 つ並ぶか、wiki と sources も改名することになる
- **上流の移行で 1 回だけ改名する**: 日本語の名前のノートはこの先も作られ続けるので、1 回では終わらない。移行は名前の判断を AI とユーザーに任せる形になり、`check` が通る状態を保てない
- **改名を待っている件数を SessionStart フックで知らせる**: ユーザーが必要としない。頼まれたときに実行すれば足りる
- **DailyNote の本文を例外にせず、daily から指されたノートは改名しない**: daily から指されるノートほど改名できず、目的を果たせない。Obsidian での改名とも結果が違う
- **英語の名前を機械的に作る（ローマ字にするなど）**: 意味の分かる名前にならず、LLM wiki の性能に役立たない

## 影響

- テンプレート: `.kit/templates/file/note.md` に `title` を足す。`main.js` のビルドは要らない
- スキル: `.claude/skills/note-rename/SKILL.md` を足す。改名とリンクの書き換えのスクリプト（依存なしの Node。`.claude/scripts/`）を足すかは、計画で決める
- 検査: `check-append-only.mjs`、`wiki-lint.mjs` と、そのテスト
- 文書: [ノート規約](../../../../.claude/docs/vault-conventions.md)（ファイル名の形式と改名）、[進め方](../../../../.claude/docs/workflow.md)（`note(rename):` の件名と main への直接のコミット）、子の `CLAUDE.md` のスキルの表とルール 1・4、`.kit/owned-paths.json`、`.kit/changes/`
- 移行は付けない。子のノートは、スキルを実行したときにだけ変わる。`title` のない既存の note は、改名するときに `title` が入る
- [ADR-0007](0007-note-format.md) の DailyNote の本文の保護と、[ADR-0002](0002-workflow-by-size.md) の main への直接のコミットに、例外が 1 つずつ増える。どちらも状態を「一部置換: ADR-0015」にする
