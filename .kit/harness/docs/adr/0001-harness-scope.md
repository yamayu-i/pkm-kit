# ADR-0001: ハーネスは Claude Code 専用。正本は `.claude/` に置く

- 状態: 承認（一部置換: ADR-0009）
- 日付: 2026-10-31

## 背景

[app-harness-template](https://github.com/yamayu-i/app-harness-template) を参考に、このリポジトリにもハーネス（進め方・スキル・検査・評価の仕組み）を入れる。前提が違う点が多い。

| | テンプレート | yamayu-pkm |
|---|---|---|
| 作るもの | Web / モバイルのアプリ | Obsidian のプラグインと、LLM wiki そのもの |
| 体制 | 少人数。ツールは各自が選ぶ（Claude Code、Codex など） | 1 人。Claude Code だけ |
| リポジトリ | アプリのコードだけ | Vault そのもの。各端末の Vault Git が main に snapshot を直接 push する |
| 見える場所の制約 | なし | Obsidian に索引されないよう、開発用のファイルは隠しフォルダに置く |

ハーネスの目的は 3 つ（2026-10-31 のヒアリング）。

1. Obsidian 上で動くプラグインを作る・改善する
2. LLM wiki の機能を開発し、wiki の仕組み自体も、調査と利用実態を踏まえて改善する
3. ハーネス自体を改善する

## 決定

- 正本は `.claude/` に置く。目次は `.claude/CLAUDE.md`（100 行以内）。詳細は `.claude/docs/` の小さな文書にし、リンクでつなぐ
- 手順はスキルとして `.claude/skills/<name>/SKILL.md` に直接書く。ラッパーは生成しない
- 検査スクリプトは `.claude/scripts/` に、テストは `.claude/scripts/test/` に置く
- テンプレートから採るもの・採らないものは次のとおり

| テンプレートの仕組み | 扱い | 理由 |
|---|---|---|
| 目次とリンクのグラフ、到達できない文書の検出 | 採る | エージェントが必要な文書だけを辿れる |
| 人間の確認地点を決めた工程 | 採る（軽くする） | [ADR-0002](0002-workflow-by-size.md) |
| ADR | 採る | 設計を変えるときの判断を残す |
| 気づきの記録と、月 1 回の評価 | 採る（wiki の仕組みも対象にする） | [ADR-0006](0006-self-improvement-loop.md) |
| 規約より先に検査で強制する | 採る | [ADR-0005](0005-checks-in-ci.md) |
| AGENTS.md の正本化、各ツール向けラッパーの生成 | 採らない | Claude Code しか使わない。生成とずれの検査が手間だけになる |
| Issue ごとの学習用 md | 採らない | 学習は目的に入っていない |
| git フック | 採らない | モバイルの Vault Git のコミットではフックが動かない。[ADR-0005](0005-checks-in-ci.md) |
| 別の 1 名の承認 | 採らない | 1 人で開発する |

## 理由

- 1 人・1 ツールなので、ツールに依存しない正本を作る利点がない。`.claude/` は隠しフォルダなので、Obsidian にも索引されない
- 目次を小さく保ち、詳細をリンクで辿らせる形は、ツールの数に関係なく効く。そのまま採る

## 却下した案

- テンプレートをそのまま入れる（`AGENTS.md`、`harness/`、`docs/`）: `harness/` と `docs/` が Vault の見える場所に出てノートと混ざる。隠しフォルダに移すと、テンプレートとの差分を追う意味も薄れる
- 正本を `.kit/src/` に置く: wiki の仕組みとハーネスはプラグインに属さない

## 影響

- Claude Code 以外のツールを使うことになったら、この ADR を置き換える（`AGENTS.md` を正本にして `.claude/` から参照する形にする）
- `CLAUDE.md` の `@` 取り込みは、ノートを書くときに常に必要な `docs/vault-conventions.md` だけにする。その他はリンクにする
